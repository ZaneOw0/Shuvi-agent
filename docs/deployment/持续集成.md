## 1. 当前门禁

[CI 工作流](../../.github/workflows/ci.yml) 继续只响应面向 `main` 的 PR 与 `main` 推送，保留 `检查与构建` 名称和同仓库来源条件。fork PR 不在自托管 runner 执行。所有步骤在同一 job 顺序运行，避免产品与测试宿主同时写共享 HAR 缓存；总超时 60 分钟。

| 顺序 | 内容 | 失败条件 |
|---|---|---|
| 1 | Node / SDK 路径 / .NET 预检 | 工具缺失或版本不符 |
| 2 | Agent、宿主、网关、历史文档来源校验；MCP fixture 与 lint 门禁回归 | 基线哈希变化或测试失败 |
| 3 | 搜索服务 `npm ci`、`npm test` | 锁文件安装、TypeScript 构建或测试失败 |
| 4 | 原 `ci-windows.cmd` | OHPM、Code Linter 或产品构建失败 |
| 5 | `ci-agent.ps1` | UX 逻辑回归、宿主/HAR/ohosTest 构建或八模块 Hypium 失败 |
| 6 | `ci-gateway.ps1` | .NET 构建/测试失败、TRX 缺失、零用例或未全部通过 |

UX 回归入口包含 `entry/src/test/run-direct-model-tests.cjs`：使用 `DEVECO_SDK_HOME` 下的 SDK loader，验证设备直连的协议、原生 HTTP 事件处理、Provider 结算和调试会话；网络由替身注入，不使用 API Key 或计费服务。该项通过不代表设备网络验收，也不会绕过前序 lint 门禁。

最新远端 [运行 40097037001](https://github.com/ZaneOw0/Shuvi-agent/actions/runs/40097037001) 在 lint 阶段失败：报告诊断为 0，但 `arkPerfCheck.log` 表明分析失败或覆盖不完整。2026-10-23 的 14 条诊断与后续修复前 31 条诊断属于历史；本轮仍保留安全规则、生产源码检查与内部日志判定。详细证据及平台交接见 [整合 CI 门禁复核](../verification/agent/整合CI门禁复核.md)。

报告诊断为 0 之后，剩余的红点是两类**工具缺陷**（与本仓库代码无关），2026-10-25 的处理方式：

- `code-linter.json5` 曾声明 12 条 `@security/no-unsafe-*` 规则，但本版 Code Linter（DevEco Studio / CLT 26.0.0.821 内置 6.0.240）的 `ruleSet.json` 没有这些规则名，引擎只会报 `Invalid rule name` 且**从不执行**。这些无效声明已移除（历史上它们也从未生效，`main` 的旧门禁不检查内部日志所以看不出来）；本版可用的安全规则是 `plugin:@security/recommended`（`@security/no-commented-code`）与 `plugin:@security/all`（另有 `no-cycle`、`no-unsafe-{huks,kdf,sm4,ecdh,sm2-*}`），启用前需单独评估新增诊断。
- ArkTS 分析器对 9 个文件抛 `Cannot read properties of undefined (reading 'getDeclaringMethod')`，这些文件被扫描但**未被真正检查**（`entry/src/main/ets/pages/Index.ets` 等，清单见 `scripts/verify-lint-report.cjs` 的 `KNOWN_ANALYZER_CRASHES`）。门禁改为**精确签名豁免**：只放行清单内文件 + 该条固定文案；清单外文件、同一文件的其他崩溃文案、其他任何 `ERROR/FATAL` 依旧失败。豁免仅在工具自报版本等于基线 `6.0.240` 时生效，且每次把缺口写入 `summary.json` 的 `coverageGaps`，不隐藏覆盖不完整的事实。
- 升级 CLT / DevEco Studio 后必须复测并清空该清单：版本不匹配时门禁会直接失败，不会静默沿用豁免。

**离线语料 fixtures**：`run-host-tests.cjs` 需要外部材料（原始 PDF 与一份 MinerU 解析 ZIP）。它们过去放在被 gitignore 的 `.cache/` 下，导致 CI 必然 ENOENT（本机 runner 实测 310 项中 6 项）。现改为**随仓库提交**并固定哈希：清单 `entry/src/test/fixtures/corpus/manifest.json`，唯一读取入口 `entry/src/test/corpus-fixtures.cjs`（`status: committed` 且 `bytes/sha256` 双校验，不符即失败），唯一写入入口 `scripts/import-corpus-fixtures.cjs`（只输出敏感命中类别计数，不打印成员名与正文）；候选 ZIP 可用 `scripts/verify-corpus-zip.cjs` 预先自检（成员数/解压字节/CRC/必需成员）。不得静默跳过。

## 2. runner 准备

复用现有 `[self-hosted, harmonyos]` Windows runner，不新增云服务或 GitHub Action 依赖。平台同学需在运行 runner 的账户环境中确认：

- CLT、JDK 与 [平台基线](../02-平台基线.md) 一致；现有 CLT_HOME / JAVA_HOME 路径继续由 workflow 配置。
- `DEVECO_SDK_HOME` 指向安装了 API 26 的 SDK 根目录；脚本显式读取并检查，不猜测 IDE 路径。
- 行尾由两处共同保证：仓库 `.gitattributes` 写 `* text=auto eol=lf`（`.cmd/.bat` 后置覆盖回 `eol=crlf`），runner 则通过 `D:\actions-runner\.env` 的 `GIT_CONFIG_GLOBAL=D:\actions-runner\gitconfig-ci` 使用**只作用于 runner 进程**的 git 配置（Windows `core.autocrlf=true`，Linux/macOS 用 `input`），不改账户级 `~/.gitconfig`，也不保存在会被 checkout 重建的仓库 `.git/config` 里。
- CLT 的 `tool/node` 中有 Node 24 与 npm；OHPM/Hvigor 在 CLT 的 `bin` 中可执行。
- PATH 中可用 `dotnet`，能满足 [global.json](../../services/local-ai-gateway/global.json) 的 .NET 10.0.302 / latestPatch 策略。
- `CODELINTER_LOG_DIR` 指向该 CLT 实际输出 `codelinter.log`、`arkPerfCheck.log`、`hpauditor.log` 的目录。平台先确认一次实际运行的日志位置，再设置变量；不能把 JSON 报告目录当作内部日志目录。
- runner 账户可写工具缓存，并可访问 OHPM/npm/NuGet 包源。环境变量变更后需让 runner 进程重新加载环境。

不在 workflow 中写入生产 API Key、网关客户端令牌或签名材料，不自动下载/安装另一套 SDK。缺少工具时明确失败，由平台配置后重跑。

## 3. 本机复验

源码/历史归档核验和 fixture 不需要设备：

```powershell
node scripts/verify-agent-host.cjs
node scripts/verify-gateway-import.cjs
node scripts/verify-agent-docs.cjs
node scripts/test-agent-fixture.cjs
```

Agent 入口接受显式工具路径，适用于 CLT 或 IDE。以下示例使用本机 IDE；不安装或运行设备包：

```powershell
$devecoRoot = 'C:\Program Files\Huawei\DevEco Studio'
.\scripts\ci-agent.ps1 -HvigorPath "$devecoRoot\tools\hvigor\bin\hvigorw.bat" -OhpmPath "$devecoRoot\tools\ohpm\bin\ohpm.bat" -SdkHome "$devecoRoot\sdk" -JavaHome "$devecoRoot\jbr"
.\scripts\ci-gateway.ps1
```

已有完整依赖时 Agent 可加 `-NoInstall`；CI 默认仍安装。PowerShell 若阻止本机脚本，可用单进程 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/ci-agent.ps1` 并补上同样参数，无需改变机器永久策略。

Hypium 证据写入 `.local/agent-tests/<时间>/`，网关 TRX 写入 `.local/gateway-tests/<时间>/`；均不入库。网关脚本只统计声明 `IsTestProject=true` 的工程，排除 ProcessFixture 辅助程序。脚本核验本次新目录中的报告，不复用以前通过记录。

lint 证据写入 `.local/ci-lint/<时间-随机标识>/`。CLT 模式只读取本轮追加或重写的内部日志，不删除共享工具日志；不要与 IDE 检查并发使用同一日志目录。本机只有 DevEco Studio 时，可独立验证已安装 CLI，不能称作远端 CLT 门禁通过：

```powershell
.\scripts\ci-lint.ps1 -NodeScript "$devecoRoot\plugins\codelinter\run\index.js"
node --test scripts/tests/verify-lint-report.test.cjs
```

修复后的本机报告同样为 0 项诊断，但分析器内部异常仍使门禁失败，错误摘要和原始证据都保留。不要为获得成功退出码删除日志检查或规则。

## 4. 验证边界

CI 不签名、不安装、不运行 HDC，不启动正式网关或调用 Tavily/模型。网络活动限依赖恢复及本机测试服务。设备测试包“构建成功”与设备测试“运行成功”分别记录。

来源校验是当前导入基线门禁；后续修改导入代码必须记录相对上游的差异和审核理由，再维护校验清单，不能只改哈希隐藏修改。

远端工作流只有用户提交/推送并创建或更新 main PR 后才会运行。当前实际结果和未覆盖项统一见 [项目进度与验收](../08-项目进度与验收.md)。
