## 2026-10-29 L1 搜索历史误失效修复

用户模拟器反馈：点击语义搜索提示 `LocalMembershipChangedStartNewSession`，问题未发送。已使用真实 `KnowledgeQuerySession`、`UnifiedKnowledgeHistoryRepository`、`ParsedDocumentAssets` 与普通库复现同名错误。原因是本轮 `klex_upd_asset_*` 触发器范围过宽：搜索页自动保存历史，历史卡片与 manifest 也写入共享 `upd_asset`，触发 L0 revision 递增。L1 review 对比搜索时捕获的 revision，因搜索自身的历史写入而拒绝授权。

此前页面专项用了空 history adapter，没有覆盖这一真实组合；原 236/236 和构建通过不能证明该组合可用。这是本轮重构引入的回归。

修复仅收窄资产触发器：INSERT/UPDATE/DELETE 只在该资产被当前、未删除文档的图片 occurrence 引用时递增修订。UPDATE 同时检查 OLD/NEW id。其他正文、归档、删除与标注变更拦截保留；不移除 L1 的资料修订校验。初始化时在普通库事务中原子替换三个旧资产触发器，无正文、历史、向量或 schema 表删除，不要求重新导入。现有页面会话需在新版本重启后重新搜索。

## 1. 实现与数据边界

页面和 L2 adapter 共用 `KnowledgeLexicalSearchPort`。生产实现使用现有 S3 普通库、现有 ArkData API，不新增权限、依赖、模型服务或云请求。旧 `text_fts` 与 `upd_*` 布局保留，原件、正文、历史、向量不清理。

派生 schema 使用 `klex_*`，不被 `ParsedDocumentStoreLayout` 的 `upd_*` 严格布局检查误判为未知表：

| 对象 | 字段或职责 |
|---|---|
| `klex_state` | 单行 id=1；policy、revision、indexed、state、phase、cursor；policy=`UNIFIED-LEXICAL-1`，indexed 保存已发布索引对应的源修订 |
| `klex_fts` | FTS5；kind、id、version、hash 为 UNINDEXED，body 为检索字段；body 来自当前 chunk 或有效图片 description |
| `klex_probe` | 本机自有测试文本，验证真实建表/写入/中文、英文、数字、标点词项查询/更新/读回/删除；不放用户内容 |
| `klex_upd_*_*` triggers | 正文、文档、标注等变更提交时递增修订并标 Stale；asset 限定为当前图片引用，历史与其他派生资产不改变语料修订 |

普通库内容先提交，索引后续维护；不将 FTS 写入加入原有权威发布事务。状态按 NotBuilt → Building → Ready 流转，源变更标 Stale，运行能力或维护失败报告 Unavailable。Building 的 phase/cursor 每行持久化，取消在下一检查点停止，新查询可恢复；不恢复任何旧模型任务。未知 policy 拒绝使用，不自动删除未知布局。

重建只清理本任务自有的 `klex_fts` 派生行。先写 NotBuilt，再清派生行，最后进入 Building；进程中断可重新进入该顺序。逐行写入/读回后推进断点，完成才发布 indexed=revision / Ready。rowid 从 kind+id 的 SHA256 前 48 位派生；先检查已有行身份，碰撞时明确失败并降级，不覆盖另一证据。rowid 定位避免逐行按未索引文本字段扫描整张 FTS 表。

候选读回校验当前 generation/effectiveId、输入 hash 和原文；图片同时核图 hash，description 的 hash 用现有 `unifiedProxyText(description,tags)` 规则验证，但证据正文不包含 tags。标题/tag-only 不能作为断言证据。多父图复用原有合卡与可见性规则；页面翻页、L2 裁剪后均重验。

查询结果区分 Keyword/Literal、实际 engine 和 evidenceType；Keyword 无连续原文范围也可保留，Literal 仅高亮实际 UTF-16 范围，保护代理对并合并重叠区间。原历史 wire 不变，codec 对新增 reason 字段兼容缺省读取。

## 5. 合成规模与预算

夹具在独立 host scope 中生成一个当前文档的 1k/10k/30k 块，不接触生产资料；通过人工写入的受控合成普通库行构造容量，不代表真实导入/掉电全链路验收。常规行有 7 个中文字符和英文/编号，查询固定唯一英文词；没有用该夹具证明中文召回质量。以下数据来自 `.cache/test-logs/2026-10-29-l0-fts-profile-closeout-89fe2e2/`：

| 块数 | 原文 UTF-8 字节 | FTS p50 / p95 ms | 旧全量路径 p50 / p95 ms | 索引维护总 ms / 批次 | 派生逻辑页增量字节 |
|---:|---:|---:|---:|---:|---:|
| 1,000 | 38,863 | 1.04 / 1.38 | 8.70 / 16.05 | 160.66 / 4 | 348,160 |
| 10,000 | 398,862 | 2.44 / 2.76 | 60.15 / 63.42 | 1,559.25 / 40 | 2,867,200 |
| 30,000 | 1,218,861 | 6.76 / 10.74 | 201.43 / 234.57 | 5,730.99 / 118 | 8,384,512 |

每组 7 次观测，p95 为该小样本的最大观测值，不作统计稳定性承诺。三组 FTS 正常路径均候选读回 1、全文扫描 0。旧路径实际执行 `captureLocal` 的全部正文读取/hash 与 `unifiedLocalDirect`，相同语料和查询，候选相同。主进程 heap 观测分别约 94.0 / 86.0 / 163.2 MB，受共享 harness 和 GC 影响，不能归为索引独占内存；逻辑页增量来自内存 SQLite 页统计，不是真机磁盘测量。

实现采用保守的 256 行/批、2 MiB 应用处理/批、1 秒处理检查点；候选窗口 256+1，字面页用 id seek，不重复读取已经消费的块。正文超过 30k 明确拒绝；这只是源码预算上限，不声明目标手机/平板已支持 30k 或 2 MiB 大块。索引和扫描仍需目标设备标定，单次 ArkData 调用没有可抢占超时保证。
