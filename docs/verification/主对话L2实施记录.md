## 1. 授权与实现范围

用户批准 spec 11 v0.3 的“授权开关 + 模型自主调用”开发，并明确允许以仓库 ArkTS 约束及本机编译器替代缺失的 `arkts-grammar-standards`。没有新增依赖、系统权限或模型供应商；复用已有 SDK、RDB、模型及 Embedding 能力。

- `RuntimeAssistantCoordinator` 只为主助手准备一个模型会话，不再复制 Key 给独立知识库回答任务。消息统一走 `RuntimeChatService.session.send`。
- `ModelLoopToolsPort` 为工具循环提供可组合端口；`ModelKnowledgeTools` 按会话授权提供工具定义和允许函数名，`tool_choice=auto` 由同一模型选择。开启时可选允许语义查询或仅本机检索；两者都明确需要命中片段发送给 DeepSeek。取消弹窗不授权。
- `KnowledgeAgentRuntime` 注册 `native://shuvi/knowledge.search` / `knowledge_search` v1.0.0，经生产 Runtime 的参数、许可、预算、持久化派发与结果记录后执行。原 `knowledge.search.local` v1 契约不变。
- `KnowledgeAgentSearchAdapter` 使用现有统一生产 scope、查询服务和物理向量库。每次独立查询，不复用 UI `querySession`；L1 不可用时采用现有统一字面策略，实际标注 `literal-scan`，不冒称 FTS5。
- 模型工具参数严格校验 `query / keywords / topK / mode`；原问题、turn/toolCall、授权修订、外发许可和 deadline 由宿主注入并进入 checkpoint。`role=tool` 回同一 loop；最终结构校验、真实来源编号和当前世代可见性校验后才标为知识库回答。
- 累计去重最多 5 条/3200 字符，单条 800；最多 2 次检索、3 次模型请求、会话共享 10 次 HTTP 请求；沿用主助手 6 工具总上限，90 秒请求墙钟与 UI watchdog 对齐。工具第三轮被禁用，不执行模型忽略 `tool_choice=none` 后给出的调用。
- 开关/新对话修订清除后续模型历史；在途结果经取消令牌和许可修订拒绝。仅重试回答复用冻结证据、禁止声明检索工具，仍重验来源。

## 2. 恢复、费用与存储兼容

`KnowledgeAssembly.acquire(true)` 恢复本机资料及配置，不初始化自动入库队列；前台恢复也只对已初始化处理队列执行。随后知识库页面正常 acquire 时才按既有入库许可启动队列。复用 `shuvi_kb_user_v1.db` 与 `shuvi_kb_vector_v1.db`，没有新建语料或重嵌入历史资料。

查询许可通过 `KnowledgeQueryAuthorization` 按 query session、epoch、授权修订和实时取消令牌绑定。既有 `upd_grant` 的 JSON 元数据增加可选 `queryGrantRevision`，旧记录缺失时按 0 解析，沿用原策略；新 query-only 授权在最终消费处核对内存有效许可，因此不能跨进程复活。没有新增 DDL 或更改普通/向量语料布局。查询与自动入库的 enabled/paused/费用同意分开，但配置绑定、技术 baseline、token 资格、当前 scope 与持久化准入仍保留。

新增 `shuvi_knowledge_agent_execution_v2.db` 仅保存工具执行证据，复用已有加密执行恢复结构，不充当语料权威。结果账单未知时用现有 PendingInvoice 保留未结算记录；`XXX` 是本机复合执行记录的未识别币种占位，usage 为 unknown，不是供应商回执或真实费用。工具预留上限 20000 micros 是工程上限，不能视为报价/账单；没有可信供应商账单时不按零费用结算，也不自动重发可能计费的请求。
