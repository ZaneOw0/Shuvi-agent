## 1. 本次变更及边界

补入 `native_tools` 0.1.1 和 `agent_testkit` 0.6.0，共新增 31 个原始模块文件，包含四个测试文件。八模块合计 224 个来源文件、40 个 `src/test` 文件。生产源码保持 Git blob 原样；八模块包声明 Apache-2.0。

`tests/agent-host/` 导入上游宿主、设备测试和资源 23 个文件，另以主仓库配置创建独立工程入口。只修改三处来源文件：宿主 OHPM 相对路径、AppScope 应用包名，以及生命周期测试中的启动包名。每个文件在宿主 `UPSTREAM.json` 分别记录原始哈希、导入后哈希和适配原因。

`tools/agent/fixture/` 保留三个原始文件，提供确定性 MCP 协议测试服务。本轮没有复制或运行上游 Git 改写、工作区迁移、设备安装/卸载和发布打包脚本。

独立宿主引用同一套模块源码，产品工程仍只注册原六模块。没有向产品添加本地工具或 TestKit 依赖，没有改变产品权限、模型服务、业务契约或签名配置。测试宿主包名为 `com.example.shuvi.agenttest`，不会按配置覆盖产品包或原上游测试包；实际安装仍待验收。

本次遵循 `openharmony-development` 的 Windows DevEco、toolchain 与 testing 路由。`arkts-grammar-standards` 未安装，继续沿用此前已批准的替代资料与实际编译校验。本轮没有新增或重写平台 API 实现，仅迁移现有模块和测试。

## 2. 环境和复验入口

Windows、Node.js 24.14.1、DevEco Studio 26.0.0.821 配套工具、HarmonyOS API 26。测试工程沿用主仓库 Hypium 1.0.25 / Hamock 1.0.0，没有采用上游 Hypium 1.0.28。OHPM 在测试工程下生成锁文件。

入口见 [独立测试宿主 README](../../../tests/agent-host/README.md)。`scripts/test-agent-unit.ps1` 顺序执行模块测试，保存逐模块日志及报告并检查新鲜度、退出码、用例数和失败/忽略数，不以 `BUILD SUCCESSFUL` 单独判断测试通过。

首次沙箱内 OHPM 下载返回网络 EACCES，首次测试工程构建返回用户 Hvigor 缓存目录 EPERM；使用正常权限重试相同步骤后成功。这两次为环境限制，不是测试断言失败，没有修改代码、降级依赖或放宽规则绕过。
