# 02 平台基线

本文维护工程配置与工具版本。当前工程运行系统为 HarmonyOS；目标 OpenHarmony 发行版、硬件及兼容接口仍需单独确认。

## 1. 工程基线

| 项目 | 当前值 |
|---|---|
| runtimeOS | HarmonyOS |
| compatible / target SDK | 26.0.0，API 26 |
| SDK 包 | 26.0.0.105 |
| modelVersion | 26.0.0 |
| 产品 | default，debug / release |
| 应用 | com.example.shuvi，Stage entry HAP，phone / tablet |
| Agent 模块 | 八个 HAR，产品使用原六模块及 native_tools；agent_testkit 用于独立测试 |
| 测试宿主 | tests/agent-host，com.example.shuvi.agenttest |
| 权限 | INTERNET、MICROPHONE、READ_CALENDAR、WRITE_CALENDAR，按功能检查和申请 |
| 签名 | 入库 build-profile 为无签名模板，本机缓存与临时装配不入库 |

配置以根 `build-profile.json5`、`oh-package.json5`、`hvigor/hvigor-config.json5` 和 `entry/src/main/module.json5` 为准。

## 2. 配套工具

| 工具 | 基线 |
|---|---|
| DevEco Studio / CI CLT | 26.0.0.821 |
| Hvigor / OHOS 插件 | 6.26.4 |
| OHPM | 26.0.0.630 |
| DevEco Code CLI | 1.3.2 |
| IDE / CLT 配套 Node | 24.14.1 |
| CI JDK | 21 |

使用前核对 `node --version`、`devecocli --version` 和实际命令来源。PATH 可指向其他 Node，脚本与 SDK compiler 应使用明确的配套工具；本机路径通过环境配置管理。

Windows 使用 Git for Windows Bash 执行 `.sh`，`.cmd` 包装器避免调用 System32 的 WSL bash。CI 的 CLT_HOME、JAVA_HOME、DEVECO_SDK_HOME、CODELINTER_LOG_DIR 由 runner 环境提供，见 [持续集成](deployment/持续集成.md)。

## 3. 构建与验证边界

修改 ArkTS 后先静态检查，再运行 `devecocli build`；构建成功后才安装运行。完整日志按 [协作约定](01-协作与工程约定.md) 落盘。

HarmonyOS 模拟器、真实手机/平板与 OpenHarmony 真机分别验收。SDK 包内存在 openharmony 目录只说明工具布局，目标系统能力仍需实际验证。手机和平板使用同一 HAP，布局契约见 [spec 15](../specs/15-平板端适配与手机功能一致性验收.md)。

## 4. 升级与维护

SDK、插件、依赖、系统权限和服务变化单独评审。生成目录、私有路径、Key 和签名材料不入库。当前功能与证据统一见 [项目进度](08-项目进度与验收.md)。
