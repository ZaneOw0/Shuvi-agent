# 02 平台基线

> 本文是工程平台、SDK 与工具链版本的统一记录。项目目标见 [00-项目总览](00-项目总览.md)，协作规则见 [01-协作与工程约定](01-协作与工程约定.md)。
> 本次通过只读检查工程配置、安装元数据与既有报告核验，未执行构建、安装或设备测试。

## 1. 基线状态与适用范围

项目计划使用 ArkTS / ArkUI、DevEco Studio 和 DevEco Code，面向开源鸿蒙社区竞赛开发。

当前工程配置的运行系统为 **HarmonyOS**，本机已安装的配套 SDK 为 **HarmonyOS 26.0.0，API 26**。赛事要求的 OpenHarmony 发行版、目标设备及可用接口范围仍需确认，不能仅凭 SDK 内包含 `openharmony` 目录认定工程满足赛事要求。

本文区分三类状态：

- **已配置**：工程文件中明确声明。
- **已安装**：本机安装元数据可核实。
- **已验证**：有对应构建、运行或真机验收证据。

已配置、已安装不等于已经通过整套兼容性验证。

## 5. 待确认与能力验证

进入正式功能开发前逐项补齐：

| 待确认项 | 需要形成的结论 |
|---|---|
| 赛事平台 | 允许的系统发行版、SDK、设备、应用身份与交付格式 |
| 目标设备 | 型号、系统版本、API、屏幕形态及可用系统能力 |
| 开发工具 | 三人实际使用的 IDE、DevEco Code、SDK 与工具链版本 |
| 签名安装 | 签名方式定为本机自动生成、材料不入库；模拟器安装启动通过，真机证书与安装结果待验证 |
| LLM 接入 | 服务商、模型、多模态能力、流式协议、鉴权和额度 |
| 日历与提醒 | 权限范围、系统日历、代理提醒与通知跳转 |
| 文件与个人知识库 | 文件访问范围、离线存储、检索与问答运行条件 |
| 多模态与长语音 | 输入来源、录音/上传、识别与摘要能力及资源限制 |
| 多设备与协同 | 设备矩阵、登录身份、任务和上下文流转条件 |

验证用于明确实现方式与限制，不自动改变 00 中的需求优先级。需要调整需求时，由团队确认并同步文档。

## 6. 维护与升级约定

- 公共 SDK、modelVersion、构建工具或依赖升级单独评审，不随功能改动隐式升级。
- 配置变更与本文在同一 PR/MR 中更新，记录原因、影响和验证结果。
- 成员接入或 CI 建立时，对照本基线核验实际工具来源与版本。
- 后续版本验证至少覆盖工程同步、构建、签名安装及受影响的目标设备能力。
- 构建通过、模拟器通过和真机通过分别记录，不互相替代。
- 私有路径、密钥和签名密码通过本机配置管理，不写入本文或公共工程模板。
- 项目状态变化后及时替换过期结论，避免把启动阶段快照当作长期运行状态。
- CI 工具链版本须与本节记录一致；路径与运行细节由 `.github/workflows/ci.yml` 与 `scripts/ci-windows.cmd` 维护，不写入本文。
