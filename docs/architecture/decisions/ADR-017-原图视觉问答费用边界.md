# ADR-017：原图视觉问答费用边界

> 状态：已实现边界待验收（仅会话/请求边界；真实图片计费未实现）。
> 更新日期：2026-10-26。
> 关联：[spec 08](../../../specs/08-原图视觉问答.md) · [设备验收清单](../../verification/原图视觉问答设备验收清单.md)

## 背景

原图视觉问答直接调用 DeepSeek 视觉接口。当前仓库没有可信的图片输入计费单价，也没有导入供应商实际账单；因此不能把任何本地 token 估算或固定 micros 值当作真实图片费用上限。`VisionAnswerRuntimeAssembly` 中的 `maxMonetaryCostMicros = 10000` 只是 Agent 的本地预算门槛，不是供应商扣费保证。

## 决策

1. **当前仅 debug 验收，不宣称生产可用。** `VisionAnswerRuntimeFactory` 要求 `debug=true`；真实调用必须由用户显式同意并在设备上输入会话 Key。
2. **按请求数设硬边界，而不是伪造金额边界。** 每次启用最多 10 次模型请求；每次只允许一张图片；无自动重试/恢复。第 11 次在 `RuntimeVisionSession` 层直接拒绝，不提交任务。
3. **费用状态显式标记“未核账”。** `RuntimeVisionView.pricingState = 'unverified'`；不显示虚拟金额、credits 结算或“已扣费”结论。供应商返回的 token 用量可以记录，但不等于实际账单。
4. **取消/失败不承诺免费。** 取消只保证停止本地等待和丢弃迟到结果；已发出的请求仍可能计费，实际以 DeepSeek 账单为准。
5. **生产启用必须另有可信计费依据。** 至少满足以下之一后才能去掉“未核账”：
   - 经评审的图片/视觉计费单价与预算结算实现；
   - 可核对的供应商逐请求账单导入；
   - 用户显式配置、可强制执行的金额预算（仍需供应商侧证据）。
   在此之前，真实请求只用于受控验收，不作为正式费用能力。

## 已实现的边界

- `VISION_ANSWER_MAX_REQUESTS = 10`、`VISION_ANSWER_PRICING_STATE = 'unverified'`。
- `RuntimeVisionView.requestCount / maxRequests / pricingState` 暴露给调用方；第 11 次返回 `false` 并显示请求上限消息。
- `start()` 重新启用时重置 `requestCount`；停止/后台不自动重置已发送请求的计费事实。
- 单张图片 ≤20MB/≤20MP，重编码后 ≤8MB/最长边 ≤2048；一次只处理一张。
- 执行库最多 128 条；无自动清理、恢复或重发。
- 现有 `maxMonetaryCostMicros=10000` 保留为本地 Agent 预算门槛，文档与 UI 不得把它描述为图片费用上限。

## 代价与风险

- 请求数上限不能替代金额控制：单次图片请求可能高于本地估算，仍可能产生超出预期的账单。
- 没有账单导入时，不能证明实际扣费、余额或退款；验收记录只能写“未核账”。
- 10 次上限是会话级，不是账户级；重新启用会重置请求计数，不能当作跨会话预算。
- 2026-10-26 已用 host 脚本完成一次真实 DeepSeek 视觉请求（452 prompt/25 completion tokens，HTTP 200，回答含 `[1]`）；Key 未进入对话/日志/仓库。该请求不等于设备 ArkTS transport、账户账单、余额或退款能力已验收；实际扣费仍未核验。
