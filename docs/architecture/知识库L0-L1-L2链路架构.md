# 知识库 L0 / L1 / L2 链路架构

> 状态：统一接口已接入页面与主助手，设备引擎、质量与性能按场景验收。

## 1. 共同底座

```mermaid
flowchart TD
  PAGE[知识库页面查询] --> L0[KnowledgeLexicalSearchPort]
  TOOL[主助手 knowledge_search] --> L0
  L0 --> FTS[klex 派生 FTS 主召回]
  FTS --> VERIFY[当前原文与版本核验]
  L0 --> LITERAL[有界字面补充或降级]
  VERIFY --> RESULT[片段 来源 引擎 覆盖 续查]
  LITERAL --> RESULT
  RESULT --> PAGE
  RESULT --> TOOL
```

L0 使用统一查询规范，区分 Keyword / Literal 和真实引擎。资料身份、generation、epoch、标注及当前成员状态决定候选有效性；历史卡片存储不作为语料变化。

## 2. L1 语义检索

```mermaid
flowchart LR
  Q[用户问题及语义授权] --> EMB[当前 Provider 查询向量]
  EMB --> SPACES[兼容且合格的物理空间]
  SPACES --> KNN[本机 KNN 与来源核验]
  KNN --> HITS[真实语义结果]
```

兼容性按 Provider、区域/工作区、模型、维度、预处理、tokenizer、角色、归一化与供应商版本等条件判定。已有向量保持原空间和回执，配置修订变化不自动删除或重嵌入。

## 3. L2 自主知识库工具

```mermaid
flowchart TD
  CHAT[主助手授权会话] --> MODEL[同一模型工具循环]
  MODEL --> KS[knowledge_search 经 Registry 与 Runtime]
  KS --> SEARCH[共享 L0 与允许的 L1]
  SEARCH --> EVIDENCE[有界证据与来源]
  EVIDENCE --> MODEL
  MODEL --> ANSWER[校验回答与引用]
  ANSWER --> UI[聊天与来源卡片]
```

每轮最多两次知识查询，累计最多 5 条 / 3200 字符。命中来源及派生上下文仅在本次授权会话使用；持久 UI 快照与普通模型记忆分别管理。

## 4. 实现入口与验收

| 落点 | 职责 |
|---|---|
| KnowledgeLexicalSearchPort / KnowledgeLexicalRepository | L0 端口与派生索引 |
| KnowledgeQuerySession / UnifiedQueryService | 页面查询、L1 授权和结果 |
| KnowledgeAgentSearchAdapter / KnowledgeAgentRuntime | 工具查询与 Runtime 派发 |
| ModelKnowledgeTools | 工具定义、证据预算与引用收尾 |
| ChatKnowledgeSources | 即时来源绑定和历史卡片恢复 |
