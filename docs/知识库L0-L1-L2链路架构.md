## 1. L0：统一关键词检索

```mermaid
flowchart TD
  PAGE[知识库页面 KnowledgeQuerySession] --> PORT[KnowledgeLexicalSearchPort]
  AGENT[L2 KnowledgeAgentSearchAdapter] --> PORT
  PORT --> REPO[KnowledgeLexicalRepository / 同一生产普通库]
  REPO --> INPUT[query、keywords、intent、归档范围、游标与取消校验]
  INPUT --> REV[klex_state / 普通库修订与索引状态]
  REV --> MAINTAIN[恢复一批索引维护 / 断点读回]
  MAINTAIN --> ROUTE{实际索引状态与查询意图}
  ROUTE -->|Ready 普通关键词| FTS[klex_fts / 参数绑定 OR MATCH / 候选窗口]
  FTS --> READ[仅候选正文或当前有效描述读回]
  READ --> CHECK[generation、effectiveId、hash 校验]
  CHECK --> WORD[Keyword 证据 / 实际排名]
  CHECK --> RANGE[原文 Literal 范围 / UTF-16 高亮]
  FTS -->|零候选或 MATCH 失败| SCAN[有界字面扫描]
  ROUTE -->|精确短语、单字、不可用或恢复中| SCAN
  SCAN --> CHECK2[原文 hash 校验 / 实际命中范围]
  WORD --> MERGE[稳定身份合卡 / 多父图片 / 窗口内排序]
  RANGE --> MERGE
  CHECK2 --> MERGE
  MERGE --> RESULT[真实引擎、命中类型、覆盖、状态与续查游标]
  RESULT --> PAGEOUT[页面每页最多 10 张 / 历史兼容 / 来源重验]
  RESULT --> AGENTOUT[L2 topK 与片段外发预算 / 引用重验]
  DB[upd_* 普通库提交] --> TRIGGER[klex_* 普通表触发器 / 修订递增并标 Stale]
  TRIGGER --> REV
```

2026-10-29 修复增量：`upd_asset` 触发器只跟踪当前图片 occurrence 引用的资产，历史快照写入不再改变语料 revision，避免搜索自身保存历史后误撤销 L1 review。真实正文/归档/图片变化的失效检查保留，详见验证记录新增修复章节。

生产装配由 `KnowledgeAssembly` 创建一个 `KnowledgeLexicalRepository`，注入页面会话、独立 RAG 会话和 L2 adapter。正常路径不再先调用全量 `captureLocal`；读取文档/图片/标注元数据后，只读回 FTS 候选的正文。L0 不打开向量库、不发模型请求，也不受 Embedding Key 就绪与否限制。

正文、OCR、公式按原 chunk 的 evidence 返回；有效图片描述经 `unifiedProxyText(description,tags)` 的 hash 校验后检索，实际证据只取 description。标题与 tags 不拼入正文、不单独作为事实证据；既有 tags 相关结果仍保留。OCR 图片与描述通过图 hash、有效标注和父来源合卡。

请求规范版本为 `UNIFIED-LEXICAL-1`。普通词项 OR 召回，FTS 表达式由应用转义并绑定。引号短语选择字面模式，单字符显式走短词补检。FTS 返回 Keyword 时不要求完整问题连续出现；有原文范围时标 Literal，并合并重叠区间，保持代理对边界。历史 codec 可读取旧记录缺失的新增字段。

正常查询维护完成后使用 FTS；未完成时明确恢复/部分范围状态。维护和扫描每批最多 256 行，应用处理预算 2 MiB / 1 秒；不是数据库调用可被抢占的硬超时。每批保存 phase/cursor，取消或后台使下一检查点停止，重新打开后由新的本机查询继续。维护由能力检查初始化、查询推进，不在后台静默遍历全库；大库首次恢复可能需要多个请求/续查。

FTS 以实际排名取候选窗口；窗口内按字面命中、可核命中词覆盖、FTS 排名与稳定 ID 排序。分页追加已计算的卡，不承诺跨窗口全局重排。字面扫描游标绑定 query、词项、intent、归档范围和 scope revision，续查不重复消费已扫描块；scope 变化要求新查询。扫描尚有范围时返回 partial，页面不显示全库无命中。

### 旧 L0 对照（重构前）

```mermaid
flowchart LR
  PAGE[页面 / L2 adapter] --> CAPTURE[captureLocal 全量读取正文并 hash]
  CAPTURE --> DIRECT[unifiedLocalDirect]
  DIRECT --> MATCH[unifiedDirectRanges / knowledgeMatch]
  MATCH --> RESULT[合卡 / 分页 / 引用]
  OLD[旧 M1 TextRdbRepository] --> FTS[text_fts / FTS 或 LIKE]
```

旧 `text_fts` 仅服务 `text_*`；本轮没有将统一语料重新导入 M1，没有删除旧表、原件、向量或历史。旧 Runtime local v1 adapter 的独立字面契约保留；主对话 L2 和统一页面使用新的统一端口。

## 2. L1：查询向量与合格空间语义检索

```mermaid
flowchart TD
  REQUEST[页面显式语义搜索 / L2 语义请求] --> SESSION[独立 KnowledgeQuerySession]
  SESSION --> LOCALREV[重验本轮 L0 scope revision]
  LOCALREV --> REVIEW[UnifiedQueryService.review]
  REVIEW --> AUTH[配置、基线、token 证据与费用授权]
  AUTH --> CAPTURE[UnifiedQueryRepository.capture]
  CAPTURE --> TARGETS[当前正文、标注、binding、job 与兼容空间资格]
  TARGETS --> GRANT[持久化一次性 query 授权]
  GRANT --> ADMIT[approve / admitUnified / 发起前重验]
  ADMIT --> EMBED[Embedding transport 生成查询向量]
  EMBED --> RESPONSE[模型、维度与当前 scope 重验]
  RESPONSE --> KNN[逐个兼容空间 filteredKnnAll]
  KNN --> VERIFY[距离排序 / 目标身份与空间重验]
  VERIFY --> CARD[unifiedSemanticCards / Vector reason]
  CARD --> FUSE[与本机 Tag 候选显式排名融合]
  FUSE --> OUT[可见性重验 / 分页 / 来源]
```

本轮 L1 的模型、向量维度、空间与入库授权规则保持现有实现。显式启动语义查询时，原有全量语义资格捕获仍保留；其成本不能算作 L0 正常检索成本。Embedding 失败保留已取得的 L0 原文。

这里的 L1 指语义检索，不等于 spec 02 历史称作 L1 的“在线生成回答”。L0 重构不证明冷启动旧向量资格缺陷已修复。

## 3. L2：主对话 Agent 工具循环

```mermaid
flowchart TD
  CONSENT[用户开启会话知识库授权] --> TOOLS[ModelKnowledgeTools / 当前许可工具集合]
  USER[原始问题与有界上下文] --> MODEL[主对话模型 / DeepSeekToolTransport]
  TOOLS --> MODEL
  MODEL --> CHOICE{需要查询个人资料吗}
  CHOICE -->|无需查询或需澄清| GENERAL[普通回答 / 澄清]
  CHOICE -->|knowledge_search| REGISTRY[KnowledgeAgentRuntime / ToolRegistry]
  REGISTRY --> GUARD[参数、许可修订、调用预算与截止时间]
  GUARD --> ADAPTER[KnowledgeAgentSearchAdapter]
  ADAPTER --> MODE{mode 与 query 外发许可}
  MODE -->|允许语义| L1[L1 独立 RAG 会话 / query embedding / KNN]
  MODE -->|direct 或未允许 query 外发| L0[统一 L0 端口]
  L1 -->|失败或无候选| L0
  L1 -->|有候选| EVIDENCE[当前有效证据]
  L0 --> EVIDENCE
  EVIDENCE --> LIMIT[合卡 / topK / 片段裁剪 / 引用重验]
  LIMIT --> TOOL[实际通道、Keyword 或 Literal、证据类型与 partial]
  TOOL --> LOOP[role=tool / tool_call_id 返回同一模型循环]
  LOOP --> MODEL
  MODEL --> ANSWER[本轮引用校验 / 回答与来源展示]
```

L2 通过 Registry 使用知识库应用端口；本机模式直接调用统一 L0，不再先全量读取正文或在 adapter 逐个关键词扫描。语义路径使用独立会话与临时历史，不复用页面全局查询状态。

L2 保持最多 5 条来源、单片段最多 800 字符和本次总片段 3200 字符限制。L0 首窗不足时最多续查一次，仍有范围时保留 partial/hasMore；不能把预算内未找到当成全库 empty。查询外发、片段外发与本机读取仍由宿主分别约束；模型不能传入数据库路径、SQL 或归档范围。

工具结果携带实际 engine、matchKind、evidenceType；模型侧不再把所有本机结果强制标为 Literal。关闭授权撤销工具与未完成任务；回答失败保留已取得来源。图示只说明实现链路，不证明模型检索决策和事实质量已验收。
