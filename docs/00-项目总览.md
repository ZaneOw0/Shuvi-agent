# 00 项目总览

> 状态：项目启动阶段。本文区分当前事实、建议基线与待确认事项；架构方案需随平台验证和功能 spec 收敛。

## 1. 项目定位与目标

休比（Shuvi）是面向开源鸿蒙社区竞赛开发的智能个人助理，使用 ArkTS / ArkUI 辅助开发。

产品目标：理解用户通过文字、图片或语音表达的个人事务需求，由 Agent 主控协调专业子智能体，将建议转化为可确认、可执行、可追溯的操作。

项目需求层级由团队持续维护，具体范围见第 2 节。

实际工程配置、工具版本与验证状态统一记录在 [02-平台基线](02-平台基线.md)，本文不重复维护。

## 2. 功能范围与需求层级

以下需求层级由团队持续维护，不代表范围已经冻结或功能已经实现。具体行为、平台约束与验收标准在对应功能 spec 中逐步明确。

| 优先级 | 功能 | 当前需求说明 |
|---|---|---|
| P0  | AI 对话 | 集成 AI 导航与 App 使用说明 |
| P0  | 文件管理 | 具体范围在功能 spec 中细化 |
| P0  | 日历日程 | 集成系统提醒与备忘录 |
| P0  | 构建个人知识库 | 支持个人知识库离线检索与问答 |
| P0  | 联网搜索 | 具体范围在功能 spec 中细化 |
| P0  | 多模态输入和交互 | 支持文字、图片、语音，理解复合指令 |
| P0  | 多设备适配和登录 | 支持多设备适配与登录 |
| P0  | 主题切换与自定义 | 支持主题切换与自定义 |
| P1  | 跨设备协同 | 流转任务和上下文 |
| P1  | 智能体编排 | 至少 3 个子 Agent 协同，自主分解复杂任务 |
| P1  | 长语音转写 | 录制或上传长语音音频，提取原文转写与 AI 摘要 |

功能优先级与实现状态分别管理。平台验证用于明确实现方式、限制与待决事项；调整需求范围或优先级须由团队确认，不由实现方自行删减或降级。

## 3. 架构建议与模块边界

建议采用单仓库、一个 entry HAP，以及按需建立的核心与平台适配 HAR；不按成员或子智能体拆独立服务。

应用链路：

`ArkUI → 应用服务 → Agent 主控/子智能体 → 行动草稿 → 确认与校验 → 工具执行 → 平台能力`

| 模块 | 职责 |
|---|---|
| entry | 页面、交互状态、生命周期、路由及依赖装配 |
| assistant_core | 领域对象、应用用例、Agent 编排、契约、规则校验 |
| platform_adapter | LLM 网络、日历、提醒、多媒体、权限与存储适配 |

依赖约定：

- entry 组装核心与平台实现。
- 平台适配器实现核心声明的接口。
- 核心不引用页面和具体平台适配器。
- 模块通过显式接口协作，禁止循环依赖和跨模块访问内部实现。
- 页面不直接调用模型、写系统日历或处理跨模块业务事务。

工程目录及模块配置由选定版本的 DevEco 工具链建立，上述名称和拆分属于建议基线。

## 4. Agent、数据与执行原则

Agent 主控负责复杂任务分解、子智能体协同和结果汇总。P1 智能体编排要求至少 3 个子 Agent 协同；具体身份、职责、调用关系及验收场景在架构设计与功能 spec 中确定。

确定性系统操作通过统一工具接口执行。智能体共用模型调用、工具注册、输入输出校验、权限控制、超时、有限重试、预算和追踪机制，具体委派深度与并发限制由验证结果确定。

模型只产生候选动作。工具执行必须同时满足业务校验、当前系统权限和用户确认要求；不能把 Prompt 或工具白名单当作操作系统授权。

| 数据 | 权威来源 |
|---|---|
| 会话、草稿、操作记录 | 应用本地存储 |
| 已写入系统的日历事件 | 系统日历；应用保存事件 ID 与关联 |
| 提醒注册状态 | 系统能力；应用保存提醒 ID 与关联 |
| 权限状态 | 操作系统当前状态 |
| 模型回答 | 待验证的建议，不直接作为执行事实 |

操作须有稳定 ID，区分待澄清、待确认、执行中、成功、部分成功、失败和取消。响应丢失时先核查原操作结果，不盲目重建；日程成功但提醒失败时应保留结果并允许补救。

应用进程被回收后，不假设 Agent 自动续跑。已注册提醒由系统管理；未完成操作在回访时恢复、核查或明确重试。界面不得将“草稿生成”“日程创建”“提醒注册”“提醒送达”混为成功。

发布本应用通知与订阅其他应用通知是不同能力；应用存活期间的定时器不能替代系统代理提醒。日历提醒与独立代理提醒应明确选用策略，避免重复提醒。

## 5. 质量与交付目标

- 正常、异常、权限拒绝、模型失败四类路径均有验收案例。
- 时间解析覆盖相对日期、时区、跨天、缺失信息及必要的重复规则。
- 模型输出经过运行时校验；错误或不确定信息不得直接触发写入。
- 页面具备加载、空态、失败、取消和可恢复反馈，并考虑不同屏幕、字体缩放及可访问性。
- 记录操作 ID、失败阶段、耗时、模型与提示词版本、用量；日志不包含密钥和无关个人数据。
- 首版使用固定样例评测和目标设备验收，区分 Mock、真实模型、模拟器与真机结果。
- 每个里程碑提供可安装制品、提交版本、验收记录和已知限制。
