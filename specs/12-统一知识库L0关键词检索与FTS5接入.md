# 12 统一知识库 L0 关键词检索与 FTS5 接入

> 状态：已实现待验收。页面和主对话共用关键词端口，设备引擎、质量与性能仍需验证。

## 1. 用户流程

1. 用户在知识库查找内容，或授权助手调用知识库工具。
2. 通过统一查询规范执行关键词主召回与原文核验，按需要进行有界字面补充或降级。
3. 展示片段、命中类型、来源、实际引擎及覆盖；还有候选时允许继续查找。
4. 资料发生变化时重新查询，不把旧问题授权用于新语料。

## 2. 页面事项

- 区分 Keyword / Literal、FTS 主召回、补充与降级；索引缺失或失败不能显示为完整覆盖。
- 保持已有正文、图片代理及来源预览能力。候选原文高亮与排序依据可解释。
- 本机搜索历史保存不使当前问题失效；归档、删除、正文与图片标注变化按语料修订规则生效。

## 3. 业务与 Agent 事项

`KnowledgeLexicalSearchPort` 和版本化查询规范为页面、L2 adapter 提供共同入口，`KnowledgeLexicalRepository` 维护 `klex_*` 派生索引。规范化文本、原件和用户修正继续由现有权威存储负责。

FTS 候选须读回当前原文验证；精确短语、单字符、零候选及索引不可用时采用有界字面路径。窗口内稳定排序与去重，结果携带引擎、覆盖与续查信息，不借全库无界预读保证表面成功。

图片使用 OCR / 描述 / 标签等文本代理，结果关联真实 occurrence 和父文档；用户修正、生成版本、归档、删除与 epoch 一致性仍校验。

资料成员修订只跟踪真实语料变化。资产触发器仅在当前图片引用的资产变化时递增修订，历史搜索卡片和 manifest 写入不会误使 L1 问题失效。

L1 查询向量、Provider 配置与合格空间规则独立；L0 派生索引重建不触发重新解析或全库外发。旧数据升级复用现有内容与向量，不清库。

## 4. 平台能力

使用 API 26 配套 RDB / FTS 能力与本机派生索引。FTS、tokenizer、事务和回退在目标设备分别验证；索引能力不可用时保留真实降级状态。

无新增系统权限、模型供应商或服务。索引迁移与重建保留当前 schema 兼容和所有权边界。

## 5. 验收方式

| 路径 | 验收重点 |
|---|---|
| 正常 | 中英文、短语、单字、符号、OCR/描述、稳定排序、分页续查与双入口一致 |
| 异常 | 索引缺失/陈旧、预算耗尽、部分覆盖、旧数据恢复、资料变更与历史保存 |
| 授权拒绝 | L0 本机检索不启动未授权外发；拒绝 L1/L2 不影响已有本机结果 |
| 模型失败 | 嵌入/回答失败不污染 L0，降级明确且引用仍有效 |

命令、日志、性能样本和设备限制见 [L0 验证记录](../docs/verification/知识库L0重构验证记录.md)。设备 FTS/tokenizer、真实召回质量、跨页稳定性和大型语料预算待验收，host 结果只证明其用例范围。
