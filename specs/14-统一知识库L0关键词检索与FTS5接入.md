## 1. 目标与范围

统一 L0 为：**FTS5 主要关键词召回 → 当前原文与资格读回 → 字面命中校验/高亮 → 有界字面匹配补充或降级 → 去重、排序和可引用证据**。知识库页面与主对话工具调用同一知识库应用接口。

| 层级 | 最新定义 | 本次范围 |
|---|---|---|
| L0 | 本机关键词检索，FTS5 主召回，保留字面匹配校验和降级 | 本 spec |
| L1 | 由知识库模块生成查询向量，在当前合格空间中进行语义检索 | 保持现有方向，不因 L0 改造变更模型、向量或授权 |
| L2 | 模型规划查询、通过 Registry 调用 L0/L1、接收工具结果并总结回答 | spec 13，消费本 spec 的 L0 能力 |

当前统一路径是 `KnowledgeQuerySession → captureLocal → unifiedLocalDirect → unifiedDirectRanges/knowledgeMatch` 的逐块字面匹配。旧 `TextRdbRepository` 已有 `text_fts`、能力探测和 FTS/LIKE 分支，但对应 `text_*` 资料，不能直接作为当前 `upd-*` 统一语料索引。本次复用已验证机制与经验，面向统一数据重新适配。

范围包括统一正文、OCR、公式文本、图片有效描述的检索与证据定位；标题和 tags 可辅助召回，不能单独支持事实断言。只检索本机已校验发布的内容，遵守当前世代、归档、删除、标注与多父来源规则。

非目标：向量空间/模型迁移、修复尚未定位的冷启动向量资格根因、云同步、重新解析原件、调用模型提炼关键词、添加分词依赖或原生扩展、删除旧表/历史数据。L0 不依赖模型、Key、网络或自动向量入库设置。L2 的关键词提炼由 spec 13 定义，不能成为页面离线搜索的前提。

## 2. 用户流程

1. 用户在知识库页面输入词或短语，直接执行本机 L0；不要求配置 Embedding 或启用在线回答。
2. 应用在已发布的当前语料上执行 FTS5 候选召回，读回原文与有效身份，返回关键词证据；存在连续字面命中时生成高亮。
3. 引号包围的短语、未被分词器覆盖的短词/子串，以及索引不可用或恢复中的情况，按第 4 节使用保留的字面匹配。不会把普通空结果解释成索引故障，也不会静默遍历无限语料。
4. 用户查看结果、命中方式和来源原文。FTS 词项命中没有连续字符串时仍可呈现为“关键词命中”，不伪造连续高亮。
5. 用户可另行启动 L1 查询向量语义检索。L1 失败保留已得到的 L0 结果；L0 的正常运行不发送向量请求。
6. 主对话 L2 使用同一服务传入提炼后的 keywords/query，接收相同语料范围与证据规则下的 L0 结果，再由 Agent 总结；L2 的 topK 和外发预算仅影响该调用，不限制页面全部分页结果。
7. 重启后旧资料无需重新解析或重新嵌入即可恢复 L0；索引需恢复时明确状态，在预算内使用字面降级，不能要求先导入新文件来解锁。

## 3. 页面事项

- 主结果组名称采用“关键词命中”，区分“原文字面命中”和“分词关键词命中”；L1 结果保留语义来源。不能把所有 FTS 命中都标成连续 Direct 命中。
- 普通用户主要看到命中方式、来源和“关键词检索降级 / 索引恢复中”等必要状态。FTS/扫描/LIKE、索引版本与诊断原因放在技术详情，不挤占正常问答流程。
- 引用原文只高亮实际存在的文本范围；多个不连续词分别高亮，不合成原文不存在的整句。标题/tag 召回必须明确实际证据来自何处。
- 独立展示空结果、范围读取失败、索引不可用、恢复中、部分覆盖、扫描预算到达与取消。范围不完整时不能提示“知识库没有相关内容”。
- 保留分页、来源预览、历史快照和失效标记；关键词与语义结果按稳定证据身份合并，保留全部实际命中原因。
- 长查询、查询编辑、翻页、后台与切页均有独立取消/版本隔离；沿用无障碍及最小 44vp 操作区域要求。

## 4. 业务与 Agent 事项

### 4.1 统一服务与查询语义

拟定知识库应用端口 `KnowledgeLexicalSearchPort`，提供 `capabilities()` 和 `search(request, context, cancel)`；名称为实施设计占位，不是已有系统 API。页面服务和 spec 13 的 Agent adapter 都注入该端口，不各自实现 FTS 或扫描。

请求包含原始 `query`、可选的 `keywords`、查询意图 `keywords / literal`、分页/结果上限；用户身份、可读语料范围、是否包含归档、scope 修订和截止时间由宿主注入。L2 的 `mode=direct` 表示使用本机 L0，不强制选择 literal 模式。

- 页面默认 keywords 模式；引号包围的短语或明确的精确查询选择 literal 模式。普通关键词匹配不承诺理解中文问句的全部逻辑。
- 页面可用固定本机规则处理空白、标点、引号和查询词，无需模型；实际中文词项由已验证的 FTS tokenizer 决定。保留原始查询与实际关键词，规范化策略必须版本化。
- L2 提供的 keywords 沿用 spec 13 的 1–8 个词、每词最多 40 字符；页面输入边界沿用现有查询上限。任何模型输出都需运行时校验。
- 默认关键词采用 OR 召回，再依据命中词覆盖与原文证据排序；OR 仅表示候选相关，不证明用户全部条件已满足。精确短语按字面子串核验，不把 FTS phrase 等同于连续字符匹配。
- 用户与模型均不能传入 SQL、FTS 表达式或 tokenizer 名称；将词项转义并绑定参数，禁止原样解释 `OR/NOT/NEAR/*` 等为用户控制的查询语法。

### 4.2 主召回、校验与补充

```text
请求与 scope 校验
  → 检查当前索引资格和覆盖
  → FTS5 分词关键词召回候选（可用时）
  → 从普通库读回候选原文、generation、有效标注及来源
  → 校验证据身份与原文完整性
  → 保留 FTS 词项命中；另做字面匹配与 UTF-16 高亮
  → 按策略执行有界字面补充/降级
  → 合并去重、稳定排序与分页
```

1. FTS5 是主召回器，正文/标注及普通库可见性是内容权威；索引文本不能替代当前原文，失效、串世代或 hash 不符的候选必须拒绝。
2. **字面校验不是所有 FTS 结果的准入门槛。** FTS 候选经有效原文核验后，可以作为 Keyword 命中返回；否则若要求整句字面匹配，会抵消分词召回的价值。
3. 对 query/keywords 在原文进行现有字面匹配，标识 Literal 命中与实际位置。折叠大小写、Unicode 边界和 UTF-16 范围规则需沿用/版本化，不能把规范化后的位置直接套回原文。
4. FTS 可用且覆盖完整时，普通关键词请求不默认全库扫描。字面补充仅用于 literal 模式、已验证不受 tokenizer 支持的短词/子串，或 FTS 零候选时的一次有界字面探查；记录触发原因及实际扫描范围。
5. FTS 运行错误、能力不可用、索引缺失/恢复中或覆盖不完整时，使用当前字面扫描作为降级；可选 LIKE 只有在原文/转义/归档/世代语义一致且通过测试时采用，不把现有所有 `Like` 通道标签当作实际执行 LIKE 的证据。
6. 空结果本身不是错误，不能因无命中反复重建索引或重复扫描。扫描超时、超量或只覆盖部分语料必须返回 partial/budget 状态；不能伪报全库 empty。FTS 不完整时即便已有候选，也须补检未覆盖范围或明确部分覆盖。
7. 合并以文档世代+chunk/occurrence+有效标注的稳定证据身份去重；图片沿用图 hash、有效标注与多父来源合卡规则。同一证据保留多路原因，topK 在当前有效候选合并后截取。
8. 排序优先考虑已核连续短语/字面命中、关键词覆盖和正文信息量，再采用实际 FTS 排序及稳定 ID 打破平局。FTS 分数与向量距离不能直接相加；融合采用显式排名策略并保留原通道。

### 4.3 内容索引与生命周期

统一索引只消费当前已发布正文/OCR/公式和图片有效描述；正文、描述、标题、tags 的字段/来源角色必须区分。只有标题/tag 命中的候选，如没有可支持问题的正文/描述证据，不可单独作为 L2 断言来源。不能把 tags 拼成虚构正文。

索引行绑定 owner、document/chunk/occurrence、generation/effective annotation、内容 hash、索引策略版本；具体表名、字段与事务边界在实施前核对 SDK/平台行为并评审，不在本 spec 编造可执行 DDL。禁止把旧 `text_fts` 当全量统一索引，或暗中把统一内容再导入旧文本库。

索引是本机可重建派生数据，状态至少区分 `NotBuilt / Building / Ready / Stale / Unavailable` 并独立记录覆盖：

- 发布、更新、标注变更、归档/恢复、删除均产生可恢复的索引维护记录；新世代未完成时不把旧索引当作当前索引。
- 采用“普通库权威提交 → 索引写入/读回 → 索引资格发布”的可恢复流程，不假设 FTS 虚表与普通表在目标设备可共享事务。以实际官方依据及平台试验确定事务实现。
- 每次查询过滤当前世代/可见性，避免维护延迟暴露已删、归档或旧标注内容。多父图片仍可引用其他有效父来源。
- 启动时核对索引策略、待完成记录与覆盖，恢复中断的本机工作；重建只读取已保存规范化内容，不触发解析、视觉或 embedding，不清除原件、向量及历史。
- schema 演进仅做获准的派生索引升级；先保数据迁移、回滚兼容与故障注入评审。旧表、旧 wire/历史不随本任务清理。

### 4.4 结果契约与 L2 对接

统一结果包含 `status`、`scopeRevision`、覆盖与分页信息，并逐项区分：

| 字段 | 语义 |
|---|---|
| `engine` | `fts5 / literal-scan / sql-like`；多路合并时每条 reason 保留实际 engine |
| `matchKind` | `Keyword / Literal`；同一证据可有两种 reason，不伪造连续范围 |
| `evidenceType` | Body / Ocr / Formula / AiDescription 等内容性质，与检索引擎分开 |
| `matchedTerms / ranges` | 实际命中词和经核验的原文位置；Keyword 无字面范围时允许 ranges 为空 |
| `fallbackReason` | 能力不支持、查询错误、索引恢复/不完整、短词/子串补充、零候选补充等稳定原因 |
| `coverage / truncated / hasMore` | 当前可读、索引覆盖、实际扫描/未覆盖范围及截断；不把“返回 k 条”解释为“全库只有 k 条” |

内部结果保留稳定 ID、版本/hash 与原文定位，供工具结果持久化和引用重验；发送给 LLM 时由 spec 13 裁剪，保留可理解的匹配/证据类型及降级状态，不外发内部 ID、路径或完整文档。

`directReady` 在 L2 中表示 **L0 至少存在可执行的本机关键词或字面检索路径**，不是“FTS 一定 Ready”，也不依赖 L1 向量。Query/Embedding 与 L0 索引状态分别管理；L0 故障不改变向量库或偷偷发网络请求。空结果、部分覆盖与 unavailable 均不得伪造为知识库问答成功。

### 4.5 资源、取消与性能

保留当前字面实现作为降级，但须有扫描块数/字节、候选数、内存和时间预算；不得以固定前 N 块扫描后返回 empty。达到预算时返回明确截断状态和继续方式，分页不能重复扫描已消费范围或混合不同 scope。

FTS 正常路径应通过普通库修订、索引资格和候选读回建立范围/完整性保证，避免先全量加载并 hash 所有 chunks 再执行 MATCH；同时保留发布时完整性校验和查询候选读回校验，不能以性能为由放弃数据身份验证。

取消令牌贯穿 MATCH、原文读取、扫描与分页；编辑 query/切换范围/页面离开使旧请求失效。后台暂停索引维护，持久化断点；进程重启恢复本机索引，不恢复旧模型任务。

预算具体数值及性能目标需在实施前用 1k/10k/30k 级 chunk 夹具测定，分别记录原文大小、中文占比、耗时 p50/p95、内存与索引磁盘。数据量超过支持预算必须明确拒绝/部分覆盖，不宣称 30k 为已支持规模。验收至少证明正常 FTS 查询不全量加载正文且优于同语料全量扫描；达不到时不能只凭 MATCH 被执行宣布优化完成。

## 5. 平台能力与权限

- 基于现有 HarmonyOS API 26 ArkData 和本机持久化能力，无新增权限、网络服务、分词依赖或云费用。实施前用 `devecocli docs search/read` 核对 FTS5、tokenizer、能力检测、事务及迁移条件并留官方文档依据；不照搬桌面 SQLite 特性为 HarmonyOS 已支持。
- 能力探测必须包含真实建表/写入/中文、英文、短词与标点查询、读回及维护验证；不能只看 API 探测布尔值。不得默认 `customtokenizer` 或 trigram 在目标设备可用，分词不可用时保留字面降级。
- 本机索引与正文属于个人数据，沿用现有安全级别、访问范围和本机数据归属；不打印用户正文/Key/路径，不把派生索引同步到外部。
- 维护与重建只作用于本任务拥有的派生索引，不清库、卸载或删除既有资料。切换回旧版本如不识别新索引，应保留数据并明确降级，不把生产文档重置为未入库。

## 6. 验收方式

### 6.1 四类路径与集成

| 路径 | 用例 | 预期 |
|---|---|---|
| 正常 | 中文词项、英文、数字、混合标点在统一正文/OCR/图片描述召回 | 使用实际 FTS 主路径，回到当前有效原文，证据类型正确 |
| 正常 | FTS 词项命中但无连续完整短语 | 返回 Keyword，不能被字面校验错误清空，不伪造高亮 |
| 正常 | 精确短语、短词、子串、Unicode/代理对 | 按策略字面校验/补充，返回正确 UTF-16 原文范围 |
| 正常 | 页面与 L2 对同 query/keywords/scope 查询 | 候选资格与匹配规则一致；topK/外发限额差异有记录 |
| 正常 | 无 Key/断网/无向量；关闭重开并重启进程 | L0 可离线使用旧资料，不触发任何模型、解析或 embedding |
| 异常 | tokenizer 不支持、MATCH 错误、索引缺失/恢复中 | 明确原因，字面降级保留有效来源；不把错误称 empty |
| 异常 | FTS 零候选、索引仅部分覆盖、扫描超时/超限 | 最多按策略一次有界补检；完整无命中与部分/预算状态分开 |
| 异常 | 导入、更新、标注修改、归档/恢复、删除与查询并发 | 无旧世代或越权来源；候选读回失败不显示成功 |
| 异常 | 普通库提交后崩溃、索引写入中断、资格发布失败 | 重启可恢复；原件/正文/向量/历史保留，无新云请求 |
| 异常 | 多父图片、同图不同标注、跨路/分页重复 | 稳定去重，保留实际原因及有效父来源 |
| 权限拒绝 | 无读库授权、模型传路径/SQL/归档越界参数 | 宿主拒绝，不执行越界检索，不因降级放宽 scope |
| 权限拒绝 | L2 不允许片段外发 | L0 仍可本机显示；不把原文发给模型 |
| 模型失败 | 回答模型或 Embedding 不可用 | L0 正常运行且保留原文；L2 失败不得吞掉本机结果 |
| 模型失败 | L2 生成非法/超长关键词或检索指令注入 | 参数校验拒绝；关键词作为数据，不执行 FTS/SQL 指令 |

### 6.2 质量与性能

固定夹具至少覆盖：中文单字/双字/长词、专名、英文大小写、日期/编号、标点、精确短语/子串、长问句、OCR 和 AI 描述、tag-only、无答案及删除/归档。为 FTS Keyword 和 Literal 分别标 gold，不能拿两种不同命中语义强求相同结果。

- Literal 路径对声明支持范围的基准结果与现有字面匹配一致，来源/范围身份与高亮正确率 100%；FTS 候选仍须独立通过完整性校验。
- 逐题比较新旧召回，说明新增 FTS 词项命中和字面补充带来的变化；有效字面 gold 不得因改用 FTS 丢失且不报告，tag-only 不得成为断言证据。
- 性能记录需包含候选读回量、全库扫描量、索引维护成本及冷启动恢复；大规模测试与日常查询分开，不以小样本通过冒充容量验收。
