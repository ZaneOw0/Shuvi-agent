## 1. 目标与范围

### 1.1 目标

让用户把个人资料（笔记、Office/PDF 文档、图片）放进应用，用自然语言提问或查找图片，得到**可追溯到原文或原图位置**的结果：

- 支持目标为 `docx/xlsx/pdf/pptx/jpg/png/txt/md`，逐格式、逐阶段验收（见 5.7.1、6.2），不是当前实现声明；
- `.txt/.md` 本地处理与关键词检索不要求云解析授权；复杂文档首次解析和图片视觉增强需联网、配置服务并独立授权；断网或拒绝外发仍可保存原件，显示待处理，不显示就绪；
- **已取得并校验规范化内容后**，可离线重建关键词索引、检索并展示引用；端侧 OCR 以目标设备能力验证为前提，语义层以模型准备为前提。不承诺八格式首次处理全离线；
- 独立图片与文档内嵌图支持 OCR、视觉描述、关键词 tag 和分类，可通过其文本代理检索返回图片，不依赖图像向量；
- 需要成段自然语言回答时，用云端大模型生成，回答必须能回溯到命中的知识片段。

**本闭环存在五种彼此独立的外发行为，不能合并成一句「只上传命中片段」**：

| # | 行为 | 发送内容 | 接收方 | 触发时机 | 默认 |
|---|---|---|---|---|---|
| ① | 在线生成（L1） | system 提示词、**本次命中文本与来源类型**、用户问题；默认不发原图 | 用户配置的回答模型服务 | 用户提问且开启在线生成 | 关 |
| ② | 语义向量化 | **参与索引的块文本**、提问时的查询文本 | 所选嵌入服务；官方路径 A 的推理位置仍待核验（见 5.4.1） | 建索引、重建向量、生成查询向量 | 关，默认关键词层 |
| ③ | 跨设备同步 | **原件、版本化规范化内容、提取图像、OCR/描述/自动标签快照及用户修正元数据**；不含索引、任务或凭据 | **用户本人的华为云空间** | 用户开启同步后离散版本发布/元数据变更（见 5.16） | 关，需账号及系统同步开关 |
| ④ | 托管文档解析 | **完整原文件**与必要处理参数，包含文件中的图像，不只是正文 | 优先评测 MinerU 精准 API；实际接收/转处理方须取证 | 用户同意解析该文件，或明确发起重新解析 | 关，需独立同意与 Token |
| ⑤ | 托管图像理解 | 原图或文档提取图、必要图注/上下文，及确需托管补充的 OCR 输入 | 用户配置并获批准的视觉服务，选型待定 | 用户开启图片理解并同意处理相应图片 | 关，需独立同意与视觉 Key |

五者**各自独立开关、互不授权**，即使接收方相同也不得合并同意。设置与处理确认需说明「上传什么、给谁、什么时候、保存/删除规则、费用、不开启失去什么」。关闭④/⑤不影响已有规范化内容的离线检索；允许④不等于允许把全部内嵌图再发给⑤；同步获得的图像也不得未经本机⑤授权自动外发。关闭某项只停止该项后续外发，不表示已撤回先前上传的数据，远端删除须如实报告。

### 1.2 平台范围（硬约束）

**运行平台为手机与平板。本闭环不得依赖任何「仅 PC/2in1」的能力。**

已据此排除的官方能力（均为 PC/2in1 专属，**本项目一律不用**）：

| 被排除的能力 | 官方设备口径 | 影响 |
|---|---|---|
| `rag`（RAG 会话 + `StreamType.REFERENCE` 引用输出） | 仅 PC/2in1 | 检索编排与引用构造全部自建 |
| `localChatModel`（端侧问答模型） | 仅 PC/2in1，且仅企业开发者可申请 | 端侧生成不承诺 |
| `knowledgeProcessor`（知识加工，schema 驱动自动建库） | 仅 PC/2in1 | 应用自建编排与规范化，复杂解析消费托管 API，分块与索引在本机 |
| `intelligence.splitText`（文本分块） | 仅 PC/2in1 | 分块自建 |
| `intelligence.getImageEmbeddingModel`（图像向量化） | 仅 PC/2in1 | 不做图像向量检索；允许 OCR/描述/tag 文本代理查图 |
| `enableSemanticIndex` + `knowledge_schema.json` 自动建库链路 | 依赖知识加工，仅 PC/2in1 | 不使用该字段 |
| CANN LLM Engine | 硬件要求 Kirin X90 平台 | 不使用 |

补充：既有方案选用的**语音识别**（Core Speech Kit `speechRecognizer`）与**通用文字识别**（Core Vision Kit）面向手机/平板，实际能力需设备验证；端云同步边界不变。本稿通过托管视觉模型形成图片的文本代理，不引入 PC/2in1 图像嵌入，也不承诺本机运行 MinerU 或 Python 模型。

### 1.3 技术方向与选型状态

| 环节 | 选型 |
|---|---|
| 数据底座 | **ArkData**：`relationalStore` 关系型数据库 + 向量列（`FLOATVECTOR`）+ FTS5 倒排 |
| 检索 | **智慧化数据检索**：`retrieval.getRetriever` + `Retriever.retrieveRdb`（向量 + 倒排双路召回 + 重排） |
| 离线引用式回答 | 由本应用基于 `retrieval.ItemInfo` 自建（官方在手机/平板不提供） |
| 在线生成 | 用户自填 Key → 云端大模型（OpenAI 兼容 HTTP） |
| **多格式解析（本期目标）** | txt/md 在端侧处理；复杂格式优先评测 **MinerU 精准托管 API**，不采用轻量 API；原生位置与产物 schema 未取证，不锁定其覆盖全部格式（见 5.7） |
| **多模态输入与图片知识源** | 提问语音/OCR 转文本；独立与内嵌图另做 OCR、视觉描述、tag、分类并关联原图；视觉托管模型待评测，不做图像向量（见 5.15） |
| **跨设备同步（本期目标）** | **端云同步**；共享原件、规范化快照/图像与用户标注，索引、向量、本机任务与状态不同步（见 5.16）；新增布局须团队评审 |
| **内容管理（本期）** | 用户可重命名、重新索引、**归档**、**删除单篇/批量**、清空知识库；删除时级联清理块、FTS5 行、向量列、沙箱副本与资产文件（见 5.17） |

### 1.4 非目标

- 不做端侧大模型生成；
- **不做图像向量与跨模态向量检索**、以图搜图/图搜文；**文字通过 OCR、视觉描述/tag 查找图片属于本期**，不得与图像向量方案混称（见 5.15.3、5.15.4）；
- 不做知识库**端端（设备直连）同步**：只采用端云同步，理由见 5.16 与 D11；
- 不引入自有后端，不部署解析/视觉服务或局域网自建服务，不购买服务器；仅接托管 API，客户端上传与轮询，不要求回调服务；
- 不做多模态**输出**（语音播报、图片生成属于其他闭环）；
- 不做联网搜索（属于「联网搜索」闭环，本 spec 不引入 web 内容作为知识源）；
- 不做 Office 编辑器、宏/脚本执行、公式重算、精确求和/筛选/跨表统计；表格结构与可溯源问答属于本期，不以模型生成代替确定性计算；
- 不承诺像素级版式还原或所有特殊对象无损解析；不开放 HTML、旧 `.doc/.xls/.ppt`、宏文件等八格式之外的输入。

> **与既有闭环的边界**：长语音的录制、上传与摘要仍属 P1「长语音转写」，本闭环消费文本；图片取字提问与图片入库是两种流程，后者新增的保存、理解、标注和引用由本 spec 定义。相机拍摄/拍照权限不在本轮扩展中；图库选择入口消费系统选择器，不引入相机能力。

## 2. 用户流程

### 2.1 主流程

1. 用户进入「知识库」页，看到各格式能力、文档处理/索引/同步状态，而非仅一个“支持格式”标记。
2. 用户点击「导入资料」，选取八格式中的一个或多个文件；jpg/png 可由图库入口选择。系统选择器返回临时授权，取消不产生文档或外发。
3. 应用校验类型与预算，**保留原字节沙箱副本**、哈希和文档版本。txt/md 本地解析；复杂文档先显示完整文件外发范围，只有用户独立同意④才上传到已通过门禁的托管服务，否则保留待处理。
4. 显示上传、排队/转换/解析、结果下载、结构与原生定位校验的阶段进度；取得规范化内容后，独立图与内嵌图按⑤授权执行视觉增强；用户可检查、修改或删除描述/tag/分类。
5. 按结构切块并建立本机索引，显示「就绪」及检索通道；必需结构/锚点缺失不得标完整支持，已验证文字可查但图片增强失败时标「部分可用」。各阶段可停止，远端任务是否停止与本地暂停分开说明。
6. 用户在「知识库」入口内切换到**检索与问答**视图输入问题。输入方式包括键盘、**语音**（`speechRecognizer` 识别为文本）、**图片取字**（Core Vision Kit OCR 后作为问题或附加内容）；三种方式产出同一类文本，进入同一条检索链路。
7. 应用先做本机检索，返回文本/表格证据或图片及其文本代理来源；文字查图须显示缩略图、父文档与定位，不只返回 tag。
8. 分支：
   - **L0（默认，仅检索）**：展示命中片段 + 来源 + 相关度；本机关键词可离线，云查询向量仅按②授权使用并标联网路径。
   - **L1（已配置 Key 且联网且用户已开启）**：把命中片段作为上下文交给云端模型，流式展示生成回答，并在回答下方列出引用来源。
   - **L1 不可用**：明确提示「未配置模型 Key / 当前无网络，已展示检索结果」，不静默降级、不假装生成成功。
9. 用户可点击引用核对正文、表格、原图或文档提取图及原生位置；AI 描述和 OCR 分别标注，tag 仅用于召回/过滤，不独立作为事实依据。
10. 会话与回答落库，可回溯。
11. 用户可**重命名、修改图片标注、从已有快照重新索引、另行授权重新解析/理解、归档、删除单篇/批量、清空知识库**。重建索引不自动重新上传原件；重跑模型不覆盖用户修正（见 5.17）。
12. 删除某文档后，历史回答中指向该文档的引用**保留文本快照并标注「原文档已删除，引用已失效」**（见 4.4）。
13. 开启同步后，同账号其他设备取得原件、规范化快照与图像、共享标注，下载并校验完成后可在不开④/⑤且断网时重建关键词索引；未下载完显示待下载，不把列表同步当内容可用（见 5.16）。

### 2.2 异常流程

- **导入失败**：损坏、加密、类型伪装或超限逐文件报告；不把二进制当 UTF-8 硬读。必需表格/原生位置缺失标未完整支持，部分页或图片失败明确列出，不静默丢弃。
- **处理不可用**：无网络、无 Token 或拒绝④/⑤ → 保留原件和已验证产物，显示待联网/待授权；无字照片 OCR 为空不等于图片无效，仍可在⑤同意后做视觉理解。
- **服务/下载失败**：鉴权、配额、429、排队、签名地址过期、ZIP 或 schema 不合法分别标阶段；查询超时不等于云解析失败，保留任务 ID 可继续查询，不盲目重复提交。
- **索引中断**：应用退出或用户取消后，已完成文档保留，下次进入可「继续索引」。
- **检索结果为空**：区分两种状态，**不得混为一谈**（本稿明确，原稿此处与第 6 节冲突）：

  | 状态 | 判定 | 是否调用模型 | 界面 |
  |---|---|---|---|
  | **A 无召回** | 两路召回结果均为 0 | **不调用模型**（省流量与费用） | 「知识库中没有相关内容」+ 建议换问法/确认资料已索引 |
  | **B 有召回但证据不足** | 召回了片段，但相关度全部低于档位阈值（`similarityLevel` 均为"语义差异大"）或片段明显不覆盖问题 | 可按用户设置调用，但提示词必须要求"资料不足以回答时明确说明" | 「检索到相关片段，但证据不足」并**同时展示片段**；若模型给出结论，标注「依据不足，仅供参考」 |

- **生成失败**：超时 / 空响应 / 鉴权失败 → 降级回 L0 并显示具体原因。
- **删除期间**：先停该文档本地任务，阻止迟到结果重新创建文档；逻辑删除提交失败保留文档与原因，已提交后清文件失败单列待清理，不回滚文档删除。不能把本地删除称为托管服务已删除（见 5.17）。
- **删除后对账**：一端删除文档后，另一端可能长时间不知道；再次启动时必须通过对账回收孤儿索引（见 4.2）。
- **同步异常**：未登录华为账号 / 未开启「设置-云空间」同步开关 / 云端限流或同步失败时，**本地功能必须照常可用**，界面如实标注「本机数据，尚未同步」，不得显示同步成功假象。
- **提问识别失败**：语音或图片取字失败时退回键盘输入，不用空文本检索；该行为不适用于判定“图片知识源无内容”。

## 3. 页面事项

### 3.1 页面与路由

**落点以 `dev/ux` 已建立的信息结构为准**：现有实现是单个 `@Entry pages/Index` + 自定义底栏的「助手 / 工作台 / 知识库 / 我的」四个一级入口（`entry/src/main/ets/pages/Index.ets`、`entry/src/main/ets/components/FeaturePages.ets`），`main_pages.json` 仅登记 `pages/Index`，未使用 `Tabs` / `router` / `Navigation`。因此本闭环**不新增路由页**，而是在「知识库」一级入口内实现二级视图，返回键并入 `Index.onBackPress`（当前只处理一级入口与弹层，需扩展二级视图返回）。

| 视图 | 落点 | 说明 |
|---|---|---|
| 知识库首页 | 「知识库」入口内的二级视图根 | 格式能力、处理/索引/同步状态、文档列表、八格式导入、归档/删除、检索入口 |
| 检索与问答 | 知识库首页内切换 | 提问（键盘/语音/图片）、回答、引用列表、片段详情；L0/L1、输入方式、同步状态均显式标注 |
| 设置 | 并入「我的」入口 | 分用途服务/Key/Token、五类独立同意、费用与留存说明；云空间同步开关以系统设置为准，不代用户打开 |
| 片段/资产详情 | 弹层 / 半模态，不单独占路由 | 原件版本、结构内容、原生位置、图像与 OCR/AI 来源、引用失效/旧版本说明 |
| 图片标注 | 知识库内详情视图 | 自动描述/tag/分类与用户修正分开，可修改/删除，不覆盖用户修正 |

- 知识库列表与问答区在**平板宽屏**下可左右分栏，手机为单栏（当前 `Index.ets` 使用 `constraintSize({ maxWidth: 640 })` 单栏布局，分栏属本期实现项）；
- 新增视图同样必须持续显示「演示模式」标注（[specs/01](01-创建日程并提醒.md) 第 1.2 节的既定要求），并与真实数据状态明确区分。

> 与原先"新增 `pages/KnowledgePage`、`pages/KnowledgeChatPage`、`pages/KnowledgeSettingsPage` 三个路由"的写法相比，本稿改为二级视图：避免与已合并的一级入口结构产生两套导航。该调整属本期范围，若团队要求改回多路由，需同时修改 `main_pages.json`、`Index` 底栏与 01 spec。

### 3.2 交互状态

| 状态 | 知识库页 | 问答页 |
|---|---|---|
| 加载 | 上传/排队/转换/解析/下载/校验/视觉增强/索引各阶段进度 + 文件数 | 「检索中…」（本地检索通常极短，避免闪烁） |
| 空态 | 无文档：引导导入；有文档未索引：引导建索引 | 无会话：给示例问题 |
| 失败 | 逐文档失败原因 + 单条重试 | 检索失败 / 生成失败分别呈现；生成失败须降级回 L0 |
| 取消 | 本地暂停/取消，保留检查点；云端任务可能继续，不能伪称取消成功 | 停止生成，保留已收文本并标注「未完成」 |
| 可恢复 | 按检查点继续查询/下载/校验/索引，不自动重新上传 | 生成中断可重试同一问题 |
| 归档 / 删除 | 已归档、二次确认、删除失败或已删除/文件待清理分别显示 | 删除不可跳转原件；保留历史快照不等于完全擦除历史内容 |
| 同步 | 本机数据未同步（未登录/未开云空间开关）/ 已同步 / 同步中 / 同步失败 | 列表项与回答卡片标注数据来源（本机 / 已同步）；同步失败不影响本地使用 |
| 多模态输入 | 录音中、识别中、识别失败、未识别到文字 | 语音与图片产出文本后可编辑再发送；失败退回键盘输入 |
| 待处理/部分可用 | 待授权、待联网、待资产下载；缺页/缺结构/缺锚点/图片增强未完成分别说明 | 仅查询已发布、已验证内容，标明缺失范围 |
| 图片标注 | AI 自动结果/用户修正/未分类/识别不确定 | OCR、AI 描述和 tag 来源可见，可打开来源图核对 |

### 3.3 状态可见性要求（硬性）

页面必须**如实**区分并标注，不得合并表述（依据 [00-项目总览](../docs/00-项目总览.md) 第 4 节）：

- 「原件已保存」≠「上传成功」≠「云端 done」≠「规范化校验通过」≠「索引就绪」；图片增强完成与正文就绪也分开；
- 「检索到片段」≠「模型已生成回答」；
- 当前是 L0（仅检索结果）还是 L1（模型生成），回答卡片显式标注；检索是否联网按实际路径另标，L0 不自动等于离线；
- 当前检索是「向量 + 关键词」还是「仅关键词」；
- 「已同步元数据」≠「原件/规范化资产已下载校验」≠「本机索引已重建」；
- 引用失效（原文档已删除）必须显式标注，**不得继续表现为可跳转的原文**；
- 多模态输入必须标注该问题文本来自键盘 / 语音 / 图片取字，避免把识别结果当成用户原话。
- 「服务接收该格式」≠「App 完整支持」；原生定位未达标不能改用渲染页号冒充；AI 描述/tag 不是原图文字，也不是已核实事实。

### 3.4 适配要求

手机与平板共用同一套页面，需处理：

- 平板宽屏下知识库列表与问答区可左右分栏，手机为单栏；
- 文本可缩放、可访问性（[00-项目总览](../docs/00-项目总览.md) 第 5 节）；
- 平板横竖屏切换不丢失索引进度与输入内容。

| `failReason` | 失败原因（可展示、可定位） |

|---|---|

### 4.2 处理与索引状态机

```
原件已保存 -> 待处理
  txt/md -> 本地解析
  复杂文档 -> 待授权/待联网 -> 上传 -> 排队/转换/解析
                                      -> 下载 -> 结构/原生定位校验
独立图/提取图 -> OCR -> 待视觉授权/待联网 -> 理解 -> 结果校验
规范化快照已验证 -> 结构分块 -> 本机索引 -> 就绪 / 部分可用 / 失败
任一未完成本地阶段 -> 暂停/取消 -> 按检查点恢复（不意味着云任务停止）
任一文档 -> 本机归档 / 删除（文件清理结果另记）
同步完整快照 -> 本机下载/校验 -> 本地重建；远端删除 -> 对账清理
```

约束：

- 「索引中」必须可中断，中断后已完成部分保留；
- 处理阶段、视觉增强、索引、同步、归档分维度保存；单文件与批次的“部分成功”分别报告。必需结构缺失不能标完整就绪，图片增强未完成可保留已验证文本索引并显式标 `PARTIAL`；
- `documentVersion/normalizedVersion/schemaVersion/chunkStrategyVersion/embedSpaceId` 随索引落库；解析/OCR/视觉策略与模型版本组成处理指纹，重处理不覆盖用户修正；
- 嵌入模型或分块策略变更时，旧索引标记为需重建，**不静默混用**（见 5.4.3）；
- 数据库删除优先原子级联；若已验证的特定环境要求 FTS 分开提交，先屏蔽检索并持久化待清理任务，恢复时完成，不能宣称跨提交原子性；文件在逻辑删除提交后清理（见 5.17）。§5.6.3 模拟器现象不泛化为所有设备事实；
- **归档是可恢复的软状态**，归档不删除块与向量（避免恢复时重建），仅在检索时默认排除，用户可显式选择是否包含归档资料；
- 本地索引是**派生数据，不进同步**：收到同步下来的文档变更后，本机要么按需重建、要么回收对应索引；
- **启动时必须执行对账**：以现存文档及活动已发布索引版本为准回收孤儿/过期块与资产缓存；`PARTIAL` 的已验证活动块可检索，重建中的旧已发布索引不因处理中状态被误删；
- 每阶段校验后原子发布产物，新索引通过校验才切换读取，重建期间旧已验证索引仍可查；删除后的迟到结果须按文档存在性/版本校验拒绝发布。

### 4.4 回答契约（L0/L1 分级）

| 级别 | 触发条件 | 内容 | 联网 |
|---|---|---|---|
| **L0** | 已有已验证、已索引内容时可用；语义不可用退关键词 | 命中文本/表格或图像代理 + 来源/版本/原生位置 + 相关度及证据类型 | 本机关键词检索不联网；云侧查询向量仅在②授权时使用，不能标离线 |
| **L1** | 已配置模型 Key **且** 联网 **且** 用户已开启在线生成 | L0 内容 + 生成文本 + 引用列表 | 是 |
| **L1_FAILED** | 尝试 L1 但失败 | 降级为 L0 + 明确失败原因 | 是（尝试过） |

**L0 是本闭环的验收基线**：即使 L1 全部不可用，本功能也必须可用且可验收。

引用保留官方 `retrieval.ItemInfo` 的主键/分数/通道信息，但由应用扩展定位、资产、版本和证据类型；不再承诺与 `rag.Answer.data` 完全同型。FTS/LIKE 降级不得伪造官方 `similarityLevel`，按实际通道展示。

**引用失效策略（已定）**：文档被删除后，历史回答中的引用**保留文本快照**，并在引用卡片上标注「原文档已删除，引用已失效」：

- 不删除历史回答、不隐藏引用、不保留"可跳转到原文"的假象；点击后展示快照文本与失效说明；
- 快照必须取自落库时的块文本，**不重新读取已删除的沙箱副本**；
- 归档（`ARCHIVED`）不影响引用有效性，仅在检索时默认排除归档资料。
- 引用快照保存落库时文本、证据类型、原件/规范化版本与定位；原件更新后标“引用旧版本”，旧资产若已不可读取仅展示快照，不跳转到新版本冒充旧证据。
- 图片/表格引用能核对来源图/单元格；OCR 与 AI 描述分别标注可能有误。tag/分类只用于召回与过滤，不单独作为支持断言的证据。图像删除后不为历史回答暗中保留完整原图，保留文本/定位快照并标失效。
- 保留历史快照不等于完全擦除历史内容，删除确认中必须说明；L1 的编号校验仍不证明抽取或视觉内容本身正确。

> 依据：本项目已确定的「保留证据」原则——[AGENTS.md](../AGENTS.md) 第 2.4 条（不伪造成功）与 `docs/00` 第 4 节（区分不同成功阶段、不把历史当现状）。

### 4.5 Agent 主控策略

- **检索是确定性系统动作**，不是模型决策：每次提问**先**由应用执行 `search()`，再决定是否生成。不采用「让模型决定要不要查知识库」的工具调用形态（理由：模型无法知道知识库里有什么，且会让离线路径依赖模型）。
- **是否启用 L1 由应用判断**（Key 是否配置、网络是否可用、用户开关），不由模型判断。
- **模型输出只是候选内容**，必须经运行时校验后才能展示（见 5.8），不得直接当作事实。
- 本闭环**不新增子智能体**；后续若引入，须另行定义委派与预算。

## 5. 平台能力与权限

### 5.1 数据底座：ArkData

统一用 `relationalStore` 作为唯一持久化底座（关系数据 + 向量列 + FTS 三合一），**不引入第二套数据库**。

`StoreConfig` 取值（已核对起始版本）：

| 字段 | 起始 | 本项目取值与理由 |
|---|---|---|
| `name` | API 9 | 知识库主库名；**同一进程禁止同名库** |
| `securityLevel` | API 9 | `S3`（个人笔记属个人数据）。**只支持由低向高、不支持降级**，首版取值即定死 |
| `vector` | API 18 | 能力与实际建表/写入验证通过才启用；失败按 5.6.2、5.6.3 降级；旧“无副作用”断言已撤回 |
| `tokenizer` | API 17 | `CUSTOM_TOKENIZER`（API 18 起可用；官方称其分词准确率与常驻内存均优于 ICU） |
| `encrypt` | API 9 | 首版 `false`；**建库后不可直接改**，如需加密须走 `rekey` |

关键 API：

```
relationalStore.getRdbStore(context, config): Promise<RdbStore>
relationalStore.isVectorSupported(): boolean             // API 18+，能力探测
relationalStore.isTokenizerSupported(tokenizer): boolean  // API 18+，能力探测
store.execute / executeSql / querySql / query
store.insert / batchInsert / update / delete
store.createTransaction(options?): Promise<Transaction>   // API 14+，官方推荐；批量写必须用事务
resultSet.getValue(columnIndex): ValueType                // 取向量列的唯一途径
```

硬约束（实现前必读，均来自官方原文）：

| 约束 | 数值 / 说明 |
|---|---|
| 单条数据大小 | **必须严格小于 2 MB**（`querySql` 共享内存限制 2 MB）。**块文本 + 向量一起算**，「超出该大小，插入成功，读取失败」 |
| 并发 | **同一时间只能支持一个写操作**；常驻 4 读连接 + 1 写连接，**写连接不扩充** |
| 事务对象 | 一个 store **最多同时存在 4 个事务对象**，超出返回 `14800015` |
| WAL 文件上限 | **512 MB**，超限 `14800047`；诱因是「结果集未关闭时持续增删改」→ **`ResultSet` 用完必须 `close()`** |
| SQL 限制 | `executeSql`/`execute` 关系操作符**不超过 1000 个**，**不支持分号分隔多条语句**；`querySql` **聚合函数不支持嵌套** |
| 不支持的特性 | 外键 `FOREIGN` 否、`CHECK` 否；向量库另不支持 `DISTINCT` |
| bigint | **不能比较大小**，不适用 `between`/`orderByAsc`/`orderByDesc` |
| 备份恢复 | 普通库有 `backup()`/`restore()`；但 **`retrieval` 明确「暂不支持数据库的备份、恢复」**（`1021200001`）→ 知识库损坏只能重建，**必须自建导出/重建机制** |

### 5.2 检索：智慧化数据检索

- 入口：`retrieval.getRetriever(config)` → `retriever.retrieveRdb(query, condition)`
- 系统能力：`SystemCapability.DataAugmentation.Retrieval`；仅 Stage 模型；起始 `6.0.0(20)`
- **设备支持：Phone、PC/2in1、Tablet**（官方口径，满足本项目的手机 + 平板约束）
- 通道：`ChannelType.VECTOR_DATABASE` + `ChannelType.INVERTED_INDEX_DATABASE`，可多路并行
- 重排：`RerankType.RRF`（本项目采用，理由见第 8 节 D7）
- 返回 `ItemInfo { primaryKey, columns, score, recallScores, features, similarityLevel }`
  - `similarityLevel`：`NONE=0` / `LOW=1`（语义更相似）/ `MEDIUM=2` / `HIGH=3`（语义差异大）——**直接用于 L0 的相关度展示，不自行折算分数**
  - `features`：`exact_phase` / `out_of_order_phase` / `token_bm25` / `core_count`
  - `recallScores[channel][recallName] = { score, isReverseQuery }`，`isReverseQuery` 表示该分数来自**反查**补齐
- **查询向量必须由应用提供**：`VectorQuery.value` 是应用传入的 `Float32Array`。官方原文：「如果未定义 value 字段，系统将尝试将原始 query 生成向量。**目前在 PC 上支持自动生成。**」→ **手机/平板必须自己算好 query 向量传入**；自动生成失败错误码 `1021200012`
- 限制（**两个口径是不同单位，不能"取小值"了事**，见 D8）：
  - 开发指南：查询词 **≤ 512 字符**；
  - API 参考 `retrieveRdb(query)` 参数：`query` 长度**上限 1000 字节**。
  - 512 个常见汉字按 UTF-8 约 **1536 字节**，因此"512 字符"并不满足"1000 字节"；**送入检索前必须同时校验字符数与 UTF-8 字节数**，两者都受限；
- `resultCount` 默认 500，本闭环取 top-K（默认 5，可调）
- 官方强调该能力「**对中文处理进行了优化，因此中文问答的效果优于英文**」
- **查询词超长/超字节处理**：**不报错、不静默截断**。做法是：① 完整问题**原样落库**并用于界面与历史记录；② 另建"检索输入"，按 **Unicode 代码点**边界裁剪（不拆断代理对，避免 emoji / 生僻字被切成乱码），同时满足 ≤512 字符与 ≤1000 字节；③ 裁剪会丢条件，故裁剪前先做**条件保留**——把时间、范围、否定等限定成分优先前置保留；④ UI 如实提示"问题过长，已取前 N 字检索"，并说明丢弃了什么（理由见第 8 节 D8）

### 5.3 向量索引：不建 ANN 索引（决策 D3）

**本闭环不创建 `GSDISKANN` ANN 索引，统一用暴力 KNN**：

```sql
SELECT chunk_id, text, document_id, embedding <=> ? AS distance
FROM kb_chunk
WHERE embedding IS NOT NULL
  AND embed_space = ?          -- 必须：只比同一向量空间（见 5.4.3；原稿遗漏此条件，与空间隔离承诺不符）
  AND document_id NOT IN (...) -- 归档排除；也可在 retrieval 的 filters 里表达
ORDER BY embedding <=> ?
LIMIT ?;
```

理由见第 8 节 D3。约束提醒：该查询天然满足向量索引的命中条件（`ORDER BY` 单一向量距离条件 + `LIMIT`、**不带 `DESC`**、度量与运算符一致），因此**将来若要加 ANN 索引，无需改写 SQL**。

> **精确 KNN ≠ 找到正确证据**（本稿修正 D3 的表述）：暴力 KNN 只保证在给定度量下给出**最近的 K 个向量**，不保证这 K 个里包含回答问题所需的证据。因此 D3 的复核条件不能只测"检索耗时"，还要测**证据召回率**。

如需按时间等标量做二次排序，**不可**在同一个 `ORDER BY` 里叠加第二个条件（会导致向量索引失效）；正确做法是「KNN 子查询取 Top-K + 外层再排序」。

### 5.4 向量化（决策 D1）

#### 5.4.1 采三层策略（含两条云侧候选路径）

| 层 | 实现 | 何时生效 | 在线性 | 发送内容（对应 1.1 的 ②） |
|---|---|---|---|---|
| 关键词层 | 优先实际验证可用的 FTS5/分词器，否则已验证 SQL LIKE 降级 | 已有规范化内容且关键词路径实际可用；均不可用时报检索失败（5.13.1） | 离线 | 无 |
| 端侧语义层 | `intelligence.getTextEmbeddingModel`（`ModelVersion.BASIC_MODEL`） | 能力探测通过、且**模型已准备**（见 5.4.2） | 推理在端侧；**模型准备需联网** | 无（推理不出设备） |
| 云侧语义层 A：**官方云侧模型** | `intelligence.getSupportedCloudModel()` → `ModelConfig.modelInfo` + `networkPolicy`（起始 26.0.0） | 端侧不可用、用户开启、且设备在支持列表内 | 需联网（**首次需下载模型**，`networkPolicy` 默认 `WIFI_ONLY`） | **待核实**：接口名含"云侧"，但 `networkPolicy` 描述为"下载云侧模型的网络策略"——本稿不推断推理位置，须以官方说明/实测确认 |
| 云侧语义层 B：**第三方嵌入 API** | 用户自填 Key 调云端嵌入 API（HTTP） | 端侧不可用、用户配置了嵌入 Key、联网且开启 | 需联网 | **参与索引的块文本**（不是命中片段） |

**关键词层是已有规范化内容的可用性下限**：语义层不可用仍须本机可查；它不能替代尚未完成的复杂解析。两条云侧路径不得默认开启，与①/③/④/⑤分别授权；从同步快照重新建关键词索引不需解析/视觉外发同意（见 1.1）。

> **"离线语义检索"≠"开箱即离线可用"**：端侧模型需要先准备（官方手机/平板步骤使用 `getSupportedCloudModel` / `modelInfo` 与下载网络策略，默认仅 Wi-Fi 下载）。首次使用、未准备模型、缓存失效或重启后的行为**必须真机验证**；在这些场景下应当如实降级为关键词层，而不是承诺语义检索可用。

#### 5.4.2 能力探测（不使用设备型号判断）

依据 [AGENTS.md](../AGENTS.md) 第 2.2 条（不编造 API，能力探测走官方依据）与第 2.4 条（不伪造成功），**能力探测一律走运行时 API，不硬编码设备型号或芯片型号**：

```
端侧嵌入探测流程：
  1. relationalStore.isVectorSupported()        → false 则禁用向量路（并切换到 5.6.1 的降级库配置）
  2. 模型准备：判断端侧模型是否可用（含缓存/下载状态）
       ├─ 未准备 → 允许联网时按 networkPolicy 下载（默认 WIFI_ONLY）；不允许则跳到 3
       └─ 已准备 → 继续
  3. intelligence.getTextEmbeddingModel({version: BASIC_MODEL, isNpuAvailable: false, cachePath})
       ├─ 抛 801        → 设备类型不支持，禁用端侧语义层
       └─ 成功 → textEmbedding.loadModel()
                  ├─ 抛 31300000 → 间隔 1s 重试 1 次；仍失败则禁用端侧语义层
                  └─ 成功 → getEmbedding('测试') 取 Array.length 作为维度 N
  4. 任何一步失败都降级到下一层（云侧 A → 云侧 B → 关键词层），不崩溃、不阻断导入
```

补充要求：

- **`isNpuAvailable` 首版传 `false`**（CPU 路径），避免因 NPU 不可用直接抛 `31300000`；是否启用 NPU 作为性能优化项在真机验证后另行决定；
- **向量维度运行时读取**，不硬编码（`floatvector(N)` 的 N 上限官方未给）；
- **错误码 `801` 语义歧义**：`isReadOnly`/`rootDir` 下的写操作也返回 801，需按调用点区分，不可一律当作「设备不支持」；
- **模型的下载与推理要分别定义**：`networkPolicy` 只管下载；下载完成后能否离线推理、缓存有效期与重启行为**均需真机验证**（见 §7.1 与 D16）。

#### 5.4.3 向量空间一致性与**维度迁移**（必须落库）

不同嵌入来源产生的向量**不在同一向量空间，不可互相比较**。因此：

- 每个向量随 `embedSpaceId` 一起落库，`embedSpaceId` 由**来源 + 模型标识 + 维度**组成（例如 `intelligence:basic:v1:128`、`cloud:bge-m3:1024`）；
- 查询向量必须用**与库内向量相同的 `embedSpaceId`** 生成；不一致时**不允许**参与距离计算；
- 检索时只对 `embedSpaceId` 与当前嵌入来源一致的块做向量召回；不一致的块退回关键词路；
- 嵌入来源或模型变更时，把相关文档标记为「待重建向量」，**不静默混用**；
- 该约束与 [AGENTS.md](../AGENTS.md) 第 7 节「持久化结构带版本与升级策略」一致。

**但 `embedSpaceId` 不是维度迁移方案**（本稿修正）：`embedding FLOATVECTOR(N)` 的 **N 在建表时就固定**，行级标签无法让一个固定维度列装下不同维度的向量。因此：

| 规则 | 说明 |
|---|---|
| 单一活动空间 | 同一时刻**只允许一个"活动向量空间"**；`kb_chunk.embedding` 的 N 即该活动空间的维度 |
| 模型/维度变更 | **新建块表**（如 `kb_chunk_v2`，`FLOATVECTOR(N2)`）→ 重新索引 → 校验通过后**原子切换读取指向**（表名切换或视图/元信息 `kb_meta` 指向），旧表确认无误后删除。切换期间旧索引保持可查，避免"改模型即不可用" |
| 禁止混装 | 不得在同一列里写入不同维度的向量，也不得只改 `embedSpaceId` 而不改列定义 |
| 多空间并存 | 若确需并存多个维度，**按维度/模型分表**（每表一个固定 N），不共享同一列；并存前需实测存储布局与召回写法 |
| 召回必须过滤 | 向量路 SQL **必须带 `embed_space = ?` 与 `embedding IS NOT NULL` 条件**，示例见 5.3，不跨空间比较 |

> **另需注意**：本机文档库仍未收录"端侧生成的向量仅在本设备有效、不可跨设备检索"的口径，而初审引用的官网更新版本含有该表述（见 D16）。无论该口径最终是否成立，本方案"**索引与向量不进同步、各设备本地重建**"（D12）都与之相容。

### 5.5 结构感知分块（D1 文本参数 + D19 结构规则）

官方 `splitText` 不作为手机/平板依赖，**分块自建**。先解析结构节点，再对过长节点做有界切分；不把完整 Office/PDF、表格或图像代理直接平铺给当前字符串 chunker。以下保留文本基线参数，不表示当前实现已支持结构：

| 参数 | 取值 | 理由 |
|---|---|---|
| 块大小 | **512 字符** | 端侧嵌入单次推理上限即 512 字符（官方硬上限）；超出会被截断或报错 |
| 重叠 | **10%**（约 51 字符） | 官方知识加工 `overlapRatio` 默认 0.1，取官方默认值对齐 |
| 切分边界 | 章节/工作表/幻灯片/原页/节点优先；过长文本内再按段落、句子、有界硬切 | 保留来源关系，标题跟随正文，不产生仅标题证据块 |
| 空块 | 丢弃纯空白块 | — |
| 溯源 | 文档/规范化版本、`blockIds/locator/assetId/evidenceType`，可选文本偏移 | 原生定位不能只用 `charOffset`；多区域列表可核对（见 4.1） |

**结构切分规则（待实现）**：

- 标题路径随正文携带，长列表/代码块保留类型与父节点，不能为满足长度无提示删内容；所有附加标题/表头/图注都计入实际送 embedding 的长度。
- 表格以表头与有界行组形成可检索文本，保留单元格定位、类型与合并关系；超宽/超长单行可有界拆解，仍关联原行/单元格。完整表格结构存在规范化快照中，不能只留切碎 Markdown。
- 跨页表格只在关联可靠时合并逻辑表，仍保留每段原页/区域；工作表、幻灯片及图像边界不能未经规则拼接。
- OCR、图注、视觉描述、自动 tag/分类与用户标注按来源分开建文本代理，关联相同资产；图像去重不丢父文档关系，也不改变用户标注归属。
- 文本切分保证 Unicode 边界安全；当前 chunker 使用 UTF-16 字符串长度且已知可能拆代理对，标题/正文分离缺陷也尚未修复，需新增版本与测试，不能由历史样本通过推出普遍安全。
- 文本大小参数继续以 512/10% 为基线，模型字符/token/字节计量需分别校验；实际完整输入不满足模型限制时有界再切分并记录映射，不静默截断。切块策略变更必须新版本重建。

**块体积核算**：512 个常见汉字 UTF-8 约 1536 字节，128/1024 维 float32 分别为 512/4096 字节；还需计算定位、结构和其他列的整行体积，严格 <2 MB。该示例不是 Unicode 最大字节数证明，更不是导入文件上限。

**分块的确定性测试（host 层，不依赖设备）**：用例在 `entry/src/test/ChunkerCases.ets`（构造用例）与 `entry/src/test/CorpusCases.ets`（真实语料用例，语料见 6.1.5），经 `entry/src/test/run-host-tests.cjs` 转译后在 Node.js 执行：

```bash
DEVECO_SDK_HOME="<DevEco Studio 安装目录>/sdk" node --test entry/src/test/run-host-tests.cjs
```

覆盖范围：空文本 / 纯空白 / 前导与尾部空白、恰好 512 与 512+1 的边界、重叠比例（0 / 10% / 25%）对下一块起点的精确影响、无边界长文本硬切、段落边界优先于句末标点、窗口内不足一半处的分隔符**不采纳**、中文句末标点、英文句末标点、中英混排与混合标点、单换行、连续空行、超长多段落（>5000 字符，≥10 块）、重叠比例递增与块数单调、含 emoji/代理对（不丢字符，**已知限制：可能拆分代理对**）、极端小块参数（32 / 64 / 128）。每条用例都断言同一组不变量：块长 ≤ 上限、`char_offset` 处原文与块文本一致、块内无首尾空白、偏移严格递增、相邻块无空洞、覆盖到原文有效结尾。

**缺陷记录（由上述用例发现并已修复）**：`SENTENCE_BREAKS` 初版漏掉英文句号 `.`，导致中英混排长文在句号处不切分、按硬切落点切分（复现：`paddedTo(300,'alpha') + '.' + 填充`，期望首块在 `.` 后结束，实际切在第 512 个字符）；修复为 `['。','！','？','；','.','!','?',';','\n']` 后 31 项全部通过。日志：`.cache/test-logs/2026-10-02-chunker-host-5b4f742/host.log`（修复前的失败可在同目录索引的前一次运行中复现）。

同一结构策略下切换嵌入来源仍沿用文本基线边界，尽量只重算向量；若模型输入限制或结构策略要求边界改变，必须更新 `chunkStrategyVersion` 重建，不承诺任何换模型均无需重切。上述历史测试只覆盖原字符串 chunker。

### 5.6 数据布局与建表 DDL

#### 5.6.1 单库方案

官方手工建库示例用**两个库**（向量库 + 倒排库）。**本项目采用单库**：向量列放进块表，倒排用同库 FTS5 虚表，只向 `getRetriever` 传一个 `dbConfig`。理由：

1. 单库避免两库间的一致性维护与备份分裂——`retrieval` **不支持备份恢复**，重建成本高；
2. 官方 API 参考示例本身把向量表与 FTS 表指向同一个 `name`，单库是受支持形态；
3. 主键天然同源，不需要额外保证一致。

**DDL 适用范围**：下方保留的是四稿文本基线布局/待验证 DDL，不是八格式最终建表定义，也不表示已部署同步表。它缺少规范化快照、图像/标注及原生定位；多格式扩展布局见 5.6.4，须完成产物取证、平台验证与团队评审后另行冻结，不能照抄此 DDL 宣称新契约已满足。

```sql
-- ① 同步表：原文 + 共享元数据（进端云同步；字段一旦部署到生产环境只能新增，不能删改，见 5.16）
CREATE TABLE IF NOT EXISTS kb_document (
  id TEXT PRIMARY KEY,                 -- 稳定 ID（端云同步要求主键全局唯一，禁用自增）
  title TEXT,
  source_type TEXT,                    -- TEXT_FILE / VOICE / IMAGE_OCR
  content_hash TEXT,                   -- 原文校验与幂等判重（同步后另一端据此校验原文一致）
  content TEXT,                        -- 小原文直接入库：整行须严格 < 2 MB
  content_asset ASSET,                 -- 大原文走资产列（资产文件需放分布式文件路径，端云同步按需下载）
  schema_version INTEGER, created_at INTEGER, updated_at INTEGER
);

-- ② 本地处理状态（不进同步：A 已索引不代表 B 已索引）
CREATE TABLE IF NOT EXISTS kb_doc_state (
  document_id  TEXT PRIMARY KEY,
  status       TEXT,                   -- IMPORTED / INDEXING / INDEXED / FAILED / CANCELED / ARCHIVED
  chunk_count  INTEGER,
  fail_reason  TEXT,
  index_version TEXT,                  -- 本机索引版本（分块策略 + embedSpaceId），与文档内容版本分开
  updated_at   INTEGER
);

-- ③ 本地派生表：块与向量（不进同步，可整表重建；字段演进不受同步约束）
CREATE TABLE IF NOT EXISTS kb_chunk (
  chunk_id     TEXT PRIMARY KEY,
  document_id  TEXT NOT NULL,
  ordinal      INTEGER NOT NULL,
  text         TEXT NOT NULL,
  char_offset  INTEGER NOT NULL,
  embed_space  TEXT,
  embedding    FLOATVECTOR(N)          -- N 在建表时固定；维度变更走 5.4.3 的换表迁移
);

-- ④ 倒排虚表（本地派生，不进同步）。**必须自带 document_id**：
--    倒排路的 responseColumns 与 filters 只能引用本表列（fromClause 即本表时不做 JOIN）
CREATE VIRTUAL TABLE IF NOT EXISTS kb_chunk_fts USING fts5(
  chunk_id, document_id UNINDEXED, text,
  tokenize = 'customtokenizer',
  content = 'kb_chunk', content_rowid = 'rowid'
);

-- ⑤ 本机元信息（不进同步）
CREATE TABLE IF NOT EXISTS kb_meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
```

**原文怎么传给另一台设备（本稿修正，原稿缺失）**：`sandbox_path` 是本机路径，**不是原文载体**——B 端拿到这个字符串无法取得 A 的文件字节，而索引与块又不同步，B 将缺少重建所需的原文。因此：

| 原文大小 | 载体 | 依据 |
|---|---|---|
| 小文本（阈值内，需实测） | `kb_document.content`（TEXT 列） | 行须严格 < 2 MB（5.1）；阈值按"整行（含向量与其它列）"核算后取安全值 |
| 大文件 | `kb_document.content_asset`（`ASSET` 列） | `ValueType` 支持 `Asset`/`Assets`；`AssetStatus.ASSET_TO_DOWNLOAD` 表示按需下载；`Asset.size` 是端云同步判断资产是否变更的关键字段；**资产文件需放分布式文件路径** |
| 本机路径 | `sandbox_path` **不再作为同步列**（本机信息） | 各设备路径不同，且沙箱副本可重建 |

验收必须让 **B 端在拿不到 A 的原文件的情况下**取得相同原文、核对 `content_hash` 一致，再建立本机索引；"文档列表相同"不算原文同步通过（见 §6）。

**表的界线（八格式目标，最终列定义待评审）**：

| 类别 | 成员 | 是否进同步 | 字段演进 |
|---|---|---|---|
| **共享内容** | 文档原件/元数据、版本化规范化 manifest/内容/图像、用户标注（见 5.6.4） | 用户开启③后，是（`DISTRIBUTED_CLOUD`） | 已部署同步列只能新增，不删改；新增表/资产配置待评审 |
| **本地派生/任务** | `kb_doc_state`、块/向量/FTS、`kb_meta`、处理任务/缓存路径/归档偏好 | 否 | 按版本迁移，可从完整快照重建；任务和凭据不能通过同步恢复 |

设计含义：

- **文档级"是否已索引"是本机结果，不是共享事实**：`status` / `chunk_count` / `fail_reason` 已从同步表移出到 `kb_doc_state`，避免"A 已索引"被 B 端误读为"B 已就绪"；
- 四稿不预留 `modality` 的理由属于当时纯文本范围；本稿实际消费格式、节点/证据类型及资产身份，须显式进入目标模型，不能再因“本期未用”省略。字段演进仍遵循新增而非修改已部署列；
- 索引与向量如果也进同步，会因为高频重建触发云端限流（官方建议只对"用户操作触发的离散变更"启用），且 `retrieval` 不支持备份恢复、向量还绑定 `embedSpaceId`，故一律本地重建。

`recallCondition` 两路的文本基线字段（**responseColumns 只能取该路 `fromClause` 表的列**）：

| 字段 | 向量路 | 倒排路 |
|---|---|---|
| `fromClause` | `kb_chunk` | `kb_chunk_fts` |
| `ftsTableName` | — | `kb_chunk_fts` |
| `primaryKey` | `['chunk_id']` | `['chunk_id']` |
| `responseColumns` | `['chunk_id', 'text', 'document_id']`（均在 `kb_chunk` 中） | `['chunk_id', 'text', 'document_id']`（**必须在 `kb_chunk_fts` 中声明**，见 ④） |
| `vectorQuery.column` | `embedding` | — |
| 空间/归档过滤 | `filters` 同时使用 `OP_EQ(embed_space, ?)` 与 `OP_NOT_IN(document_id, 归档文档 ID 列表)`；显式包含归档时仅撤去后者 | `filters` + `OP_NOT_IN(document_id, 归档文档 ID 列表)`，包含归档时撤去该条件（`document_id` 为 FTS 表列；`fromClause` 必须含过滤字段） |

契约约束（违反会报错或结果错乱）：

1. **所有通道的 `primaryKey` 数量必须相等且非空**（API 原文：一次查询中所有召回操作的主键字段数量必须相等且不能为空）→ 统一用单列 `chunk_id`；
2. `responseColumns` 至少含 `chunk_id` 与 `text`，供 L0 直接取用；**且只能是该路 `fromClause` 表中真实存在的列**——外内容表不会把未声明的字段自动暴露出来（原稿让倒排路返回未声明的 `document_id`，是契约错误，本稿修正）；
3. `VectorQuery.similarityThreshold` **必须 ≤ `VectorRerankParameter.thresholds` 的最小值**（默认 `[0.6, 0.45, 0.4]` → 默认最大只能填 **0.4**），否则报 `1021201008`；本项目填 `0.4`；
4. 倒排路 `fromClause` 与 `ftsTableName` 填**同一个值**（把检索局限在倒排表内），标量过滤一律走 `filters`。若改用 `select...join` 形式，API 要求 `select` 中必须含 FTS 表的 `rowid`（形如 `SELECT fts表的rowid as rowid, * FROM ...`）；本闭环**优先不用 JOIN**，因为归档过滤已可由 FTS 表内的 `document_id` 表达；
5. FTS5 是虚表，**不能与普通表混用同一套 DDL 管理**，重建索引时单独处理；
6. **`StoreConfig.vector = true` 是启用向量数据库能力的开关**（官方原文："该参数为 true 时才可以使用向量数据库"），不是"无副作用"的装饰位。本稿撤回旧稿"库内无向量数据时该开关无副作用"的表述；`isVectorSupported() = false` 时采用哪套 `StoreConfig` 与 DDL（是否保留 `FLOATVECTOR` 列）**列为 5.6.2 必测项**。
7. 多格式召回先通过稳定 `chunk_id` 读取应用自己的证据/locator/资产关联，不要求 FTS 自动返回未声明结构。tag/分类过滤与本机归档过滤须在最终 schema 下验证，不能仅凭后处理丢结果后仍宣称 top-K 覆盖。

#### 5.6.2 建表 DDL 的前置验证（实现第一步）

以下各点在本机官方文档中**无直接示例**，必须先跑通最小 demo 再固化 DDL：

1. FTS5 **外内容表**（`content='kb_chunk', content_rowid='rowid'`）+ `customtokenizer` 的组合是否可用；
2. 单库内同时存在向量列与 FTS5 虚表时，`retrieval` 双通道是否都能正常召回；
3. `fts5` 与 `ICU` 不兼容，本方案用 `customtokenizer` 走 FTS5，需确认 `CUSTOM_TOKENIZER` 在当前设备可用（`isTokenizerSupported`）；
4. **FTS5 外内容表的删除协议**：外内容表不能只对内容表做 `DELETE`，必须按 FTS5 自身协议（对 `kb_chunk_fts` 发送 `'delete'` 命令，并带旧值）同步索引，否则倒排索引与内容表不一致，会出现"已删文档仍能命中"。此点官方 FAQ 未展开，**必须实测**；
5. **倒排路的字段可用性**：`kb_chunk_fts` 声明 `document_id` 后，`responseColumns: ['chunk_id','text','document_id']` 是否真能召回该列（验证"外内容表只暴露已声明列"的边界）；
6. **归档过滤**：`filters` + `OP_NOT_IN(document_id, '归档ID列表')` 能否在 `fromClause = kb_chunk_fts` 下生效；归档文档数量大时（数百上千 ID 拼成字符串）是否仍可用，超限则改为 `select...join` 形式；
7. **端云同步的适用性**：FTS5 虚表与含 `FLOATVECTOR` 列的表能否 `setDistributedTables(..., DISTRIBUTED_CLOUD)`（本期设计不依赖该能力，但若实测可用，也**不得**把索引放进同步，理由见 5.6.1）；
8. **同步后的删除感知**：验证 `autoCleanDirtyData=false` 下，通过 `predicates.greaterThan(Field.CURSOR_FIELD, lastCursor)` 能查到云端删除，并能用 `cleanDirtyData` 正确清理本地；
9. **原文资产同步**（本稿新增，见 5.6.1）：`ASSET` 列 + 资产文件放分布式文件路径 + `AssetStatus.ASSET_TO_DOWNLOAD` 的按需下载链路是否可用；下载前 `path` 指向什么、下载完成如何触发、失败如何重试；同时测 TEXT 列原文的大小阈值（整行须 < 2 MB）；
10. **不支持向量时的库配置**：`isVectorSupported() = false` 时，`vector: false` 的库能否承载同一套 DDL（尤其含 `FLOATVECTOR` 列的建表语句是否报错），以及是否需要准备"无向量列"的降级 DDL；
11. **维度迁移**：按 5.4.3 的"新建块表 + 重新索引 + 原子切换"流程验证一次模型/维度变更，确认旧表可查、切换不丢数据。

若第 1 点不可用，退化为**独立内容表的 FTS5 虚表**（`fts5(chunk_id, document_id UNINDEXED, text, tokenize='customtokenizer')`，不带 `content=`），由应用层在写入/删除时同步维护两张表——代价是多一次写，但仍在单库内。

**实现约束（由实测新增，已是硬约束）**：

1. **能力探测不能只看 API 返回值**：向量库与分词器都要"探测 API + 实际建表/写入"双重确认，任一失败即降级；
2. **FTS5 虚表写入与普通表写入必须分开提交**，且状态机可恢复（先 `INDEXING`，写倒排成功后再 `INDEXED`，失败保留可重试状态）；
3. **FTS 表的定义要记录在 `kb_meta`**（实测的 4 种变体说明"表已存在"不能只靠 `IF NOT EXISTS` 判断，否则会误判变体）；
4. 中文检索在**默认分词器下不可用**，模拟器/CI 上的关键词路应显式降级为 SQL `LIKE`/`前 N 字`匹配，并在界面标注"仅关键词（降级）"。

**历史结论边界（2026-10-12 注记）**：以上保留 2026-10-02 的环境、结果及当时约束，不代表本轮复验。特定模拟器的事务写入现象不能泛化为所有真机的写入/删除协议；后续须验证实际提交及恢复行为。当前源码尚未完成最终 `INDEXED` 更新，也未接真实文件/结构解析，不能用该历史链路宣称八格式可用。

#### 5.6.4 八格式存储扩展与三层权威

| 层 | 内容与用途 | 是否共享 |
|---|---|---|
| 原始内容 | 八格式原件、原字节哈希/内容版本/格式；核对最高权威 | 开启③后共享，二进制走资产，不转成 TEXT 冒充原件 |
| 规范化快照与标注 | 版本化 manifest、结构节点/表格、提取图、OCR/描述/自动标签快照、用户修正；可移植的处理结果，不等于事实已核实 | 开启③后共享；完整校验后发布离散快照，用户修正独立版本 |
| 本机索引与任务 | 块、向量、FTS、就绪状态、任务 ID/检查点、缓存位置、归档偏好 | 不共享；索引可从完整快照重建，任务仅本机恢复 |

共享 manifest 必须绑定 `documentId/documentVersion/originalHash/normalizedVersion`，列出节点/资产身份、大小、哈希、必需/可选及覆盖范围；引用不跨版本混装。本机校验所有必需内容与来源关联后才认定快照可用。快照缺图或缺页不能仅因文本可读标完整。

共享快照/资产/标注与本地处理任务需要新增概念布局，不在本稿捏造完整 DDL。大 JSON、原件、图片走受控资产，整行含所有元信息仍须 <2 MB。云侧表/列、资产 manifest 发布与下载、用户标注冲突策略由核心/平台共同评审并按 5.16、6.2 验证；不得只同步本机路径字符串。

### 5.7 八格式导入与托管解析（D19、D20、D22）

- 用系统**文件选择器**（`DocumentViewPicker`）选取文件，返回**临时授权路径、不需要额外存储权限**；
- 导入时**保留原始字节沙箱副本**，核对哈希并分配稳定身份；原件是溯源依据，不能用解析后的 Markdown 替代，不依赖选择器长期授权；
- 目标白名单是八格式，扩展名大小写规范化且与实际内容/MIME核对；无法确定类型、伪装、空/损坏/加密文件明确拒绝或待处理，不尝试错误解码；
- `.txt/.md` 为 UTF-8：识别 BOM、校验非法字节，规范化换行/BOM 时保存到原文映射；二进制不适用此规则；
- 前台可中断、按预算逐文件/小批处理，数据库写入串行；单写连接不等于所有网络或解析任务必须无条件串行，外部并发上限须先标定；
- 本机保存原件无需④/⑤；真实个人文件外发须先通过隐私/服务/资源门禁并获得用户同意。未知格式能力不显示“已支持”。

#### 5.7.2 MinerU 精准 API 优先接入方案

2026-10-12 已只读核对用户提供的 MinerU《文档解析接口文档》，未提交任务或下载实际结果包。**优先评测精准 API 的 `vlm` 模式，不锁定 MinerU 满足全部格式质量/定位要求**；`pipeline` 默认与 `vlm` 推荐是文档模式值，不是固定生产模型版本。无需将 Python/模型/Office 转换引擎嵌入手机，也不部署回调服务。

| 步骤 | 接口/行为 | 应用契约 |
|---|---|---|
| 申请上传 | `POST /api/v4/file-urls/batch`，一项或小批 `files`，返回 `batch_id/file_urls` | 用户自配 Token，仅在④授权后请求；稳定 `data_id` 关联业务文件与版本，不用顺序/文件名作为唯一匹配依据 |
| 上传原件 | 客户端 PUT 返回的签名地址 | 使用沙箱原字节；完成后服务自动提交，不再额外创建任务；地址不入日志/同步，不把 Token 自动转发给存储主机 |
| 轮询 | `GET /api/v4/extract-results/batch/{batch_id}` | 区分 `waiting-file/pending/converting/running/done/failed`；有界退避/恢复，先查已有任务而非重复收费提交 |
| 下载/校验 | 每文件 `full_zip_url` | `done` 只表示服务完成；下载、ZIP 安全检查、schema/原生锚点/结构/图像关联校验后才发布规范化快照 |
| 能力判定 | 逐格式按 5.7.1 校验 | 缺原生锚点不能用渲染页号冒充；不足时保留原件、显示未完整支持，另评测获批准的托管补充服务 |

显式启用表格识别；语言、OCR、公式策略在固定样本上确认，`is_ocr` 默认 false 不证明扫描文件可完整覆盖。文档指出 `vlm` 的公式开关只影响行内公式，不能当所有公式禁用/启用保证。

| 官方描述（非实测） | 设计采用方式与未决项 |
|---|---|
| 精准 API 列出 pdf/docx/xlsx/pptx、jpg/png 等 | 八格式中复杂文档可优先评测；txt/md 本地，文档支持更多格式不自动扩大 App 白名单 |

托管文档称结果包含 `full.md/layout.json/*_model.json/*_content_list.json`，并指向开源输出文档；本轮取得的开源 4.0 文档使用另一套协议/保存命名，且明确远端输出由远端服务定义。**必须取实际托管样包锁定 API 路径版本、产物 schema/生产版本与适配版本**，不能直接把开源协议套进托管结果或猜图像文件名。缺生产版本时记“未报告”，按兼容性检测处理漂移，不虚构版本。

#### 5.7.3 不可信产物、隐私与选型门禁

- 原件及结果包均作不可信输入：防路径穿越、绝对路径、符号链接、重复/冲突成员及解压炸弹；校验成员数、压缩比、展开字节、磁盘预算、图像像素、schema/枚举/数值范围、定位和资产关联。拒绝的包隔离/清理，不执行宏/脚本或自动加载外部资源。
- 签名地址/重定向限定到经核验的服务及存储接收方，校验传输安全；授权请求头不跨主机无条件传播。产物内未知外部资源只报缺失，不能按任意地址下载。
- API 页仅提供法律协议导航，本轮未取得完整条款。原件/结果/缓存保存期限、删除保证、训练用途、地域、转处理方及结果访问控制均未核验；上传链接 24h 与 `cache_tolerance=900` 秒都不是到期销毁承诺。
- 文档错误表称运行中任务暂不支持删除，但没有可直接采用的取消/删除 API 说明。停止本地轮询不等于云端取消，删除本机资料不等于清除服务缓存/备份。
- 服务许可/账号条件、隐私和预算未通过前，真实个人资料外发受阻；后续仅可在另行授权下用专门非敏感、已获许可样本取证。补充服务与视觉模型须同样评审，禁止无提示切换接收方。

### 5.8 在线生成：云端 LLM 与输出校验

- 传输：`@kit.NetworkKit` 的 `http`，OpenAI 兼容 `POST /v1/chat/completions`，支持流式与非流式；
- 服务商预设 + 用户自填 Key（**代码与仓库内零硬编码密钥**，[AGENTS.md](../AGENTS.md) 第 2.8 条）；接口配置项含 Base URL、模型名、Key；若改用官方云侧模型（5.4.1 路径 A），同样受 1.1 的独立授权约束；
- 请求只包含 system 提示词、**本次命中文本与版本/证据类型**、用户问题，不发送整库/原件/原图；tag/分类只作检索线索，不单独注入为事实证据。OCR、视觉描述标来源与不确定性，未经用户同意不把⑤上传能力复用给①；回答模型看图须另行扩展契约与同意；
- 提示词要求模型**只依据给定片段作答**，无依据时明确说「资料中没有」；要求以编号形式标注引用来源；**提示词是引导，不是正确性保证**；
- **输出校验分两段，且不得混为一谈（本稿修正）**：

  | 段 | 校验内容 | 可自动化 | 结论强度 |
  |---|---|---|---|
  | **第一段：引用合法性** | 引用编号必须存在于本次注入的命中集合内；不存在的编号一律不展示 | 是，可完全自动 | 只能证明"引用指向真实片段"，**不能证明答案受原文支持** |
  | **第二段：答案依据** | 回答中的每个断言是否真被所引片段支持（条件、量词、时间、否定不得被改写） | **否**，无法用规则可靠判定 | 只能通过"引用片段快照随回答落库 + 用户可核对"与固定评测集人工度量支持率（见 §6 与 D13） |

- 第一段不通过时不展示该引用，并按策略标注或整体降级 L0；
- 超时 / 空响应 / 鉴权失败 → 降级 L0 并给出原因；
- **不使用 `as` 断言替代校验**，逐字段做运行时类型与取值检查；
- **流式输出要区分状态**：流式过程中的文字一律是**候选文本（未校验）**，必须标注"生成中"；只有流结束后完成第一段校验，才能标记为"已完成校验"；若最终校验不通过或降级为 L0，已显示的候选文本要撤回或明确标注"未通过校验"；
- **禁止把"编号校验通过"或"提示词要求"表述为"答案已核实"**（[AGENTS.md](../AGENTS.md) 第 2.4 条）。
- 图片描述和 OCR 的来源校验也不证明识别准确；L1 须保留其候选性质与可核对来源，不以有效引用掩盖错误视觉结论。表格计算超出本期时明确提示不支持，不让模型猜计算结果冒充确定性执行。

### 5.9 密钥存储（决策 D4）

采用 **Asset Store Kit（ASSET）**：安全环境内加解密（AES256-GCM）、按应用 appId 做属主隔离、支持锁屏状态与用户认证访问控制。

要求：

- 回答 Key、嵌入 Key、MinerU Token、视觉 Key 按用途独立保存与授权，只有对应服务的认证请求携带；不内置共享团队密钥，不传自有后端，不跨用途隐式复用；
- 禁止明文落库、禁止写入日志、禁止进入截图与 AI 上下文（[AGENTS.md](../AGENTS.md) 第 2.8 条）；
- ASSET 面向**短敏感数据、不适合高频读写**，因此**启动时读一次、缓存在内存**，不在每次请求前读取；
- 若将来启用跨设备能力，添加资产时显式设置不同步，避免密钥随华为账号同步出去；
- 更换签名证书会导致 appId 变化、旧资产读不出，**需在升级路径中处理**（引导用户重新填写）。
- 上传/下载签名地址同样是敏感能力凭据：不进日志、截图、历史回答或同步，按本机安全缓存策略仅保留恢复所需期限；Token 不转发至其他存储主机。数据文件的 ArkData `ASSET` 资产列与这里的 Asset Store Kit 密钥存储是两种不同用途。

| `ohos.permission.MICROPHONE` | **user_grant** | 语音输入（`speechRecognizer`） | 仅当用户使用语音输入时按需申请；拒绝后键盘输入不受影响 |

- 文档导入**不引入**宽泛存储权限（走 `DocumentViewPicker` 选择器 + 沙箱副本）；
- 图片走 `PhotoViewPicker` 选择器与图库选择器**不需要额外权限**；若将来支持拍照取字，再单独评审 `ohos.permission.CAMERA`；
- **端云同步不需要额外用户授权权限**（系统级能力，前提是用户已登录华为账号并在「设置-云空间」打开同步开关，见 5.16）；
- **本稿修改了原「不引入任何用户授权（user_grant）权限」的表述**：语音输入必须要有麦克风授权，因此改为"按需申请、拒绝即可用其余功能"，并作为待团队确认项（见头部）；
- `INTERNET` 是系统授权，不是个人文件外发同意，不能用其声明代替①–⑤业务授权；本轮只改 spec，不修改权限配置。
- 无网络/无麦克风下须完成 txt/md 本地导入及 L0，或对已保存的完整规范化快照离线建关键词索引/查原图；未解析复杂格式显示待处理，不承诺首次完整解析。网络权限不是 user_grant，验收用断网/无网络配置、未配置服务或拒绝业务同意模拟，而非期待网络弹窗。

### 5.11 数据归属

| 数据 | 权威来源 |
|---|---|
| 文档原件 | 本机原字节及版本/哈希是溯源最高权威，允许同步副本，路径不是共享身份 |
| 规范化内容/表格/提取图/识别快照 | 应用保存的版本化处理结果，可核对但可能抽取有误；共享完整快照让另一端无需再次上传 |
| 块/向量/FTS/本机状态 | 本机派生数据，低于原件与规范化快照，可从完整快照重建，不同步 |
| 用户标注 | 用户修正的共享元数据，与自动描述/tag/分类分开，重处理不覆盖 |
| 会话与回答记录 | 应用沙箱（ArkData）；历史引用的快照随回答落库，不随文档删除而消失（见 4.4） |
| 用户知识库的同步副本 | **用户本人的华为云空间**；经③同意的原件、规范化资产/图像与共享标注，不含索引、任务、沙箱路径或凭据 |
| 模型回答 | 待验证的候选内容，**不直接作为执行事实** |
| 用户 Key/Token | 本机安全存储，认证时仅发对应服务，不作内容上传/同步 |
| 语音/提问 OCR 临时输入 | 默认不长期保留原音频，提问图片可由用户选择去留（5.15.2）；与图片知识源必须保留原图的规则分开 |
| 托管服务数据 | 已经④/⑤发送的文件/图片及结果由服务规则约束；本机删除不能证明服务侧清除，门禁见 5.7.3 |

### 5.12 超时、取消、重试、幂等与部分失败

| 项 | 定义 |
|---|---|
| 索引超时 | 单文档设上限；超时标记该文档失败，不阻塞其余文档 |
| 索引取消 | 用户可取消；已完成文档保留；下次可继续 |
| 检索超时 | 明确检索失败/超时，不当作“资料无答案”；保留问题和旧结果，不用失败空数组触发无答案结论 |
| 生成超时 | 设首字节与总时长上限；超时降级 L0 并标注原因 |
| 生成重试 | 允许用户手动重试同一问题；不自动无限重试 |
| 嵌入重试 | `31300000` 间隔 1s 重试 1 次；仍失败则降级，不循环重试 |
| 幂等 | 原字节 `contentHash` 负责重复导入，处理指纹负责解析/OCR/视觉版本，索引版本负责块/向量；同指纹有已验证结果就复用，不混不同版本 |
| 部分失败 | 多文件逐文件报告，单文件另列缺页/结构/锚点/图片增强缺口；可查范围与不可用范围可见，必需结构不全不标完整支持 |
| 提交/轮询超时 | 保存本机 job、业务 data ID、已取得服务 ID；先查询再恢复。提交响应不确定时记待核对，不假定服务幂等或盲目自动重提 |
| 上传/下载超时 | 首字节、总时长、传输大小有界；检查签名地址窗口，恢复仅在服务已核验支持范围内，不能假定断点续传 |
| 429/排队/服务错误 | 有界退避与总轮询预算；耗尽后暂停供手动恢复，遵循已核验的限频/费用约束，不无限重试 |
| 取消解析/视觉 | 停本地上传/下载/非必要轮询/新请求，分别报告远端状态；未核验取消接口时不得标云端已取消或已删除 |
| 关闭授权 | 停该项后续外发，保留本机原件及已验证内容；明确已上传数据可能继续处理，不谎称撤回 |
| 用户修正 | 描述/tag/分类重跑生成新自动版本，保留用户编辑/删除覆盖记录，不因重新生成把已删除 tag 恢复 |

页面离开时解除 UI 订阅、停非必要轮询并保存检查点；返回可查已有任务。进程终止后恢复不依赖自动后台续跑。重算/解包/校验异步执行；仅校验并发布的新版本进入活动索引，暂停不破坏旧已验证结果。所有超时、重试/轮询与费用参数必须在 5.13.3 标定后冻结，未知值不以默认无限代替。

### 5.13 能力探测与「能力 × 预算」降级策略

#### 5.13.1 能力降级矩阵（与能力有关，与资源无关）

| 探测结果 | 向量路 | 倒排路 | 生成 | 界面标注 |
|---|---|---|---|---|
| 全可用 + 有 Key | 开 | 开 | 按 2.2/4.4 选 L0 或尝试 L1 | 「向量 + 关键词」；只有实际生成完成才标模型生成 |
| 向量不可用 + 有 Key | 关 | 开 | 按 2.2/4.4 选 L0 或尝试 L1 | 「仅关键词」；有 Key 不等于联网/①同意/生成成功 |
| 向量可用 + 无 Key | 开 | 开 | L0 | 「向量 + 关键词 · 仅检索」 |
| 向量不可用 + 无 Key | 关 | 开 | L0 | 「仅关键词 · 仅检索」 |
| 有效 FTS 不可用，但已验证 LIKE 兜底可用 | 关 | SQL LIKE 降级 | 有召回才按①选 L0/L1 | 「仅关键词（降级）」；不能宣称中文分词/语义质量通过 |
| 关键词兜底也不可用 | 关 | 关 | 不凭失败触发生成 | 明确报检索不可用，不静默空结果 |

#### 5.13.2 资源预算策略（与资源有关，与能力无关）

同一台设备的能力矩阵行不变，但**资源预算**不同时策略要变；两维必须分开记录，不能只报"降级了"。

| 预算输入 | 观测方式 | 影响的策略 |
|---|---|---|
| 语料块数（1k / 1w / 5w） | 库内计数 | 是否仍用暴力 KNN（D3 复核条件）、`topK` 上限、是否提示"资料规模较大" |
| 可用内存 / 前台或后台 | 运行时判断 | 索引分批与事务粒度、是否放弃预取、是否暂停索引 |
| 是否充电 / 电量 | 运行时判断 | 向量化与索引是否可继续（大量写入 + 推理属高耗电动作） |
| 是否有网络与用户开关 | 探测结果 | 是否使用云侧嵌入（不得默认开启，见 1.1） |
| NPU 可用性 | `isNpuAvailable`（首版 `false`，见 D9） | 端侧嵌入走 CPU 还是 NPU |

约束：**策略调整只允许改变"用哪条路 + 批量多大 + topK 多少"，不允许把失败包装成成功**（例如"内存不足跳过索引"必须如实显示未建索引，不得显示"已就绪"）。

**CI 与模拟器**：沿用该 Kit 不支持模拟器的约束，按 5.6.3 实际能力走纯 `relationalStore` FTS，中文有效性不足时显式 LIKE 降级，不崩溃、不把 API 返回“支持”当实际通过。兜底是机制而非中文检索质量结论。

**本矩阵之外、但同样必须如实标注的四类状态**（不得合并成一句"完成"）：

| 类别 | 状态取值 | 依据 |
|---|---|---|
| 端云同步 | 本机未同步（未登录 / 未开云空间开关）/ 同步中 / 已同步 / 同步失败 | 见 5.16；「已同步」不代表「本机索引已就绪」 |
| 内容管理 | 已导入 / 索引中 / 已就绪 / 已归档 / 删除中 / 删除失败 | 见 4.2、5.17 |
| 多模态输入 | 录音中 / 识别中 / 识别成功（标注来源）/ 识别失败 / 未识别到文字 | 见 5.15.2；识别结果不得当作未经确认的用户原话 |
| 内容处理/图片增强 | 待授权/待联网、上传/云排队/转换/解析、下载/校验、部分可用/失败/暂停 | 原件已保存不等于索引就绪；缺必需结构不标完整，见 4.2 |

#### 5.13.3 多格式资源与外部用量预算（实施前标定）

下面是必须冻结的参数清单，**本轮没有压测，不编造 App 实测上限**。启用某格式前须使用非敏感固定样本在手机/平板标定并审阅，未配置预算不得开启真实资料处理；服务上限与 App 上限分别记录。

| 参数组 | 必须确定的边界与超限行为 |
|---|---|
| 原件/批次 | 单文件/批量总字节、文件数、网络并发；按流式/分段能力验证，不将 200 MB 服务上限自动等同 App 可全量载入 |
| 文档结构 | 页/slide/sheet 数、行列/单元格/节点数量、表格/图像张数；缺失页数口径不猜，记录 Office 服务计量规则 |
| 图像 | 像素/尺寸/解码内存、缩放质量、每文档理解张数与重复图策略；缩放映射保留，预算不足标未完成 |
| ZIP/磁盘 | 包下载大小、成员数、压缩比/展开字节、临时及常驻磁盘预算、清理期限；不足先暂停，不在解包途中无界占满 |

| 外部请求 | 上传/下载/首字节/总时长、轮询间隔/退避/总窗口、重试次数、每日请求/页数预算；配额不足不无限重试 |
| 视觉与费用 | 图像/Token/请求额度、每文件/批次/日费用、用户确认阈值；免费额度/最高优先级不称费用保证 |
| 输出约束 | 描述、tag 数量/长度、受控类别与版本、允许 schema/资产类型；模型质量阈值与资源阈值分别标定 |

超限逐文件/阶段显式失败或暂停，已验证产物可保留；不无提示只处理前几页/几图然后显示完整。数据库 <2 MB 单行、512 文本块、API 200 页/200 MB、被排除的图像嵌入 <20 MB 是不同计量边界，不能互相替代。

### 5.14 跨线程与性能

- `ValuesBucket`（`Record<string, ValueType>`）**不支持 Sendable 跨线程传递**；如需跨线程用 `sendableRelationalStore.getSendableRow`；
- 大数据量查询官方建议单次 ≤ 5000 条、放 **TaskPool**、SQL 尽量简洁、分批执行；
- 索引是长任务：前台可感知、可中断、分批 + 事务提交，**不依赖后台长跑**（第三方应用不支持 `ServiceExtensionAbility`）；
- 向量路是**全表扫描**（5.3 决策），须在真机压测后确定语料规模上限（见第 6 节异常用例与第 8 节 D3 的复核条件）。
- 解包/结构校验/OCR/分块与网络处理不得以同步整文读写阻塞 UI；TaskPool 等跨线程使用具名可传递数据并遵循 SDK Sendable 约束，普通数据库桶不能任意跨线程；平台行为须后续查官方资料验证，不凭 Node/Python 库假定 ArkTS 兼容。
- 探针与用户库按数据库、目录、日志隔离；禁止进入用户页面即清库。日志只保留去敏阶段/错误/用量，标题、命中片段、原图、Token、签名地址不得公开输出。

### 5.15 提问多模态与图片知识源（D21）

**两条流程分开**：语音/图片取字提问产出可编辑文本；图片知识源保留图像及 OCR、视觉描述、tag/分类，文字查询可返回图片。二者都复用本机文本检索，不引入图像向量。当前端侧 OCR 与托管视觉实际能力仍待验证。

#### 5.15.1 两项能力

| 输入 | 能力 | 设备口径 | 说明 |
|---|---|---|---|
| 语音 | Core Speech Kit `speechRecognizer` | 手机 / 平板，**支持无网** | 官方 FAQ：手机/平板在无网状态下提供音频转文本；短语音 ≤ 60s、长语音 ≤ 8h |
| 图片取字 | Core Vision Kit 通用文字识别 | 手机 / 平板 | 把图片中的文字转为文本；图片经 `PhotoViewPicker` 选择，**不需额外权限** |

#### 5.15.2 提问识别链路与约束

```text
语音 / 图片 ──(speechRecognizer / OCR)──> 文本 ──> 用户可编辑确认 ──> 同一条 search(query)
```

- 识别结果**必须让用户可见、可编辑再发送**，并在界面标注该问题文本的来源（键盘 / 语音 / 图片取字），避免把识别结果当成用户原话；
- 识别失败或未识别出文字时明确提示原因并退回键盘输入，**不得用空文本发起检索**；
- 麦克风权限为 user_grant：仅在使用语音时按需申请，拒绝后其余功能照常（见 5.10）；
- 语音/提问 OCR 文本落库标原输入来源，兼容旧 `VOICE/IMAGE_OCR` 语义；**临时原音频/提问原图去留由用户选择**，默认不长期保留原音频。图片知识源按 5.15.3 必须保留原图，不用该临时策略删掉溯源资产；
- 本闭环只消费"已转成文本的结果"；长语音的录制、上传与摘要属 [00-项目总览](../docs/00-项目总览.md) 第 2 节 P1「长语音转写」闭环（见 1.4）。

#### 5.15.3 独立与内嵌图：OCR、视觉描述、tag、分类

```text
独立 jpg/png / 文档提取图 -> 原图/来源资产保存与定位
  -> OCR 文本与区域（端侧能力已验证时优先）
  -> ⑤独立授权 -> 托管视觉模型 -> 描述、tag、受控分类
  -> 运行时校验与质量标记 -> 用户可修正 -> 分来源文本代理索引
文字问题 -> 本机检索 -> 图片缩略图 + OCR/描述/标注来源 + 原生定位
```

- 图片理解端口与文档解析端口分离；MinerU `vlm` 用于页面解析，不据此认定用户标签/分类能力。视觉供应商/模型未定，须具备图片输入、可校验输出、同意范围、隐私/费用和质量证据，不本轮编造模型/接口。
- OCR 先独立报告有字/无字/失败，无字照片是正常输入，不丢弃原图。端侧 OCR 不可用/不充分时仅在已获对应外发同意下托管补充，记录接收方和方法；不以 OCR 抽取冒充视觉理解。
- 描述仅表达可见内容与必要不确定性；tag 是用于召回的关键词，分类输出应用受控类别 ID，类别表版本、允许集合在模型评测前明确，不确定用 `UNCLASSIFIED`。无法取得可信质量信息时不补造置信度；不推断未展示的身份/属性或图外事实。
- 自动结果与用户修正分栏保存；可编辑/删除描述、tag、分类，用户覆盖与删除记录独立于自动版本。重跑不覆盖修正、不复活已删 tag；对同图在不同文档的去重保留每个来源关系与标注归属。
- 索引 OCR、图注、视觉描述及自动/用户标注，严格关联 `assetId/documentId/locator` 与快照版本。tag/分类仅用于召回/过滤，不能独立形成事实引用；如果只命中 tag 就展示图片候选，不能当足够证据生成结论。
- 检索、过滤与生成上下文只消费应用用户覆盖/删除记录后的**生效值**；被覆盖或删除的自动结果仅保留用于溯源，不继续召回或注入回答。B 从快照重建也遵循该规则，不把自动历史与用户修正同时索引为当前内容。
- 命中显示缩略图及可打开的来源资产，正文内嵌图附父文档位置；裁剪图明确类型，缺原始嵌图不能冒充保真提取。AI 描述标“AI 识别描述，可能有误”，OCR 标识别来源；用户可核对原图。
- 缺少有效图像理解快照且无网络/未开⑤时保留原件与已有 OCR，标待联网/待授权或增强未完成；**已有完整、已校验快照不因断网或⑤关闭被降为未完成**。主文档可查但部分图失败时明确缺口，不能标全图完成。
- 图像理解结果可按③共享；已有快照离线消费不需⑤，同步仅不能授权本机再次向⑤外发。①默认不发原图，回答模型看图不在本期扩展中（见 5.8）。

#### 5.15.4 图像向量（本期不做）：将来的增量路径

本期允许文本代理“文字查图”，但不做图像向量/跨模态 embedding、以图搜图/图搜文。将来立项时须重新确认目标设备/云服务，而不是仅因端侧 API 不可用宣布图像内容完全不能检索：

| 事项 | 结论 |
|---|---|
| 架构 | 保留端口/适配器边界，但须新增多模态载荷、能力状态与失败/同意契约，不能只加布尔能力位 |
| 嵌入来源 | 重新评测端/云图像嵌入；云路径须授权、费用与联网边界，已生成向量是否离线可查另行定义 |
| DDL | 共享字段依已部署列只能新增规则迁移，本地索引按新空间重建；本期实际节点/资产类型不能因未来向量非目标省略 |
| 索引 | 图像与文本需在同一嵌入空间才有意义（官方多模态嵌入模型即为此设计）；换空间必须重算，不得静默混用（见 5.4.3） |

### 5.16 跨设备同步（端云，本期范围）

**本期采用端云同步**：`relationalStore` 分布式表 + `DISTRIBUTED_CLOUD`；满足 5.16.1 条件且用户开启③后，联网时在用户本人的华为云空间与同账号设备间最终一致。登录本身不构成外发同意，关闭③须停止后续同步外发；对应系统/App 开关约束在部署验证时核对，不承诺已撤回云端副本。**不采用端端同步**。

#### 5.16.1 前置条件与限制（官方口径）

| 项 | 要求 |
|---|---|
| 开发侧 | 实名认证的开发者账号 + 在 **AGC 创建项目和应用**，云侧创建容器、配置数据类型与同步字段；**无需自建服务器、数据库、存储与带宽** |
| 用户侧 | 设备登录**同一华为账号**，并在「设置-云空间」**打开同步开关**，云空间存储空间充足 |
| 系统与地域 | **仅中国大陆**；设备系统 ≥ HarmonyOS 6.1.0、云空间 ≥ 6.3.0；支持手机、平板、2in1/PC |
| 数据库 | 安全级 **S4 不能上云**（本项目 `S3`，可以）；主键必须全局唯一（**禁用自增**，本项目用 TEXT 稳定 ID） |
| 表结构 | **列只能新增，不能修改和删除**；云侧数据类型/字段**部署到生产环境后不允许删改**（开发环境不受限） |
| 限流 | 同步触发频率过高会被云端限流；官方建议**只对"用户操作触发变更"的离散数据项**启用，不推荐后台定时任务或变更频繁的场景 |
| 互斥（不可逆） | **同一张表不能同时配置为端端分布式表和端云分布式表，且不支持切换**；每个应用最多同时打开 16 个关系型分布式数据库，单库最多注册 8 个变更订阅回调 |
| 删除感知 | 需 `autoCleanDirtyData = false`，否则感知不到云端删除；另一方用 `predicates.greaterThan(Field.CURSOR_FIELD, lastCursor)` 查变更，再 `cleanDirtyData` 清理本地 |

#### 5.16.2 同步范围与接口

- **共享原件、规范化内容/提取图/识别快照和用户标注**，仅发布已完成校验的离散版本，不同步每次处理中间块。同步表/资产列须显式部署，最终新增表/列与版本发布协议待评审（5.6.4）；
- `kb_doc_state/kb_chunk/kb_chunk_fts/kb_meta`、任务/缓存/归档偏好、向量与凭据不进同步。A 已索引不代表 B 已索引，云解析任务也不能靠同步任务 ID转给 B 继续；
- 四稿 `setDistributedTables(['kb_document'], DISTRIBUTED_CLOUD, ...)` 仅为文本基线注册示意；扩展后注册经评审的共享表集合，继续使用现有 `cloudSync`/变更订阅/网络策略，不本轮创造平台 API 或修改云部署；
- 冲突：修改冲突以 **`SYNC_MODE_TIME_FIRST`（修改时间较近的一端为准）** 解决，因此 `updated_at` 必须可靠；用户可见的"我删了它它又回来了"要有明确解释与可重试操作；
- **同步状态必须如实呈现**（见 3.2）：未登录 / 未开开关 / 同步中 / 同步失败 / 已同步，且不得把"已同步"显示成"本机索引已就绪"。
- 规范化快照不可变、绑定原件版本及 manifest 哈希；多端同时重处理产生不同快照时保留各自身份，经冲突策略确定活动版本，不按相同版本号合并内容。用户标注独立版本/修改时间；自动重跑不覆盖用户修正，跨端编辑冲突按明确时间优先策略显示生效项及冲突说明，不能静默当模型覆盖。
- 资产集合不是原子到达：B 检查 manifest 中全部必需资产已下载、哈希/结构/定位对应后才可发布本机可用快照；未下载或校验失败显示待下载/失败，禁止只有列表即显示完整。
- **关键验收**：A 同步完整快照后，B 下载完成，关闭④/⑤并断网，也能从快照重建关键词索引、看原图与引用。B 缺内容时等待下载，不自动把原件上传。升级模型只标可重处理，用户另行授权才外发；单纯重索引不需重新解析。

#### 5.16.3 为什么选端云而不是端端

| 维度 | 端云（本期采用） | 端端（不采用） |
|---|---|---|
| 可用条件 | 满足 5.16.1 且开启③；离线可写，联网时同步并最终一致，登录不等于授权 | 两台设备需同时在线且同组网，仅最终一致性 |
| 权限 | 无额外用户授权权限 | 需要 `ohos.permission.DISTRIBUTED_DATASYNC`（**user_grant，首启弹窗**） |
| 存储模型 | 数据写本地表并同步到云 | 默认「多设备协同表模式」把对端数据放在按 `deviceId` 命名的独立表，**且不允许修改对端同步来的数据**；API 23+ 的「单版本表模式」需 schema 文件并支持修改 |
| 设备范围 | 手机、平板、2in1/PC | 组网内设备 |
| 其他 | 项目不需要自建服务器；数据仍在用户自己的云空间 | 无需云，但用户体验与可测性都更差 |

#### 5.16.4 应用自己要负责的部分

端云同步只搬运同步表的数据，以下必须应用实现：

1. **本机索引的建立与回收**：另一端新增/修改后按需重建，另一端删除后通过**启动对账**回收孤儿块（见 4.2、5.17）；
2. **资产文件删除**：官方明确"删除资产相关数据时，端云同步不主动删除本地资产文件，需要应用自行管理"；
3. **悬空引用**：按 4.4 的失效策略展示快照与标注；
4. **失败降级**：同步不可用时本地功能照常可用，不得阻塞导入、检索与删除。
5. **共享资产一致性**：校验原件、manifest、结构/图像/识别快照版本和用户修正，报告缺失资产；回收孤儿快照与缓存时不能误删其他活动文档引用的共享字节。

### 5.17 删除与清理（内容管理）

目标支持以下内容管理操作，当前探针不等于已实现用户生命周期（云侧冻结的是列定义，与数据行无关）：

| 操作 | 语义 | 索引处理 |
|---|---|---|
| 重命名 | 改 `title`，同步传播 | 不影响索引 |
| 归档 | 独立本机归档标记，不覆盖处理/索引状态 | 保留活动块与向量，默认排除、可显式包含 |
| 恢复归档 | 只撤销归档标记，按实际就绪/部分可用/失败/暂停状态展示 | 已验证块仍在则无需重建，未处理内容不能因恢复而显示就绪 |
| 修改图片标注 | 用户修正/删除描述、tag、分类，独立于自动版本 | 更新受影响文本代理/过滤，保持原图定位，③可共享 |
| 重新索引 | 从已验证活动快照重建 | 不自动上传/重新解析，旧已发布索引保留至新版本校验通过 |
| 重新解析/理解 | 用户明确授权④/⑤，保留新的处理版本 | 原字节哈希不替代策略版本，成功后再切换快照/索引，不覆盖用户修正 |
| 删除单篇 / 批量 | 物理删除文档与所属内容记录，二次确认 | 优先同事务级联；环境需分提交时先屏蔽、登记清理并可恢复，不伪称全操作原子 |
| 清空知识库 | 批量物理删除（逐行删，**不删库重建**） | 逐文档级联；便于保留库结构与同步配置 |

删除的执行顺序（必须保持）：

1. 停目标文档本地处理/索引与新外发，隔离迟到结果；远端可能继续，不宣称已取消。任务结果发布时重新校验文档存在性/原件版本；
2. 事务中删除文档、所属规范化/图像/标注记录、活动块/向量，并按已验证 FTS 协议删除索引。若特定环境需 FTS 分提交，同事务登记不含资料正文的待清理任务，检索过滤以现存文档/活动版本为准，随后独立清 FTS、记录清理结果，恢复重试；
3. 逻辑删除提交后清沙箱原件、规范化/识别资产、提取图、临时包与缓存；共享字节须确认无其他活跃引用。文件不可回滚，失败记待清理并重试，不因此回滚文档删除；
4. 处理历史回答引用：按 4.4 保留快照并标注失效；
5. 同步：删除随端云同步传播；**对端不保证立即感知**，故本机与他机都要在对账时回收孤儿块。
6. 服务侧数据清理独立报告；取消/删除能力与保留规则未核验时显示未确认，不以本机删除成功冒称云端已删除。历史文本/定位快照保留须在确认中说明，完整原图不为历史引用暗中保留。

**对账**：启动、收到共享变更和恢复任务时，以现存文档/活动快照/已发布索引与资产 manifest 为准清孤儿/过期块、FTS、资产和临时文件，继续待清理任务。`PARTIAL` 已验证块可查、重建中的旧活动索引可查；不能仅依一个处理状态删掉它们。归档默认排除，删除必排除，残留 FTS 或迟到结果都不能复活文档。模拟器的分提交现象与真机事务协议分别取证（5.6.2、5.6.3）。

## 6. 验收方式

按 [00-项目总览](../docs/00-项目总览.md) 第 5 节覆盖四类路径。**全部用例在真机（手机和平板各一台）执行**，记录：设备型号、系统版本、API Level、应用版本、提交 SHA。

> 沿用 Data Augmentation Kit 不支持模拟器的约束，模拟器结论不可替代真机结论；构建、host、模拟器、真机与托管服务评测分开记录。模拟器检索按实测能力走 FTS/LIKE 显式降级，不以不崩溃证明语义或复杂解析质量。本轮只有文档更新，不执行上述验证。

**阶段划分（不得混报）**：

| 阶段 | 范围 | 环境 | 可下的结论 |
|---|---|---|---|
| **S1 机制验证（当前探针阶段）** | 固定文本→文档→分块→索引；问题→命中片段；DDL/能力探测与降级 | 既有模拟器记录 | 只证明特定环境机制，不代表真实文件导入、语义质量或八格式支持 |
| S2 质量与预算 | 评测集上的证据覆盖率、答案支持率、延迟、内存、耗电 | 真机（手机 + 平板） | 质量与资源结论 |
| S3 在线增强 | L1 生成、两段校验、引用失效、同步（端云） | 真机 + 账号 + Key | 生成与同步结论 |

S1 的实测结论必须写回 §5.6.2 与 §7.1，并注明**设备型号 + 系统版本 + 能力探测结果**，否则不作为结论。

### 6.1 评测集与指标口径

#### 6.1.1 评测集构成

评测集是第 6 节全部质量指标的**唯一裁判依据**，必须先建后测，不得事后挑选样例。

| 项 | 要求 |
|---|---|
| 语料 | 真实、已获许可且去敏的八格式资料；文本基线沿用 `.md/.txt`，新格式/图像金标准按 6.2 增补，未建立不宣称已测 |
| 规模 | 起步 **20–50 题**；语料建议 ≥ 20 篇 / ≥ 500 块（覆盖 5.4 的 512 字符分块边界） |
| 题型分布（四类 + 四特例） | ① 资料中**明确存在**；② 资料中**不存在**（测"无答案"）；③ **同义表述**（测语义路）；④ **多版本文档**（测时效）；特例：**否定条件**、**时间/范围限定**、**超长问题**（测 D8 截断）、**已删除文档** |
| 每题必备字段 | 题号/问题、期望命中文档/资产或应无答案、金标准原文/表格/图像与定位、证据类型/版本、期望引用、是否截断；tag 命中与事实证据分开 |
| 版本与来源 | 评测集文件随代码入库（`entry/src/test/eval/`），记录语料 SHA 与题集版本；语料变化即视为新版本，不得跨版本对比 |

#### 6.1.2 指标口径（三层，不得混报）

| 层 | 指标 | 口径（分子 / 分母） | 判定方式 |
|---|---|---|---|
| **L-检索** | 证据召回率 | 命中集合包含金标准证据片段的题数 / 总题数 | **需人工或金标准比对**（本稿 D3 修正后要求"不只是耗时"） |
| | Recall@k（k=5） | 金标准证据出现在前 k 条的比例 | 金标准比对 |
| | 无答案判断准确率 | 应无答案题中正确区分“无召回/证据不足”并不编造答案的题数 / 应无答案题数（标定目标 100%）；不绑定同一句提示 | 自动（召回/调用行为）+ 人工（证据不足/答案）复核 |
| | 条件满足率 | 带时间/范围/否定条件的题中，命中结果满足条件的比例 | 自动（条件可结构化时）+ 人工 |
| **L-生成（S3）** | 引用合法性 | 引用编号全部落在本次命中集合内（越界数必须为 **0**） | **全自动** |
| | 答案支持率 | 人工判定"引用片段确实支撑该断言"的断言数 / 总断言数（≥95% 为标定后目标） | **仅人工**（D18 明确不可自动判定） |
| | 时效正确率 | 多版本题目中未采用过时版本的比例 | 人工 |
| **L-资源** | 检索延迟 | p50 / p95（本地检索，单独记录预热与冷启动） | 应用内埋点（业务 ID + 起止时间） |
| | 索引吞吐 | 块/秒、单篇耗时；分 1k / 1w / 5w 块三档 | 埋点 |
| | 内存峰值 | 索引与检索期间的进程内存增量 | 真机系统级观测（手段按官方文档确认，不预设工具） |
| | 耗电 | 相同任务下的设备耗电（前台、充电/不充电分组） | 真机系统级观测 |

#### 6.1.3 对照实验设计（单变量）

必须至少完成以下四组对照，且**每次只改一个变量**，否则结论不可归因：

| 异常 | 删除后迟到结果；分提交/文件清理中强杀 | 不复活文档、不再命中；对账继续清理，远端残留另说明 |
| 异常 | B 仅有列表/缺资产，多端快照或标注冲突 | 待下载/失败，不显示完整；按 manifest/版本发布，用户修正不被自动覆盖 |
| 权限拒绝 | 选择器取消，拒绝④或⑤，关闭③，断网或无 Token | 无未授权外发；原件/已有快照仍可用，分别说明待处理，不隐式启用其他开关 |
| 权限拒绝 | 允许④不允许⑤、同步来自 A 的图片在 B 未允许⑤ | 可消费已处理内容，不把图发给未获同意接收方；已上传数据去留不作撤回保证 |
| 权限拒绝 | 既有麦克风拒绝/未开云空间 | 键盘/其他本机功能正常，真实标本机/未同步，不谎称已授权 |
| 模型失败 | Token/视觉 Key 过期、鉴权/服务不可用、空/畸形 JSON | 阶段失败/部分可用，预算内重试，不能假数据填齐 schema |
| 模型失败 | 无依据图片描述/tag、错误分类、未报告版本/质量 | 来源/不确定性可见，用户可纠正；结构校验不宣称内容核实，质量纳入金标准 |
| 模型失败 | 只有 tag 召回，或编号合法但答案不受 OCR/图像/表格支持 | tag 只展示候选，不作单独事实证据；支持性人工评测/用户核对，不称系统已自动拦截全部误答 |

## 7. 已知限制与未覆盖项

### 7.1 平台限制与待复核口径

- 本闭环**不依赖任何 PC/2in1 专属能力**（见 1.2 的排除清单）；
- Data Augmentation Kit **不支持模拟器**、**仅支持中国境内**（港澳台除外）→ CI 依赖降级路径；
- **端侧文本嵌入的设备可用性：本机文档库与官网当前版本口径不一致，且本机未取证，不得下结论**（本稿修正）：
  - 本机 `devecocli docs` 的《应用数据向量化 (ArkTS)》仍写「当前**仅支持在 2in1 设备上使用**」；
  - 外部初审（2026-10-01）引用官网更新版（页面更新 2026-09-23）称 **API 26 起 Phone/Tablet 文本模型可用，但仅 Kirin 9010s 及以上**，且"生成的向量仅在本设备有效、不可用于跨设备检索"；
  - 因此**撤回旧稿"不存在芯片型号门槛"的断言**——该断言建立在"对当时本机文档库全量扫描零命中"之上，不能用来否定官网新版本中的限制；本机文档库是否已更新、以哪个口径为准，须按 D16 重新核对；
  - 结论不变：**探测只依据运行时结果，不硬编码型号**；设备支持只有真机探测才算数；
- **模型准备与推理是两件事**：官方手机/平板步骤使用 `getSupportedCloudModel` / `modelInfo` 与下载网络策略（`NetworkPolicy`，默认 `WIFI_ONLY`）。**首次使用、未准备模型、缓存失效或重启后的行为均未取证**，不得承诺"断网即可语义检索"；离线基线始终是关键词层；
- **`StoreConfig.vector = true` 是启用向量数据库能力的开关**（不是可忽略的装饰位）；`isVectorSupported() = false` 时的库配置尚无方案（列入 5.6.2 第 10 项）；
- `retrieval` **不支持数据库备份与恢复**（`1021200001`），损坏只能重建；
- `relationalStore` 单条 **< 2 MB**、**单写连接**、**最多 4 个事务对象**、WAL 上限 **512 MB**；
- 向量索引命中条件严格（`ORDER BY` + `LIMIT`、单一排序条件、**不可带 `DESC`**、度量须与索引一致）；
- 中文分词「**不支持中文单字检索**」（ICU 与自研分词器均基于词条）；
- `floatvector(N)` 的 N 上限官方未给；AIP 嵌入的向量维度官方未公布 → 维度运行时读取；**N 在建表时固定**，不同维度不能共用一个向量列（见 5.4.3）；
- **检索查询词有两个不同单位的上限**：开发指南 512 字符、API 参考 1000 字节，须同时满足（见 5.2、D8）；
- 免安装 HAP 体积上限 10 M；第三方应用不支持 `ServiceExtensionAbility`；
- 知识加工表**不支持端端/端云同步与搜索**；
- **端云同步**（见 5.16）受以下限制：仅中国大陆；系统 ≥ HarmonyOS 6.1.0、云空间 ≥ 6.3.0；需用户登录华为账号并自行打开「设置-云空间」同步开关；**依赖云侧环境部署**（AGC 项目与应用、实名认证）；同步列**只能新增不能删改**（云侧数据类型部署到生产环境后同样不能删改）；高频变更会被云端限流；**同一张表不能同时配端端与端云且不支持切换**；单库最多 8 个变更订阅回调、单进程最多 16 个分布式库；`autoCleanDirtyData` 需为 `false` 才能感知云端删除；**资产文件需放分布式文件路径，且删除时同步不代删**；
- **多模态输入**：语音识别对无网长语音、识别准确率与领域词有自然限制；OCR 对模糊、倾斜、手写与复杂版式图片可能无结果，均需按 5.15.2 明确提示；语音需要麦克风 user_grant 权限；
- **赛事适配尚未确认**：[02-平台基线](../docs/02-平台基线.md) 已提示不能因 SDK 中存在 `openharmony` 目录就认定符合 OpenHarmony 赛事要求。本闭环依赖 `SystemCapability.DataAugmentation.Retrieval`、`SystemCapability.DistributedDataManager.DataIntelligence.Core`、`SystemCapability.DistributedDataManager.RelationalStore.Core` 以及端云同步；这些能力在赛事允许的系统与 Kit 范围内是否可用，**须在开工前单独确认**（见 D16）。

### 7.2 非目标与未实施边界

- 端侧 LLM 生成（不承诺）；
- 图像/跨模态向量检索、以图搜图/图搜文；OCR/描述/tag 文本代理查图属于目标（见 5.15.3、5.15.4）；

- HTML、旧 Office、宏文件等八格式之外解析；PDF 与 docx/xlsx/pptx 已纳入目标但尚未实施，D2 范围已被 D19 替代；

- 知识库加密（`encrypt` 首版为 false，如需加密须走 `rekey` 且单独评审）。

### 7.3 服务、实现与共享快照缺口

- 当前实际输入/分块/命中仍是纯文本 S1；真实选择器、规范化、原生 locator、图片理解、回答/历史引用、内容同步和完整生命周期未接入，探针自动清库与公开片段日志不适用于个人资料。

- 新共享快照/图像/标注改变旧 D12/D17，尚未部署共享表/资产布局；B 无重新上传离线建库必须实际双设备验证，不能以列表一致替代。
- App 页/图/结构/展开/内存/磁盘/时间/费用预算均待 5.13.3 标定；不能把服务 200 MB/200 页上限或平台 <2 MB 行限制当 App 验收规模。
- 本轮不统一改写其他文档，平台基线/索引中的旧范围与进度需另批对齐。历史模拟器事务/LIKE 现象不推广为真机结论，现代码最终索引状态与历史记录差异也未修复。
