# 02 个人知识库问答

> 状态：已实现待验收。本文描述当前手机、平板共用的知识库实现与剩余范围。
> 关联：[L0 契约](12-统一知识库L0关键词检索与FTS5接入.md)、[主对话 L2](11-主对话Agent知识库L2检索增强.md)、[链路架构](../docs/architecture/知识库L0-L1-L2链路架构.md)。

## 1. 目标与范围

用户导入个人资料，在本机查找正文、OCR 和图片描述，按需进行语义检索，并在授权后让助手依据资料回答。来源绑定到文件、内容版本与证据位置，可返回正文或原图核对。

| 类型 | 当前处理方式 | 边界 |
|---|---|---|
| TXT / Markdown | 本机读取、规范化、结构分块与索引 | 不需要云解析授权 |
| PDF | 保存原件，经 MinerU 托管解析后消费规范化内容；PDF.js + ArkWeb 展示原件 | 原件上传逐份确认；原件预览与结构解析分别记录状态 |
| DOCX | 消费解析结果、恢复正文和内嵌图片，提供来源预览 | 特殊对象、原生位置与版式完整性按结果实际覆盖展示 |
| JPG / PNG / WebP 图片 | 原图保存、文字提取与图片描述/标签分阶段处理 | OCR、图片理解与语义索引分别显示状态 |
| PPTX / XLSX | 属于后续支持目标 | 当前不声明已完成导入、定位与问答验收 |

资料管理、检索、图片理解、向量化和模型回答各有独立状态。跨设备同步、端侧生成模型、图像向量及跨模态向量检索尚未实现；这些目标保留在项目范围中，当前页面不承诺可用。

## 2. 用户流程

1. 进入知识库 → 我的资料，按文件名、分类或排序找到资料，也可通过系统选择器导入。取消选择不保存或外发文件。
2. 保存原件及其身份。TXT/MD 本机处理；PDF、DOCX 和图片按当前解析能力及用户授权继续处理。未授权或服务不可用时保留原件与已完成内容。
3. 查看云解析、本机内容发布、正文可检索化、图片描述与标签、图片可检索化各阶段进度。部分失败显示具体阶段，已完成内容继续可用。
4. 在知识库页面进行 L0 关键词检索；需要语义查找时按当前嵌入配置确认查询外发，再进行 L1。结果显示真实通道、覆盖情况与来源。
5. 在主助手中开启知识库授权，允许命中片段发送给回答模型，并选择是否允许语义查询。模型按问题自主调用 `knowledge_search`，在同一工具循环中回答。
6. 点击来源核对文件内容。改版、归档或删除导致原版本不可用时明确提示，历史来源展示不授予文件访问权。
7. 可查看图片、修正描述与标签、归档、恢复、删除及重试未完成处理。重新索引复用已有内容，重新解析或模型调用遵守各自授权。

## 3. 页面事项

- 资料库显示当前文件状态，支持分页、分类、筛选与归档视图。详情正文分页、图片每页 9 张，并提供全屏查看。
- 处理状态采用固定高度容器：折叠预览最多 3 个未完成项，展开每页 5 项。单项与批量重试保留费用确认，详见 [界面契约](05-知识库界面易用性与预览重构.md)。
- 正文、OCR、AI 描述、用户修正与标签区分来源；标签用于召回与过滤，不独立作为事实依据。
- 本机关键词结果、语义结果、无命中、覆盖不完整和服务失败分别展示。模型未调用、证据不足或输出校验失败时不展示成功回答。
- 主对话按文件合并来源卡片，保留引用编号与文件版本。知识库来源段后追加网页来源时，卡片仍显示，网页来源文本完整保留。
- 加载、取消、失败与恢复入口可见；长文、图片和任务列表使用有界分页，手机和平板沿用同一数据与授权规则。

## 4. 业务与 Agent 事项

### 4.1 内容与所有权

原件、规范化快照、块、图片 occurrence、标注及派生索引分别保存。文档使用稳定身份、active generation 和 epoch；任务及结果绑定相同版本，迟到结果不能发布到已换版、归档或删除的资料。

用户修正保留独立所有权，重试图片理解不覆盖修正。删除先提交逻辑状态并停止相关发布，物理文件释放失败单列待清理；本机删除不宣称已删除托管服务副本。

### 4.2 处理队列

`UnifiedProcessingQueue` 管理 BodyEmbedding、Vision、ImageEmbedding，使用已有设置、授权和任务账本执行。任务状态包括 Pending、AwaitingConfig、Running、Complete、Failed、Paused、Unknown、Canceled。结果未知的请求保留账本，显式接受可能重复费用后才重新排队。

批量重试仅作用于当前资料的当前 generation / epoch：逐项复用现有单项重试，保留成功进度；一项入队失败继续其他项并报告计数。等待中的任务通过现有调度启动，未就绪设置与暂停状态保持原样。

### 4.3 L0 / L1 / L2

| 层级 | 当前职责 | 约束 |
|---|---|---|
| L0 | 统一 `KnowledgeLexicalSearchPort`，使用 `klex_*` 派生 FTS 索引、候选原文核验及有界字面补充/降级 | 返回 Keyword / Literal、实际引擎、覆盖和续查信息；索引不可用时标明降级 |
| L1 | 问题向量化与本机合格空间 KNN | Provider、模型、维度、预处理、tokenizer、角色及版本等必须兼容；配置修订本身不抹除旧向量 |
| L2 | 主助手授权下自主调用 `knowledge_search`，将证据交回同一模型循环 | 每轮最多 2 次查询，累计去重最多 5 条 / 3200 字符；引用需绑定真实证据 |

页面和主对话共享知识库检索端口，查询会话分别持有取消与授权状态。搜索历史写入不改变资料成员修订；真实资料变更使旧查询授权失效。

普通对话记忆可持久化；知识库来源及其派生后续上下文仅在当前授权会话使用，不进入持久模型记忆与摘要。UI 可持久化来源展示快照，恢复不自动外发。

## 5. 平台能力与隐私

- 使用既有 ArkData、文件沙箱、系统选择器、PDF.js / ArkWeb 和服务适配器。当前实现不依赖 PC/2in1 专属的知识加工或端侧生成能力。
- 托管解析上传完整原件；图片理解上传被允许的图片及必要上下文；入库向量化上传块文本，L1 上传问题文本；L2 上传问题及命中片段。各项配置分别说明接收方、费用和外发范围。
- Key 由应用内 Key 管理与安全存储处理，不写入知识内容、来源快照、日志或文档。用户拒绝外发时保留本机已有内容与可用的 L0 检索。
- 取消、退后台和关闭遵循既有资源生命周期。PDF 预览持有受管租约，关闭、连续打开、Web 引擎失效和页面退出均清理旧会话。
- 不自动重建全部嵌入、不清空用户资料、不更改既有向量空间来伪造兼容；云服务失败按阶段保留真实状态。

## 6. 验收方式

| 路径 | 验收重点 |
|---|---|
| 正常 | 各支持格式导入、文字与图片检索、L0/L1/L2、来源回看、分页与归档恢复 |
| 异常 | 损坏文件、服务/下载失败、ZIP/结构不合法、索引中断、资料变更、删除与迟到结果 |
| 权限或授权拒绝 | 取消选择、拒绝原件/图片/查询/片段外发、Key 缺失和服务鉴权失败；不产生越权请求 |
| 模型失败 | 超时、空响应、无依据、非法引用、未知结果、重试与重复费用提示；成功进度保留 |

质量验收分别记录分块、召回、生成与来源定位；合成 host 用例、构建、模拟器和真机结果各自留档。命令及日志规则见 [协作约定](../docs/01-协作与工程约定.md)。

## 7. 当前限制

真实设备 FTS/tokenizer、旧资料冷启动质量与性能、跨页检索质量、异常恢复、最大字体/读屏、供应商实际账单和 OpenHarmony 真机仍需独立验收。大型知识库首次打开曾出现较长等待，见 [多设备验收记录](../docs/verification/平板端适配与手机对照验收记录.md)。

PPTX/XLSX、跨设备同步、批量内容管理的完整目标以及端侧能力扩展按单独任务实施；已实现范围与产品目标分别维护，不据局部成功扩大支持声明。
