## 1. 目标与范围

- 目标：用户在应用其他页面浏览时，一次点击即可返回当前助手对话。
- 范围：工作台、工作台内的演示日程、知识库、我的页面。
- 本轮扩展：入口拖动、左右吸边、边界限制、窗口尺寸变化时重新定位；按开发者要求不提供重置位置按钮。
- 非目标：系统级悬浮窗、跨应用唤起、位置或偏好持久化、自动半隐藏、长按语音、独立聊天弹窗、会话持久化、自动发送当前页面内容。

## 2. 用户流程

1. 用户从左侧菜单进入工作台、知识库或我的页面，显示角色头像按钮；首次运行默认在右下角，调整后按本次运行保存的位置显示。
2. 在工作台打开演示日程列表后，按钮仍然显示。
3. 点击按钮直接回到助手，继续查看原消息、未发送文字、待确认草稿或操作结果。
4. 回到助手后按钮隐藏，不创建新对话，不填入样例、不自动发送或确认。
5. 打开导航菜单或演示场景设置时隐藏按钮；关闭后按当前页面恢复显示。原生提示对话框按已有模态行为阻止操作底层页面。
6. 用户在「我的 → 悬浮助手入口」关闭开关，各页面的悬浮按钮立即隐藏。左上角菜单仍可进入助手；重新开启后恢复入口。
7. 开关仅在本次页面实例中记忆，切换页面、新建对话不重置；应用重启后恢复开启。按开发者 2026-10-10 的要求，设置行只显示名称和开关，不再显示解释文字；此限制保留在文档及读屏说明中。
8. 在头像上单指移动达到 8 vp 后进入拖动，松手后吸附最近的左右边缘，不触发进入助手。未形成拖动时仍按原生按钮点击处理。
9. 拖动后切换页面、关闭再开启入口，保持同一吸附侧和纵向位置比例；应用重启后恢复默认右下角。

## 3. 页面事项

- 在 `Index.ets` 的页面层统一放置入口，不在各功能页复制会话状态。
- 默认位于应用内容区域右下角，距右侧和底部各 20 vp；按钮 60 × 60 vp、头像 48 vp。松手后左右边距为 20 vp，纵向限制在实际导航栏底部以下 12 vp 至内容区域底部以上 20 vp。
- `Stack.onAreaChange` 测量应用内容区域，导航栏单独测量高度，不采用屏幕绝对尺寸。仅在可用空间能完整容纳入口时显示；空间不足时隐藏入口，仍可使用菜单，空间恢复后恢复原吸附侧和高度比例。
- 吸边使用 180 ms 的 `UIContext.animateTo` 缓出动画；拖动跟随手指，取消拖动回到上次已保存位置。窗口大小或导航高度变化时中止拖动并重新定位，忽略旧手势的迟到更新。
- 不放置固定高度文字标签；按钮名称为「回到助手」，操作说明为「返回当前对话，保留已输入内容、消息和待确认草稿。可拖动调整位置。」头像为装饰内容。
- 开关开启时，非助手页的滚动内容额外预留 100 vp 底部空间，最后一项可滚动到按钮上方完整查看和点击。按钮不跟随内容滚动；关闭开关后移除额外留白。这不保证中途滚动时没有遮挡。
- 设置使用原生 `ToggleType.Switch`，以单行呈现名称与开关，不显示额外解释文字；上下内边距各 6 vp。开关视觉尺寸为 60 × 32 vp，居中放在 60 × 48 vp 容器内，`responseRegion` 上下各扩展 8 vp，保留 60 × 48 vp 触控区域及无障碍名称、操作说明。标题可随大字体换行，无固定行高度；标题不与开关重复朗读，开关状态交给原生控件表达。
- 助手页和场景设置页不增加该底部空间；菜单开启时保持原内容尺寸，避免滚动区域跳变。
- 不承诺恢复原聊天滚动位置；沿用现有页面切换的滚动规则。

## 4. 业务与 Agent 事项

- 点击复用 `changeTab(0)`，不调用 `newConversation()`、`resetConversation()`、生成或确认操作。
- `messages`、`input`、`draft`、`result`、`records` 与操作 ID 继续由同一个 `Index` 实例维护，没有第二份状态或公共契约变更。
- 沿用原行为：生成过程中离开助手会取消生成并忽略迟到回复；已生成的草稿保留。已经提交的模拟执行可继续完成，返回后展示原操作状态。
- 返回助手后清除演示日程子页和场景面板的导航状态；下一次进入工作台从工作台首页开始。
- `floatingAssistantEnabled` 由 `Index` 单独维护，`ProfilePageOptions` 扩展内部页面参数并通过回调更新，不改变服务公共契约。开关不清除消息、草稿或操作结果，不调用取消、生成或确认。
- `FloatingAssistantPlacement` 保存页面实例内的吸附侧、纵向比例、拖动起点及边界；由 `Index` 的 `@State` 持有，入口隐藏时不重建。坐标计算不引用 ArkUI 或 Mock 服务。

## 5. 平台能力与权限

- 仅使用 ArkUI 布局、按钮、原生 Toggle、无障碍属性和 `BrandAvatar`，不新增权限、依赖、网络或存储。`Toggle.onChange`、`selectedColor` 和 `accessibilityDescription` 签名已对照本机 API 26 SDK 的 `component/toggle.d.ts`、`component/common.d.ts` 核对。
- 入口的输入为点击事件，输出为切换到助手；不向模型或平台传递当前页面数据。
- 点击无异步请求，不新增超时、重试或写入语义；反复返回不增加消息或日程记录。
- 演示数据只在当前页面实例中保留；进程重启后重置，不保证后台持续运行或恢复会话。
- 手势采用原生 Button 的 `onClick` 与优先 `PanGesture`，不使用并行手势或全屏透明触控层。依据：DevEco CLI 官方文档「绑定手势事件」（`API参考/ArkUI_方舟UI框架/ArkTS组件/手势处理/绑定手势/绑定手势事件/ts-gesture-settings`）及「绑定手势方法」（`开发指南/ArkUI_方舟UI框架/UI开发_ArkTS声明式开发范式/添加交互响应/添加手势响应/绑定手势方法/arkts-gesture-events-binding`）；接口与事件位移单位核对本机 API 26 `component/gesture.d.ts`。拖动与点击的实际竞争结果需设备验证。
