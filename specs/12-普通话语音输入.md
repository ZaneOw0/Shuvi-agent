# 12 普通话语音消息

状态：已实现待验收（2026-10-28）。范围：HarmonyOS 手机、平板及支持 Core Speech Kit 的模拟器。

## 1. 用户流程

1. 输入框为空时点击语音按钮，仅此时按需请求麦克风权限。
2. 录制普通话语音，停顿只分句，不结束录音；点击「结束」或达到 60 秒后停止，录音中点击「取消」丢弃本次未完成录音。
3. 结束后先将原始音频保存到应用私有目录，再完成后台识别；前端显示可试听、发送的语音草稿，并保留文字输入框用于补充说明；**不展示实时转写或转写文字回填**。
4. 用户手动发送后，聊天中同一条用户消息保留可播放的语音和用户手输的补充文字；后台将完整转写与补充文字以空行连接，作为一次请求交给现有助手理解。搜索和知识库中的问题/关键词展示位置使用「语音消息」标签，不显示转写内容。
5. 「已保存语音」可跨进程重启浏览、试听及确认删除。移除草稿、新建对话不删除已保存录音；取消已结束录音的识别不删除已经落盘的音频。

不包含 OpenHarmony 后端、超过 60 秒的音频转写、长录音摘要、语音播报或原始音频上传。技术上使用系统连续识别模式，产品输入时长仍限制在 60 秒。

## 2. 页面事项

- 复用输入区的语音图标和现有主题，显示录音状态、结束、取消、试听/停止、语音时长与发送入口。
- 录音与识别期间锁定输入及发送，避免并发录音与重复发送；开始录音前停止本应用试听。
- 语音气泡及无障碍文本只包含播放状态、时长，不包含转写；旁边或下方的文字只来自用户主动补充的输入。后台识别失败时录音仍可从本机录音列表播放，但不发送空内容。
- 沿用现有 500 字后台输入上限：按转写、分隔空行和补充文字的合计长度校验；超限不截断、不显示转写，不发送，保留两部分草稿并提示减少文字或分段录制。
- 返回、切换页签、页面隐藏、退后台和销毁时取消活动录音并释放播放资源。取消后的迟到结果不能进入新会话。
- 拒绝权限、无可保存音频、识别失败、保存失败及播放失败均有反馈；键盘输入不依赖语音能力。
- 删除录音需确认，只按受校验的本机录音标识删除，不接受消息携带的任意文件路径。

## 3. 业务与 Agent 事项

- `SpeechSession` 管理授权、启动、60 秒限时、5 秒结束等待、迟到回调及异步资源释放；重复取消共享释放操作。
- `HarmonySpeechPort` 使用 AudioCapturer 采集同一份原始 PCM：既保存原音，也以 640 字节 / 20 ms 节奏喂给本机 ASR；尾帧补零仅用于识别，不写入原音。
- `VoicePcmBuffer` 在内存中最多保留 1,920,000 字节（60 秒），录音回调不做磁盘 IO；原音文件在结束后原子保存。
- `VoiceArchive` 保存 WAV（PCM 16 kHz / 单声道 / 16 位）。路径为 `filesDir/voice_messages/<受校验的ID>.wav`，先写临时文件、同步、关闭再重命名；失败清理临时文件，不覆盖已有录音。
- 音频不随转写失败丢失；后台转写只在内存及原有助手调用链消费，不写入录音文件、文件名、元数据或日志。
- `VoicePlayback` 直接读取原始 PCM，通过 AudioRenderer 播放，结束或取消时释放；创建中离开不会迟到播放。
- 当前聊天消息仍沿用原工程的会话内生命周期；重启后通过「已保存语音」访问原音，历史录音不自动重新识别或发送。
- 发送语音前需启用真实助手；不将任意语音交给固定样例伪装为真实理解。不新增模型服务、密钥或依赖。

## 4. 平台能力与隐私

- `ohos.permission.MICROPHONE` 为按需用户授权，使用场景 `inuse`；用途说明包含录制、保存与本机识别。
- `@kit.CoreSpeechKit` / `SystemCapability.AI.SpeechRecognizer`；API26 中 **online=1 代表离线**，`language=zh-CN`、`recognizerMode=long`、`recognitionMode=1`、`maxAudioDuration=60000`。
- 初版使用短语音模式，停顿约 2 秒就自动结束；现已改为连续识别，停顿只用于分句，由结束按钮或 60 秒上限结束。
- 音频保存在应用私有目录，并将 `voice_messages/` 加入系统备份排除项；原始音频不外发。用户发送后，后台转写依照已启用助手/搜索/知识库的既有外发授权使用。
- Core Speech Kit 从 API20 支持模拟器；录音、播放依赖电脑音频设备。API26 编译或模拟器结果不能替代平板/真机验收。

## 9. 结束录音时的 1002200010 误报（2026-10-30，`feat/search-direct-tavily`，已实现待验收）

现象：模拟器上偶发「录音已保留，但后台识别失败（1002200010），本次未发送。」。系统日志显示，结束录音后识别服务报 610「write audio ignore with no preceding start listen」（对外为 1002200010「Write audio failed because the start listening is failed」），但几毫秒后照常返回识别结果和 onComplete；应用收到任何错误即判失败，丢掉了这次结果。同样流程的上一条录音正常。推测是最后一包音频与 finish 紧挨着发出，服务先处理了 finish，那一包被拒收。

| 位置 | 改动 |
|---|---|
| `HarmonySpeechPort.ets` | 已发出 finish 后收到 1002200010，不再立即判失败，等识别结果和 onComplete；最多等 `SpeechSession` 原有的 5 秒结束超时，超时仍按失败处理并保留录音。录音过程中收到同一错误仍立即失败。最后一包音频发出后再等 3 个送音周期（约 60 毫秒）才发 finish，录音器没在送音时仍立即发 finish |
| `run-speech-tests.cjs` | 新增 3 个用例：finish 后报该错误但有结果时照常完成、录音中报该错误仍失败、finish 后只报错没结果时按 5 秒超时失败；原「逐包送音」用例改为检查 finish 在最后一包之后等待 |

验证：语音 60/60；把 `HarmonySpeechPort.ets` 换回修改前版本时，新增和改写的用例中 3 个失败。只有 host 证据，模拟器上该问题偶发，未做重复录音统计。
