# specs 功能契约目录

> 状态：待确认。本骨架由基线准备阶段建立，具体功能 spec 按用户闭环逐个补充。

本目录存放按用户闭环划分的功能 spec，是 UX、Agent、平台三条线并行实现的唯一对齐点（见 [01-协作与工程约定](../docs/01-协作与工程约定.md) 第 1.2、2 节）。

## 命名与组织

- 文件名：`NN-功能名.md`，`NN` 为两位序号，例如 `01-创建日程并提醒.md`。
- 一个文件对应一个用户闭环，不按成员或模块拆分。
- 跨模块契约在该闭环 spec 中定义；通用契约稳定后再另行沉淀。

## 状态流转

每份 spec 头部带状态字段，按以下顺序流转（见 01 第 8 节）：

`待确认 → 已确认待实现 → 已实现待验收 → 已验收 → 已下线`

状态变化须附版本与证据；已下线的 spec 保留并注明替代文档。

## 内容要求

每份 spec 按固定顺序描述（见 01 第 2 节）：

`用户流程 → 页面事项 → 业务与 Agent 事项 → 平台能力 → 验收方式`

最小字段清单与四类验收路径见 [_模板.md](_模板.md)。
