## 2. 用户流程

1. 用户进入助手页，看见演示模式说明、空态引导和「试试创建日程」样例入口。
2. 点击样例，将「2026 年 10 月 20 日下午 3 点到 4 点开项目会，提前 10 分钟提醒我」填入输入框，由用户发送。样例固定使用 `Asia/Shanghai` 时区，日期不随系统时间变化。
3. 页面显示用户消息与生成中状态；Mock 返回标题「项目会」、起止时间和提醒设置。
4. 确认卡片完整展示日期、时间、时区及提前提醒分钟数，并说明尚未创建。用户可确认、取消，或返回输入重新描述。
5. 用户点击「确认（演示）」后进入执行中状态，禁用重复提交。完成后显示「已添加到演示日程；未写入系统日历，不会实际提醒」。
6. 用户点击「查看演示日程」，进入工作台的日程列表，看到同一条记录；再次确认同一操作不会新增记录。
7. 用户切回助手，保留本次会话。关闭或重启应用后演示数据重置，页面说明这一限制。

自由输入允许发送，但只有明确标注的固定样例产生日程卡片。其他文本返回「当前为演示版本，请使用样例体验创建日程」，不根据任意输入套用样例结果，不声称完成真实语义理解。

## 3. 页面事项

### 3.1 页面与入口

以下名称表示页面职责，不预先锁定路由 API 或组件文件结构。

| 页面 | 本次内容与交互 |
|---|---|
| 助手 | 消息列表、文字输入、发送、样例入口、日程卡片；图片和语音入口点击后说明待接入，不弹系统权限框 |
| 工作台 | 日历日程、文件管理、联网搜索、长语音转写、跨设备协同入口；日历进入演示列表，其他入口给出具体待接入说明 |
| 演示日程 | 展示本次会话确认过的日程及模拟执行状态；无记录时提供返回助手创建样例的入口；返回后仍在工作台 |
| 知识库 | 展示明确标注的样例文档；导入、检索及问答入口说明待接入，不把样例当作用户文件或真实检索结果 |
| 我的 | 登录、多设备管理、主题设置入口；本次仅展示入口及待接入说明，不显示虚构的已登录或已同步状态 |

AI 导航通过助手的功能引导呈现；智能体编排是后续执行能力，本次不创建虚构的智能体运行面板。

### 3.2 页面状态与反馈

- 空输入或全空白禁止发送；单次文本限制为 500 个字符，超出时保留内容并提示，禁止发送。
- 生成中显示进度并提供取消；同一会话一次只处理一个请求。
- 草稿待确认时禁止继续发送；用户先确认或取消。返回输入重新描述视为取消原草稿，并保留原文字供修改。
- 新对话入口使用方框铅笔图标：有会话或未发送文字时先确认清空；取消对话框保留内容。生成、执行和草稿待处理时禁用。新对话只清空会话与输入，保留本次页面实例中的演示日程。
- 输入区整合「日程样例」「搜索」、添加内容与语音按钮；非空输入时语音按钮替换为发送。搜索、图片、文件、语音均显示待接入说明，未增加真实能力。达到 400 字显示计数，超过 500 字保留文本并禁止发送。
- 侧栏展示当前入口、待处理草稿提示和演示日程数量；关闭按钮、遮罩与系统返回均可关闭侧栏。开启菜单本身不取消生成；切换离开助手才沿用取消生成规则。
- 执行中禁用确认与发送；本次模拟执行不提供取消，避免把请求取消误呈现为操作撤销。
- 失败保留输入或草稿并提供对应恢复操作；取消后迟到的 Mock 回复不得追加消息或改变结果。
- 切换一级页面保留会话；离开助手时取消尚在生成的请求，保留已生成草稿；执行中任务可完成，回到助手展示原操作结果。
- 日程创建、提醒注册分别展示状态；提醒注册失败时保留日程，并提供「重试提醒（演示）」。
- 输入框适应软键盘，列表可滚动；长标题、长文本和放大字体不遮挡确认、取消等主要操作。图标入口提供可读名称，状态不只依赖颜色区分。

### 3.3 初稿视觉约定

| 项目 | 初稿选择 |
|---|---|
| 配色 | 奶油白背景 `#FFFBF5`、莓紫主色 `#793B68`、深紫正文 `#342638`；淡紫输入面板与气泡，暖黄用于待确认提示；完整色板见品牌文档 |

## 4. 业务与 Agent 事项

### 4.1 前端 Mock 与后续接入边界

页面通过具备明确类型的前端服务读取样例、生成草稿、确认操作和重试提醒，固定数据与模拟延迟不写入页面组件。服务由 `entry` 装配；本次类型属于前端原型内部约定，不直接发布为核心模块的公共接口。

真实接入时由核心提供用例接口、Agent 产生候选动作，平台适配器执行系统能力。以下字段仅是对齐草案，需相关负责人确认后再落入公共代码；本 spec 不指定 Agent 身份、编排算法或模型供应商。

### 4.2 数据与接口草案

| 对象／操作 | 最小字段与行为 |
|---|---|
| 用户请求 | `requestId`、`conversationId`、`text`；生成请求和取消使用同一请求 ID |
| 日程草稿 | `draftId`、`requestId`、`title`、`startAt`、`endAt`、`timeZone`、`reminderMinutesBefore`；时间采用带时区偏移的 ISO 8601 字符串，提醒值为非负整数 |
| 生成草稿 | 输入用户请求；返回草稿、待澄清问题或失败结果；缺失或无效字段不得产生可确认卡片 |
| 确认草稿 | 输入 `draftId` 和稳定的 `operationId`；同一草稿确认及执行重试复用该操作 ID |
| 执行结果 | `operationId`、`draftId`、整体状态、日程状态、提醒状态及可选错误；演示记录使用独立 Mock ID，不冒充系统事件 ID |
| 重试提醒 | 输入原 `operationId`；只重试提醒，不重新创建日程 |
| 错误 | 错误阶段（生成／日程／提醒）、错误码、用户可读说明、是否可重试；页面不依赖供应商原始错误文本 |

示例草稿时间为 `2026-10-20T15:00:00+08:00` 至 `2026-10-20T16:00:00+08:00`，时区为 `Asia/Shanghai`，提前提醒值为 `10`。固定演示日期只用于复现原型，不作为真实系统创建过去日程的规则依据。

### 4.3 状态、校验与幂等

- 状态区分待澄清、待确认、执行中、成功、部分成功、失败和取消；草稿生成成功不等于执行成功。
- 确认前检查标题非空、起止时间有效且结束晚于开始、提醒值为非负整数。确认后的草稿不可原地修改。
- Mock 服务按 `operationId` 保存结果，重复调用返回已有结果；只禁用按钮不能代替幂等检查。
- 日程失败时不执行提醒；日程成功而提醒失败时为部分成功。提醒重试成功后更新原记录。
- 待澄清、失败或取消状态不能创建日程；过期请求的回调按请求 ID 丢弃。

## 5. 平台能力与权限

- 本次仅使用 ArkUI 和应用进程内存。消息、草稿、演示日程不持久化、不外发，也不访问设备个人数据。
- 权限拒绝为 Mock 场景，不读取或改变实际权限，不调用系统授权弹窗。
- 生成和执行默认模拟延迟约 800 毫秒；10 秒未完成视为超时。取消与超时后忽略迟到结果，不自动重试。
- 生成失败可由用户显式重试；执行失败保留原操作 ID。执行超时的模拟场景明确设为无写入，再提供同 ID 重试。
- 真实接入时执行超时可能意味着结果未知，必须先核查原操作，不能沿用“超时即未写入”的 Mock 假设。核查接口及恢复流程由核心与平台共同确认。
- 真实日历、提醒方案、权限名称、系统事件 ID、提醒 ID 和后台行为待平台验证，本次不作平台能力承诺。

## 6. 验收方式

下表为界面验收清单；v0.2 对应纯逻辑用例与人工反馈见第 6.1 节，v0.3 的独立记录见第 6.4 节。Mock 场景通过专门的「演示场景」入口选择，生成类场景在发送样例前选择，执行类场景在确认前选择。页面明确这是模拟选项，不伪装成系统设置；场景被消费后恢复正常，提醒补救默认模拟成功。

| 路径 | 用例 | 预期结果 |
|---|---|---|
| 正常 | 发送固定样例、确认、打开日程列表 | 字段与样例一致，只出现一条记录，持续显示演示标识，不声称真实提醒已注册或送达 |
| 正常 | 切换四个一级页面并点击基础功能入口 | 页面可达，未接入功能给出具体说明，无无响应按钮 |
| 异常 | 发送空白、超长文本或非样例文本 | 空白及超长不能发送；非样例明确说明限制，不生成错误日程 |
| 异常 | 生成中取消或离开助手，再等待回复 | 请求停止影响页面；回访不出现迟到草稿，可重新发起 |
| 异常 | 取消草稿、重新描述、重复点击确认 | 取消不创建记录；旧草稿不可执行；同一操作最多生成一条日程 |
| 异常 | 选择生成超时或执行超时场景 | 展示对应阶段错误和恢复入口，按本次 Mock 约定不写入；重试遵守请求与操作 ID 规则 |
| 异常 | 选择日程创建失败场景 | 日程列表不增加记录，提醒不执行，可重试 |
| 异常 | 选择提醒失败场景，再重试提醒 | 保留日程并显示部分成功，重试更新原记录，不重复建日程 |
| 权限拒绝 | 选择模拟日历权限拒绝场景并确认 | 明确提示模拟权限拒绝，保留草稿；不创建日程、不触发真实授权弹窗 |
| 模型失败 | 选择模型调用失败或无效字段场景 | 显示失败原因及重试入口；无有效可确认草稿，无写入 |
| 模型失败 | 选择待澄清场景 | 展示补充信息提示，不自动补造时间；允许取消并重新选择完整样例 |

## 7. v0.5 真实日历接入：平台能力检查（2026-10-26）

本节第 7.1–7.6 节描述第一阶段及其历史反馈；当前入口和多条记录行为由第 7.7 节更新。

范围及 `READ_CALENDAR` / `WRITE_CALENDAR` 权限方案已经开发者在会话中明确确认。当前实现是完整日历闭环的第一步：独立 debug 能力检查；自然语言草稿生成、Runtime 日历工具、多条真实日程管理及提醒补救仍待实现。内部探针接口不发布为 Agent 公共契约。

### 7.1 用户流程

进入“我的 → 日历能力检查 · 调试”，填写一条未来日程 → 核对标题、起止时间和提醒 → 点击“确认并创建真实日程” → 系统权限授权 → 创建 → 读回核对。首次探针只验证一条持久化操作，不提供清空记录或再次创建入口；后续正式多条操作记录将另行实现，不能用清除应用数据绕过未知结果。

本阶段输入格式为 `YYYY-MM-DD HH:mm`，明确使用 `Asia/Shanghai`，提醒为 0–10080 分钟的整数；开始及提醒时间均须在未来。该固定时区仅为设备能力检查范围，正式自然语言接入还需处理时区与日期澄清。禁止复用已过期的历史 Mock 日期做真实验收。

### 7.2 页面事项

- 确认前可返回修改或取消；确认快照不随输入框变化。
- 执行中禁止重复确认；离开页面或进入后台停止后续创建。已发出的系统写入无法视作已撤销，迟到结果仍需保存。
- 展示“日程已创建并读回一致”“提醒配置未核对通过”“结果待核查”等独立状态；从不宣称提醒已送达。
- 重启后恢复操作记录，需手动“核查原日程”。核查不会新增账户、修改配置或重建事件。
- 20 秒等待上限用于停止后续步骤并提示状态，不伪装为底层系统请求已取消。底层请求未结束时保留执行锁；重启后仍通过操作记录核查。

### 7.3 业务与 Agent 事项

`CalendarProbeSession` 管理校验、确认快照、执行锁、停止与核查；`CalendarProbeService` 组装真实平台及存储实现；页面不直接调用系统日历。确认写入前持久化稳定操作 ID、草稿和版本，系统返回后保存事件 ID。持久化失败、损坏或未知版本均阻断新增，不以空记录兜底。

探针记录格式为 v1，使用独立 Preferences `shuvi_calendar_probe_v1` 的 `operation` 键，异步 `flush` 完成后才发送事件创建。记录仅用于单条设备能力验证，包含日程标题和时间，保存在本机应用沙箱；不发送给模型或搜索服务。未实现版本迁移时拒绝读取未知版本。记录随应用备份策略处理；恢复到不同设备后也只核查，不自动重新创建。正式持久化账本与跨设备恢复不以本探针替代。

写入抛错或系统 ID 保存失败均可能已有事件，禁止自动重试。核查只读取应用专用日历，通过系统 ID（已知时）或原时间范围，再核对 `identifier`、标题、时间及时区；无结果、多结果或字段不符保持待核查，不能推导“尚未写入”。`identifier` 不被当作系统强制唯一约束。

普通问题仍回答；缺失信息会询问，用户可在聊天框补充。明确创建请求才提议草稿，模型不能直接写入。生成草稿、用户确认、写入与读回、实际提醒送达分别记录，不混作成功。

#### 页面事项

- `RuntimeChatSetup` 明示外发本次问题或个人日程描述；澄清时只带尚未完成的日程描述（累计最多 800 字符），不读取历史日历、联系人或知识库。普通对话不带完整聊天历史。
- `RuntimeCalendarCard` 在聊天内展示标题、北京时间起止和提前提醒值。按钮为“确认创建”“取消本次日程”；需要修改时取消后重新描述完整安排。提交后按钮禁用，重复点击不产生第二次写入。
- 完成、拒绝或正常取消后保持已启用模型会话，同一助手页内不要求重复输入 Key；模型请求仍共用每次启用 10 次上限。新对话清除尚未完成的澄清上下文，不清除 Key、日历或持久化执行记录。切页、切换模式、后台或销毁会话仍清理凭据。
- 失效授权不执行；等待权限时取消阻止后续创建。已经发起系统写入后停止等待不能撤销事件，页面提示到工作台核查，不自动重试；迟到的系统事件 ID 仍保存在既有日历账本。
- 工作台日历页面保留手动填表、独立模型草稿与已有操作核查。重复标题/时段、未知操作及容量限制继续使用原有规则；失败提示保留原生日历服务的具体原因。

#### 业务与 Agent 事项

链路：`Index → AssistantRuntimeSession → Runtime LLM / DeepSeek → 严格 JSON 草稿校验 → 第二个 Runtime TOOL 任务 → PolicyRequest / 授权卡 → 持久化 grant + operation + budget → CalendarToolAdapter → CalendarProbeSession → CalendarKit`。

应用注册 `shuvi.calendar.create`，来源 `NATIVE`、提供方 `shuvi-calendar-native`，风险 `MEDIUM`、副作用 `REVERSIBLE`、幂等模式 `RECONCILE`、数据边界 `DEVICE_ONLY`。这不是 MCP Server；搜索继续走原 MCP 链路。工具只支持单个非全天、非重复、北京时间、有一个提醒值的日程创建，不开放读取列表、修改、删除或备忘录。

模型意图只接受版本 `1.0` 的 `answer`、`clarify`、`draft`；草稿字段仍使用严格日期、时区、类型与未来提醒校验。模型任务使用 `ChatPurpose.ASSISTANT` / `PERSONAL`，工具任务同为 `PERSONAL`；普通搜索回答的 `PUBLIC_CHAT` 不变。

工具预览绑定任务、策略请求、操作 ID、工具版本、schema 和参数摘要。点击确认时重查期限，适配器在原生调用前再次验证已落盘的 grant、操作与参数，并消费 invocation，拒绝篡改和重放。Runtime 生成的操作 ID 同时用于系统事件标识及工作台账本。派发前持久化失败不得触发日历权限或写入；结果持久化失败不得显示成功。

本轮是两个独立持久化的 Runtime 任务，由应用服务顺序衔接，不是可跨进程自动恢复的单一工作流。工具任务使用既有生产 Runtime 与恢复存储桥；重启保留证据，不自动重放。系统日历工具无供应商计费，工具预算按一次本地调用结算；模型费用仍沿用 token 用量与估算准入，搜索账单口径不变。

#### 平台能力与存储

复用现有 CalendarKit、READ/WRITE_CALENDAR 授权、Preferences 日历账本与加密 RDB API，没有新增系统 API。助手模型任务使用 `shuvi_assistant_model_v1.db`（沿用 `shuvi-chat-1.0` 格式）；日历工具授权/操作/结果使用 `shuvi_calendar_runtime_v1.db`（上游执行恢复存储格式）。两库独立，避免 LLM 与 TOOL 存储语义混用。工作台与聊天共用 `CalendarProbeService.session` 和原日历账本，不重复迁移既有事件。

模型限制沿用 500 字符输入、1024 输出 tokens、30 秒网络超时和 10 次/会话；确认卡期限 120 秒，工具授权 grant 60 秒，原生流程沿用 20 秒停止等待、工具步骤 25 秒。日历 Runtime 任务库上限 128，原生记录上限 64；到上限阻断，不清除用户资料。未知日历操作仍须核查；本轮不提供 Runtime 记录归档或跨阶段自动恢复。

- **新建**：页首“＋ 新建”打开表单，有记录时可“收起”。表单含标题、开始/结束的日期和时间选择器（移动开始时自动保持时长，可跨天）和提醒下拉（0/5/10/15/30/60 分钟，草稿回填的其他值会追加）；默认取下一个整点、时长 1 小时，22 点以后取次日 09:00。“核对日程”后显示确认卡：标题、“10月27日 周二 22:00–23:00”、提醒，以及“确认并创建 / 返回修改”。
- **一句话安排**（仅 debug）：折叠在表单里，用 `DeepSeekKeyField`（可用本机记住的 Key），范围与费用说明折叠；上次离开页面时留下的“已停止草稿生成”状态不再显示。
- **状态提示**：读取、创建中、失败、创建成功等结果以一条小提示显示在页首。进入页面时重放的旧状态、恢复上次已核对记录时的“已恢复上次操作”不再提示；只有待核查的记录会自动展开并提示。
- **其他**：顶栏标签在日历页显示“系统日历”（原为“演示模式”）；大号“返回工作台”按钮改为左上“‹ 工作台”；侧边栏底部过时的“助手日程与联网搜索为演示功能”改为“演示模式不联网、不写日历；真实对话、搜索和日程在助手页开启”。
