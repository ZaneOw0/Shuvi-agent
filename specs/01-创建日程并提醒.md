# 01 创建日程并提醒

> 状态：已实现待验收。范围：助手日程提议、确认写入、工作台日程管理与结果核查。

## 1. 用户流程

1. 用户启用真实助手，用自然语言描述时间、地点和事项；也可在工作台填写日程。
2. 助手在统一工具循环中按意图调用 `calendar_propose`，生成待确认草稿；信息不足时澄清。
3. 用户在卡片内修改标题、开始/结束时间、地点、备注与提醒，再确认创建。编辑不重新调用模型。
4. 确认后由 Runtime 原生日历工具写入，读取结果并显示创建卡片。未确认、取消或返回修改不写系统日历。
5. 工作台按日期分组显示日程记录，展开可核查已有操作。结果未知时先核对已有稳定操作记录，再决定后续操作。

## 2. 页面事项

- 助手可在同一会话选择普通回答、文档工具或日程提议；Key 通过现有入口管理。
- 待确认卡片内可编辑和取消；成功卡展示真实创建结果，失败与待核查分别提示。
- 工作台保留手动表单、多条记录与操作核查，列表按日期分组。切换页面保留当前对话和待确认内容。
- 演示模式使用固定样例，不写真实日历；演示结果与真实结果分别标识。
- 手机、平板使用同一数据和操作规则，布局见 [多设备适配](15-平板端适配与手机功能一致性验收.md)。

## 3. 业务与 Agent 事项

- 模型生成草稿，宿主验证字段和时间范围；系统写入仅由确认后的原生工具执行。
- 采用稳定 operation ID、持久化操作记录与结果读回，重复确认复用原操作；同一身份不同参数不得重复写入。
- 请求已派发而结果未确认时展示待核查，不自动重发或假定创建失败。
- 取消、授权变化和迟到响应按当前对话与任务身份处理；取消不撤销已经完成的真实日历写入。
- 提醒注册、系统送达与日程创建分别验证；系统通知关闭时，创建成功不代表已送达提醒。

## 4. 平台能力与隐私

使用当前 API 26 日历适配器与 `READ_CALENDAR` / `WRITE_CALENDAR` 权限。权限在实际操作前检查，拒绝时保留可编辑草稿并说明原因。

系统日历、操作账本和聊天 UI 各自保存其职责范围数据。模型按真实助手授权消费用户输入，系统写入不由页面直接调用。

## 5. 验收方式

| 路径 | 验收重点 |
|---|---|
| 正常 | 自然语言提议、卡片修改、确认创建、读回、工作台多条记录及核查 |
| 异常 | 时间非法、写入失败、响应丢失、重复确认、进程恢复与结果未知 |
| 权限拒绝 | 拒绝日历权限，保留草稿且无写入；恢复授权后显式再操作 |
| 模型失败 | 澄清、非法草稿、超时、取消与普通聊天不误触发写入 |

相关命令与证据见 [普通对话](07-Runtime普通对话接入.md)、[PR26 集成验证](../docs/verification/PR26-main合入与RAG三链路回归.md) 和 [多设备验收](../docs/verification/平板端适配与手机对照验收记录.md)。已有模拟器人工反馈覆盖助手与工作台主要流程；当前版本的完整权限拒绝、提醒送达、恢复和真机矩阵仍待验收。

## 6. 当前限制

OpenHarmony 目标设备与系统日历兼容性待确认；系统通知开关、后台策略及真实提醒送达须在目标设备取证。Mock、host、构建和模拟器结果分别记录，不能相互代替。
