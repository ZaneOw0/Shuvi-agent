## 2. 用户流程

1. 用户进入助手页，看见演示模式说明、空态引导和「试试创建日程」样例入口。
2. 点击样例，将「2026 年 10 月 20 日下午 3 点到 4 点开项目会，提前 10 分钟提醒我」填入输入框，由用户发送。样例固定使用 `Asia/Shanghai` 时区，日期不随系统时间变化。
3. 页面显示用户消息与生成中状态；Mock 返回标题「项目会」、起止时间和提醒设置。
4. 确认卡片完整展示日期、时间、时区及提前提醒分钟数，并说明尚未创建。用户可确认、取消，或返回输入重新描述。
5. 用户点击「确认（演示）」后进入执行中状态，禁用重复提交。完成后显示「已添加到演示日程；未写入系统日历，不会实际提醒」。
6. 用户点击「查看演示日程」，进入工作台的日程列表，看到同一条记录；再次确认同一操作不会新增记录。
7. 用户切回助手，保留本次会话。关闭或重启应用后演示数据重置，页面说明这一限制。

自由输入允许发送，但只有明确标注的固定样例产生日程卡片。其他文本返回「当前为演示版本，请使用样例体验创建日程」，不根据任意输入套用样例结果，不声称完成真实语义理解。

## 3. 页面事项

### 3.1 页面与入口

以下名称表示页面职责，不预先锁定路由 API 或组件文件结构。

| 页面 | 本次内容与交互 |
|---|---|
| 助手 | 消息列表、文字输入、发送、样例入口、日程卡片；图片和语音入口点击后说明待接入，不弹系统权限框 |
| 工作台 | 日历日程、文件管理、联网搜索、长语音转写、跨设备协同入口；日历进入演示列表，其他入口给出具体待接入说明 |
| 演示日程 | 展示本次会话确认过的日程及模拟执行状态；无记录时提供返回助手创建样例的入口；返回后仍在工作台 |
| 知识库 | 展示明确标注的样例文档；导入、检索及问答入口说明待接入，不把样例当作用户文件或真实检索结果 |
| 我的 | 登录、多设备管理、主题设置入口；本次仅展示入口及待接入说明，不显示虚构的已登录或已同步状态 |

AI 导航通过助手的功能引导呈现；智能体编排是后续执行能力，本次不创建虚构的智能体运行面板。

### 3.2 页面状态与反馈

- 空输入或全空白禁止发送；单次文本限制为 500 个字符，超出时保留内容并提示，禁止发送。
- 生成中显示进度并提供取消；同一会话一次只处理一个请求。
- 草稿待确认时禁止继续发送；用户先确认或取消。返回输入重新描述视为取消原草稿，并保留原文字供修改。
- 执行中禁用确认与发送；本次模拟执行不提供取消，避免把请求取消误呈现为操作撤销。
- 失败保留输入或草稿并提供对应恢复操作；取消后迟到的 Mock 回复不得追加消息或改变结果。
- 切换一级页面保留会话；离开助手时取消尚在生成的请求，保留已生成草稿；执行中任务可完成，回到助手展示原操作结果。
- 日程创建、提醒注册分别展示状态；提醒注册失败时保留日程，并提供「重试提醒（演示）」。
- 输入框适应软键盘，列表可滚动；长标题、长文本和放大字体不遮挡确认、取消等主要操作。图标入口提供可读名称，状态不只依赖颜色区分。

## 4. 业务与 Agent 事项

### 4.1 前端 Mock 与后续接入边界

页面通过具备明确类型的前端服务读取样例、生成草稿、确认操作和重试提醒，固定数据与模拟延迟不写入页面组件。服务由 `entry` 装配；本次类型属于前端原型内部约定，不直接发布为核心模块的公共接口。

真实接入时由核心提供用例接口、Agent 产生候选动作，平台适配器执行系统能力。以下字段仅是对齐草案，需相关负责人确认后再落入公共代码；本 spec 不指定 Agent 身份、编排算法或模型供应商。

### 4.2 数据与接口草案

| 对象／操作 | 最小字段与行为 |
|---|---|
| 用户请求 | `requestId`、`conversationId`、`text`；生成请求和取消使用同一请求 ID |
| 日程草稿 | `draftId`、`requestId`、`title`、`startAt`、`endAt`、`timeZone`、`reminderMinutesBefore`；时间采用带时区偏移的 ISO 8601 字符串，提醒值为非负整数 |
| 生成草稿 | 输入用户请求；返回草稿、待澄清问题或失败结果；缺失或无效字段不得产生可确认卡片 |
| 确认草稿 | 输入 `draftId` 和稳定的 `operationId`；同一草稿确认及执行重试复用该操作 ID |
| 执行结果 | `operationId`、`draftId`、整体状态、日程状态、提醒状态及可选错误；演示记录使用独立 Mock ID，不冒充系统事件 ID |
| 重试提醒 | 输入原 `operationId`；只重试提醒，不重新创建日程 |
| 错误 | 错误阶段（生成／日程／提醒）、错误码、用户可读说明、是否可重试；页面不依赖供应商原始错误文本 |

示例草稿时间为 `2026-10-20T15:00:00+08:00` 至 `2026-10-20T16:00:00+08:00`，时区为 `Asia/Shanghai`，提前提醒值为 `10`。固定演示日期只用于复现原型，不作为真实系统创建过去日程的规则依据。

### 4.3 状态、校验与幂等

- 状态区分待澄清、待确认、执行中、成功、部分成功、失败和取消；草稿生成成功不等于执行成功。
- 确认前检查标题非空、起止时间有效且结束晚于开始、提醒值为非负整数。确认后的草稿不可原地修改。
- Mock 服务按 `operationId` 保存结果，重复调用返回已有结果；只禁用按钮不能代替幂等检查。
- 日程失败时不执行提醒；日程成功而提醒失败时为部分成功。提醒重试成功后更新原记录。
- 待澄清、失败或取消状态不能创建日程；过期请求的回调按请求 ID 丢弃。

## 5. 平台能力与权限

- 本次仅使用 ArkUI 和应用进程内存。消息、草稿、演示日程不持久化、不外发，也不访问设备个人数据。
- 权限拒绝为 Mock 场景，不读取或改变实际权限，不调用系统授权弹窗。
- 生成和执行默认模拟延迟约 800 毫秒；10 秒未完成视为超时。取消与超时后忽略迟到结果，不自动重试。
- 生成失败可由用户显式重试；执行失败保留原操作 ID。执行超时的模拟场景明确设为无写入，再提供同 ID 重试。
- 真实接入时执行超时可能意味着结果未知，必须先核查原操作，不能沿用“超时即未写入”的 Mock 假设。核查接口及恢复流程由核心与平台共同确认。
- 真实日历、提醒方案、权限名称、系统事件 ID、提醒 ID 和后台行为待平台验证，本次不作平台能力承诺。

## 6. 验收方式

下表为界面验收清单，正常日程流程已获开发者确认，其余项目仍待逐项验证；对应纯逻辑用例与人工反馈见第 6.1 节。Mock 场景通过专门的「演示场景」入口选择，生成类场景在发送样例前选择，执行类场景在确认前选择。页面明确这是模拟选项，不伪装成系统设置；场景被消费后恢复正常，提醒补救默认模拟成功。

| 路径 | 用例 | 预期结果 |
|---|---|---|
| 正常 | 发送固定样例、确认、打开日程列表 | 字段与样例一致，只出现一条记录，持续显示演示标识，不声称真实提醒已注册或送达 |
| 正常 | 切换四个一级页面并点击基础功能入口 | 页面可达，未接入功能给出具体说明，无无响应按钮 |
| 异常 | 发送空白、超长文本或非样例文本 | 空白及超长不能发送；非样例明确说明限制，不生成错误日程 |
| 异常 | 生成中取消或离开助手，再等待回复 | 请求停止影响页面；回访不出现迟到草稿，可重新发起 |
| 异常 | 取消草稿、重新描述、重复点击确认 | 取消不创建记录；旧草稿不可执行；同一操作最多生成一条日程 |
| 异常 | 选择生成超时或执行超时场景 | 展示对应阶段错误和恢复入口，按本次 Mock 约定不写入；重试遵守请求与操作 ID 规则 |
| 异常 | 选择日程创建失败场景 | 日程列表不增加记录，提醒不执行，可重试 |
| 异常 | 选择提醒失败场景，再重试提醒 | 保留日程并显示部分成功，重试更新原记录，不重复建日程 |
| 权限拒绝 | 选择模拟日历权限拒绝场景并确认 | 明确提示模拟权限拒绝，保留草稿；不创建日程、不触发真实授权弹窗 |
| 模型失败 | 选择模型调用失败或无效字段场景 | 显示失败原因及重试入口；无有效可确认草稿，无写入 |
| 模型失败 | 选择待澄清场景 | 展示补充信息提示，不自动补造时间；允许取消并重新选择完整样例 |
