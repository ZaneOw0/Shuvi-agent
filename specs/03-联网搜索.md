## 1. 目标与范围

提供一个 `web_search` MCP 工具，通过一家搜索供应商返回公开网页的标题、链接和摘要，供 Agent 生成带来源的回答。

本轮在 `services/search-mcp/` 实现独立 TypeScript / Node.js 服务、运行时校验、本机验证客户端、确定性测试与启动说明。使用官方 MCP SDK 和 Zod，依赖及锁文件独立管理；不进入 OHPM 或 HAP。

v0.2 增加 ArkUI 搜索演示页面与独立 Mock 状态调度，不连接上述服务。v0.3 增加 debug 首页真实接线：显式关键词、Runtime 授权、搜索结果持久化及独立 Runtime 模型任务回答。暂不实现网页全文抓取、多供应商、RAG、云部署或自动账单核对；不代表团队已确认全部公共契约。

## 2. 用户流程

v0.3 调试闭环（已接线待设备验收）：用户输入公开关键词 → 核对实际参数并授权 → Runtime 校验及持久化派发 → `web_search` 获取来源 → 保存结果及待核账记录 → 独立 Runtime 模型任务回答 → 展示来源及引用编号。

本轮可执行流程：开发者启动本机服务 → 验证客户端完成 MCP 握手和工具发现 → 开发者本机配置凭据 → 显式调用一次公开关键词搜索 → 核对标题、链接和摘要。详见 [运行说明](../services/search-mcp/README.md)。

搜索完成与回答完成是两个状态；无搜索结果、搜索失败或回答生成失败分别处理。

v0.2 页面演示：助手页开启「搜索」→ 点击「搜索样例」→ 发送 → 模拟搜索资料 → 展示固定来源 → 模拟整理回答 → 查看引用或打开原文。关闭搜索后沿用原日程样例流程。

## 3. 页面事项

### 3.1 v0.2 已实现的页面演示

- 「搜索」默认关闭；开启时通过文字、背景和边框颜色表示，不增加对勾。读屏名称描述开关状态；操作区最小高度 44vp。
- 固定支持「帮我找一下 ArkUI 的官方开发文档，应该从哪里开始？」及「HarmonyOS ArkUI 官方开发文档」两个样例输入。其他问题明确提示仅支持样例，不套用固定答案。输入上限沿用现有页面的 500 个 JavaScript 字符串代码单元；真实接线时再对齐服务端 Unicode 码点规则。
- 搜索中、整理回答、完成、无结果、超时、授权拒绝、回答失败、取消分别展示。顶部场景设置随搜索开关切换到搜索或日程场景，搜索异常场景仅用于下一次发送。
- 来源包含标题、域名、摘要及打开原文入口；可折叠来源组、展开摘要。回答完成后默认收起来源组；失败或停止回答仍保留来源。
- 点击回答中的「来源 [编号]」弹出对应来源详情，再选择打开原文；这是原生交互对 HTML 原型中滚动定位的调整。
- 全程显示「固定样例演示」；回答明确标为「非模型生成」。来源与摘要为本地整理样例，不读取服务端响应、不产生真实 `searchedAt` 或授权结果。
- 搜索期间禁止重复发送和切换搜索模式；新对话要求先取消当前任务。取消、切换一级页面或页面销毁时结束任务，迟到结果不回写。切回助手保留已停止状态；通过悬浮入口返回同样保留消息。
- 搜索失败可重新搜索，空结果可修改问题；回答失败或停止可只重试回答，保留原来源、不重新搜索。授权拒绝的「模拟允许本次搜索」只切换演示状态，不能视为真实授权。
- 开始新对话清空消息、搜索轮次与异常场景，保留搜索开关选择及已确认的演示日程。进程结束后不续跑、不持久化搜索数据。

## 4. 业务与 Agent 事项

### 4.1 输入契约 v0.1

工具名：`web_search`，工具清单通过 MCP `tools/list` 获取。

| 字段 | 类型 | 约束 |
|---|---|---|
| `query` | string | 必填；去除首尾空白后 1–500 个 Unicode 码点 |
| `maxResults` | integer | 可选；默认 5，范围 1–10 |

拒绝未知字段、错误类型和越界数量。供应商 URL、超时及凭据不可由工具参数覆盖。实际 Unicode 长度约束由服务端运行时校验；客户端不得仅依赖生成的 JSON Schema 放行。

输入样例：

```json
{ "query": "HarmonyOS ArkUI 官方开发文档", "maxResults": 3 }
```

### 4.2 成功与失败

成功的 `structuredContent` 格式如下（内容为契约示例，不是真实搜索证据）：

```json
{
  "schemaVersion": "1.0",
  "requestId": "00000000-0000-4000-8000-000000000001",
  "provider": "tavily",
  "query": "示例关键词",
  "searchedAt": "2026-10-14T00:00:00.000Z",
  "results": [
    { "title": "示例页面", "url": "https://example.com/", "snippet": "示例摘要" }
  ]
}
```

`requestId` 是本服务生成的 UUID，`searchedAt` 是结果整理时的 UTC 时间，不表示网页发布时间。结果最多为请求数量；合法空数组表示无结果。上游数据必须立即校验，缺字段或不合法 URL 不得补假数据。

工具执行失败返回 `isError: true`，结构化内容为：

```json
{
  "schemaVersion": "1.0",
  "requestId": "00000000-0000-4000-8000-000000000002",
  "error": { "code": "CONFIGURATION", "message": "搜索服务尚未配置有效的 Tavily 凭据。" }
}
```

成功和失败均在 `content` 中附带一个 `type: "text"` 的等价 JSON 块。声明的 `outputSchema` 使用成功与失败对象的联合结构；客户端按 `isError` 分支解析，不将错误当作搜索结果。协议错误（如未知工具）使用 MCP 错误响应，HTTP 入口拒绝不承诺工具结果结构。

| 错误码 | 含义 |
|---|---|
| `INVALID_ARGUMENT` | 参数无效，不调用上游 |
| `CONFIGURATION` | 缺少或存在非法换行的凭据，不调用上游 |
| `AUTHENTICATION` | 上游 HTTP 401 / 403 |
| `RATE_LIMITED` | 上游 HTTP 429，或本服务并发已满 |
| `QUOTA_EXCEEDED` | 上游 HTTP 432 / 433 |
| `NETWORK` | 无法完成网络连接或读取 |
| `TIMEOUT` | 超过上游截止时间 |
| `CANCELLED` | 调用已取消；客户端可能先收到本地取消异常 |
| `INVALID_RESPONSE` | JSON 或必需字段、URL 无效 |
| `RESPONSE_TOO_LARGE` | 上游或整理后的结果超出限制 |
| `UPSTREAM` | 其他上游失败或无法分类的执行异常 |

不会转发上游响应正文、凭据或内部异常详情。失败不得转成空结果成功。

### 4.4 真实授权预览的应用层准备（2026-10-23）

状态：应用数据层已实现待验收；首页和授权卡片尚未接到生产 Runtime。本节使用已导出的 `ToolInvocationPreparerPort`、`PreparedToolDispatch` 和 `AgentApplicationBackend.authorize()`，没有修改 Agent 公共契约或来源文件。

`entry/src/main/ets/services/model/SearchAuthorizationPreview.ets` 提供如下能力：

- `PreviewingSearchPreparer` 包装既有 `ShuviWebSearchToolInvocationPreparer`，从准备好的 `ToolInvocation.argumentsJson` 提取 `query`、`maxResults`，不把原问题猜作实际搜索词。
- 保存前核对授权请求与调用的 task、step、operation、工具版本、schema 和参数摘要，以及搜索工具/供应商白名单、只读风险、时间及参数范围。摘要由装配时注入的 `ConnectorDigestPort` 计算，生产必须使用真实摘要实现。
- `SearchAuthorizationPreviews.resolve()` 按当前前端授权请求匹配 task/request、工具、供应商、风险、费用及有效期，返回副本；同一请求 ID 下的数据冲突被拒绝，不能改写已展示的预览。
- `decideSearchAuthorization()` 在确认点击时再次检查预览。缺失、过期或不匹配时不调用批准接口；显式拒绝仍可提交，由 Runtime 最终判定。只有后端接受决定后才释放该任务的预览，不把提交决定等同于工具执行成功。
- 数据仅存在宿主内存，最多 32 个未过期条目；不记录原始正文或凭据，不写存储。页面/宿主后续接线必须在任务结束或取消时调用 `forgetTask()`，宿主释放时调用 `clear()`；重启后预览缺失时禁止批准，不从用户旧输入拼造预览。

通用 `createShuviModelBackend()` 已安装这层包装器，预览通过 `ShuviModelBackendPorts.authorizations` 交给应用服务。页面仍只消费应用服务，不直接访问 Runtime 内部文件或供应商。

后续接线顺序：补齐真实宿主资源和准确模型/预算配置 → 应用服务持有后端、订阅任务并接入授权/取消 → 展示真实来源 → 完成回答与澄清路径。`AgentRuntimeFacade` 已公开 `provideClarification()`，但 `AgentApplicationBackend` 未包装该方法；先考虑由应用宿主通过公开 Facade 实现桥接，不以此为由擅改固定模块。来源返回不等于回答完成，现有固定回答不能用于真实任务。

### 4.5 搜索用量元数据 v1（2026-10-24）

状态：用户已批准本节扩展，应用与服务实现待真实联调验收。保持原输入、成功/失败 `structuredContent`、`outputSchema` 和等价 JSON 文本不变；不改固定 Agent 模块。MCP 工具结果顶层新增 `_meta.shuviSearchUsage`，不是来源正文或模型指令。

示例（合成数据，不是真实账单）：

```json
{
  "_meta": {
    "shuviSearchUsage": {
      "schemaVersion": "1.0",
      "requestId": "00000000-0000-4000-8000-000000000001",
      "provider": "tavily",
      "state": "known",
      "unit": "credits",
      "credits": 1,
      "providerRequestId": "supplier-example-1"
    }
  }
}
```

- `requestId` 必须与同一工具响应的 `structuredContent.requestId` 一致。元数据版本独立固定为 `1.0`，供应商固定为 `tavily`。
- `known` 必须包含 `unit: credits` 与有限、非负且不超过 `Number.MAX_SAFE_INTEGER` 的数值；不擅自限制为整数。显式返回的 0 可保留，缺失不能补 0。
- `providerRequestId` 仅在 known 中可选，取自合法的供应商 `request_id`，限 1–128 个英文字母、数字、下划线或连字符。不是本服务生成的 requestId。
- `unknown` 仅含 schemaVersion、requestId、provider、state 四个字段，不带 credits、unit 或供应商编号。供应商缺少/返回非法用量或非法编号时保留有效来源、用量降为 unknown；工具失败、超时、取消同样不能推断免费。协议/连接级错误可能根本没有工具结果。
- 服务请求显式启用 `include_usage: true`；解析 `usage.credits`、`request_id` 的依据为 [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)。使用量与账单货币不同，本轮不换算美元、不声称实际扣款。

应用实现位于 `services/model/SearchUsageReceipts.ets`：现有 `ShuviWebSearchMcpClientToolPort` 先验证来源和请求参数；包装客户端再读取公开的 `McpToolResult.raw`。校验元数据对象、字段类型/范围/版本、原始 structuredContent 与返回结果一致性。没有或非法元数据仍可使用合法来源，但用量为 unknown。

`SearchUsageMcpAdapter` 保留上游授权、工具身份和策略检查。每次调用保存独立参数快照；完成后以实际 ToolInvocation 的 task、step、operation、attempt、invocation、工具身份与参数，以及 ToolOutcome 的内容摘要建立关联。相同关键词并发并不共享“当前调用”。旧结果格式和内容仍由上游验证，应用不改 outcome。失败/取消若没有可关联的成功结果，查询收据返回 undefined，不能用于结算。

重复服务端 requestId、重复供应商编号、同一 invocation 的冲突回放会使相关记录不可用；完全一致的重复绑定不重复计量。查询返回副本。单个会话最多保留 128 条采集记录与 128 条调用绑定，满后新记录未知，不淘汰旧 ID 后重新计量；会话关闭同步清空并永久拒绝迟到写入，新会话另建实例。

限制：记录仅在内存，不能跨进程对账，也不是签名账单；远端服务认证、账单费率快照、币种/取整政策、持久化与中断恢复尚未完成。`UnsettledSearchAccounting` 继续返回 undefined；启动检查仍禁止提交任务和真实工具执行，首页仍为 Mock。此次授权不等于允许跳过这些事项启用计费任务。

## 5. 平台能力与权限

### 5.1 供应商与数据

固定调用 `POST https://api.tavily.com/search`，通过 Authorization Bearer 认证。只发送当前关键词与必要参数，不发送对话、日程或知识库全文。

固定 `search_depth: basic`、`topic: general`、`auto_parameters: false`，关闭答案、图片和网页全文返回。将 `content` 映射为 `snippet`。标题最多 512、URL 最多 2048、摘要最多 8000 个 JavaScript 字符串代码单元；URL 仅允许不含用户信息的 HTTP(S) 地址。超限或非法字段明确拒绝。

### 5.2 传输和运行限制
