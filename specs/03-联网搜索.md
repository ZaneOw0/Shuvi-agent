## 1. 目标与范围

提供一个 `web_search` MCP 工具，通过一家搜索供应商返回公开网页的标题、链接和摘要，供 Agent 生成带来源的回答。

本轮在 `services/search-mcp/` 实现独立 TypeScript / Node.js 服务、运行时校验、本机验证客户端、确定性测试与启动说明。使用官方 MCP SDK 和 Zod，依赖及锁文件独立管理；不进入 OHPM 或 HAP。

v0.2 增加 ArkUI 搜索演示页面与独立 Mock 状态调度，不连接上述服务。暂不实现真实页面接线、Runtime 注册、网页全文抓取、多供应商、RAG 检索或云部署。本文仍是对接提案，不代表 Agent、平台负责人已确认公共契约。

## 2. 用户流程

目标闭环（待集成）：用户提出需要联网的问题 → 应用明确联网状态 → Agent 校验工具调用授权 → `web_search` 获取来源 → Agent 基于来源回答 → 页面展示引用。

本轮可执行流程：开发者启动本机服务 → 验证客户端完成 MCP 握手和工具发现 → 开发者本机配置凭据 → 显式调用一次公开关键词搜索 → 核对标题、链接和摘要。详见 [运行说明](../services/search-mcp/README.md)。

搜索完成与回答完成是两个状态；无搜索结果、搜索失败或回答生成失败分别处理。

v0.2 页面演示：助手页开启「搜索」→ 点击「搜索样例」→ 发送 → 模拟搜索资料 → 展示固定来源 → 模拟整理回答 → 查看引用或打开原文。关闭搜索后沿用原日程样例流程。

## 3. 页面事项

### 3.1 v0.2 已实现的页面演示

- 「搜索」默认关闭；开启时通过文字、背景和边框颜色表示，不增加对勾。读屏名称描述开关状态；操作区最小高度 44vp。
- 固定支持「帮我找一下 ArkUI 的官方开发文档，应该从哪里开始？」及「HarmonyOS ArkUI 官方开发文档」两个样例输入。其他问题明确提示仅支持样例，不套用固定答案。输入上限沿用现有页面的 500 个 JavaScript 字符串代码单元；真实接线时再对齐服务端 Unicode 码点规则。
- 搜索中、整理回答、完成、无结果、超时、授权拒绝、回答失败、取消分别展示。顶部场景设置随搜索开关切换到搜索或日程场景，搜索异常场景仅用于下一次发送。
- 来源包含标题、域名、摘要及打开原文入口；可折叠来源组、展开摘要。回答完成后默认收起来源组；失败或停止回答仍保留来源。
- 点击回答中的「来源 [编号]」弹出对应来源详情，再选择打开原文；这是原生交互对 HTML 原型中滚动定位的调整。
- 全程显示「固定样例演示」；回答明确标为「非模型生成」。来源与摘要为本地整理样例，不读取服务端响应、不产生真实 `searchedAt` 或授权结果。
- 搜索期间禁止重复发送和切换搜索模式；新对话要求先取消当前任务。取消、切换一级页面或页面销毁时结束任务，迟到结果不回写。切回助手保留已停止状态；通过悬浮入口返回同样保留消息。
- 搜索失败可重新搜索，空结果可修改问题；回答失败或停止可只重试回答，保留原来源、不重新搜索。授权拒绝的「模拟允许本次搜索」只切换演示状态，不能视为真实授权。
- 开始新对话清空消息、搜索轮次与异常场景，保留搜索开关选择及已确认的演示日程。进程结束后不续跑、不持久化搜索数据。

## 4. 业务与 Agent 事项

### 4.1 输入契约 v0.1

工具名：`web_search`，工具清单通过 MCP `tools/list` 获取。

| 字段 | 类型 | 约束 |
|---|---|---|
| `query` | string | 必填；去除首尾空白后 1–500 个 Unicode 码点 |
| `maxResults` | integer | 可选；默认 5，范围 1–10 |

拒绝未知字段、错误类型和越界数量。供应商 URL、超时及凭据不可由工具参数覆盖。实际 Unicode 长度约束由服务端运行时校验；客户端不得仅依赖生成的 JSON Schema 放行。

输入样例：

```json
{ "query": "HarmonyOS ArkUI 官方开发文档", "maxResults": 3 }
```

### 4.2 成功与失败

成功的 `structuredContent` 格式如下（内容为契约示例，不是真实搜索证据）：

```json
{
  "schemaVersion": "1.0",
  "requestId": "00000000-0000-4000-8000-000000000001",
  "provider": "tavily",
  "query": "示例关键词",
  "searchedAt": "2026-10-14T00:00:00.000Z",
  "results": [
    { "title": "示例页面", "url": "https://example.com/", "snippet": "示例摘要" }
  ]
}
```

`requestId` 是本服务生成的 UUID，`searchedAt` 是结果整理时的 UTC 时间，不表示网页发布时间。结果最多为请求数量；合法空数组表示无结果。上游数据必须立即校验，缺字段或不合法 URL 不得补假数据。

工具执行失败返回 `isError: true`，结构化内容为：

```json
{
  "schemaVersion": "1.0",
  "requestId": "00000000-0000-4000-8000-000000000002",
  "error": { "code": "CONFIGURATION", "message": "搜索服务尚未配置有效的 Tavily 凭据。" }
}
```

成功和失败均在 `content` 中附带一个 `type: "text"` 的等价 JSON 块。声明的 `outputSchema` 使用成功与失败对象的联合结构；客户端按 `isError` 分支解析，不将错误当作搜索结果。协议错误（如未知工具）使用 MCP 错误响应，HTTP 入口拒绝不承诺工具结果结构。

| 错误码 | 含义 |
|---|---|
| `INVALID_ARGUMENT` | 参数无效，不调用上游 |
| `CONFIGURATION` | 缺少或存在非法换行的凭据，不调用上游 |
| `AUTHENTICATION` | 上游 HTTP 401 / 403 |
| `RATE_LIMITED` | 上游 HTTP 429，或本服务并发已满 |
| `QUOTA_EXCEEDED` | 上游 HTTP 432 / 433 |
| `NETWORK` | 无法完成网络连接或读取 |
| `TIMEOUT` | 超过上游截止时间 |
| `CANCELLED` | 调用已取消；客户端可能先收到本地取消异常 |
| `INVALID_RESPONSE` | JSON 或必需字段、URL 无效 |
| `RESPONSE_TOO_LARGE` | 上游或整理后的结果超出限制 |
| `UPSTREAM` | 其他上游失败或无法分类的执行异常 |

不会转发上游响应正文、凭据或内部异常详情。失败不得转成空结果成功。

## 5. 平台能力与权限

### 5.1 供应商与数据

固定调用 `POST https://api.tavily.com/search`，通过 Authorization Bearer 认证。只发送当前关键词与必要参数，不发送对话、日程或知识库全文。

固定 `search_depth: basic`、`topic: general`、`auto_parameters: false`，关闭答案、图片和网页全文返回。将 `content` 映射为 `snippet`。标题最多 512、URL 最多 2048、摘要最多 8000 个 JavaScript 字符串代码单元；URL 仅允许不含用户信息的 HTTP(S) 地址。超限或非法字段明确拒绝。

凭据由开发者本机配置，不进入代码、日志、提交或 AI 上下文。不持久化关键词、响应、会话或任务。服务端没有逐请求日志；公开验证脚本会输出固定公开查询的结果供人工核对。供应商侧的数据处理和额度规则以其条款为准。

### 5.2 传输和运行限制

- 本机开发端点为 `http://127.0.0.1:8787/mcp`，仅绑定回环地址；不修改防火墙、不开放远程访问。
- Streamable HTTP 使用 JSON 响应与会话 ID，POST 用于协议消息，DELETE 结束会话；GET 返回 405，不提供独立 SSE 流。
- 拒绝非本机 Host 和浏览器 Origin；这不等同于用户认证，本机进程仍可访问。
- 最多 16 个会话、4 个并发搜索、32 个 TCP 连接。空闲超过 120 秒的会话由每 30 秒一次的扫描清理，未知或过期会话返回 404，客户端需重新初始化。
- MCP 请求体最大 16 KiB；上游响应体最大 1 MiB；单份整理结果 JSON 最大 192 KiB。MCP 同时携带文本与结构化内容，线上响应会更大，192 KiB 不是整个 HTTP 响应上限。
- 不新增鸿蒙权限或系统 API。实际设备接入时，须另行核实网络 API、权限、服务地址和认证；手机 localhost 不能访问电脑上的服务。
- 远程部署前需确定 HTTPS、认证、配额、运维与费用承担，本版本不能直接作为公开服务发布。

v0.2 原文入口使用 `@kit.AbilityKit` 的 `UIAbilityContext.openLink`（API 12+，Stage 模型，`SystemCapability.Ability.AbilityRuntime.Core`），传入 `appLinkingOnly: false`，在前台用户点击时交系统匹配打开方式。本工程 API 26 满足版本条件，不新增 `requestPermissions`；由目标应用加载网页。入口仅放行本 spec 三条固定 HTTPS 来源，不接受任意外部 URL。打开前停止尚在执行的演示任务；启动失败明确提示，不假报网页已打开。实际浏览器跳转、返回及设备限制仍需模拟器 / 真机验证。

- `API参考/Ability_Kit_程序框架服务/ArkTS_API/接口依赖的元素及定义/application/UIAbilityContext/js-apis-inner-application-uiabilitycontext`，`openLink` 章节。
- `API参考/Ability_Kit_程序框架服务/ArkTS_API/Stage模型能力的接口/ohos_app_ability_OpenLinkOptions_openLink的可选参数_/js-apis-app-ability-openlinkoptions`。

### 5.3 超时、取消、重试与恢复

上游超时 15 秒，包含响应体读取。MCP 取消通知和服务正常关闭会传递中断信号；已发出的请求无法保证免计费。

不自动重试、不缓存去重；重复调用可能重复计费。不返回被截断的响应或部分校验失败的成功结果。正常退出可使用 `Ctrl+C`，进程重启后重新建立会话，不自动续跑任务。单纯网络断开不等同于已送达 MCP 取消通知，仍可能等待上游超时结束。

### 6.6 搜索卡片停留在初始状态的修复（2026-10-20）

用户首次模拟器验收反馈：发送搜索样例后一直显示“正在搜索相关资料”。读取当前模拟器布局也确认卡片停在搜索状态，但搜索开关和场景按钮已恢复可用。首次验收失败；修复后的复验结果单独记录如下。

原因：`updateSearch` 用相同 ID 的新 `SearchTurn` 替换状态数组元素；原 `ForEach` 以 ID 复用卡片，却通过生成回调的 `turn` 局部变量传入旧对象，卡片没有订阅到新数组元素。定时器和纯逻辑测试通过不能证明卡片会刷新。

修复：保留轮次 ID 作为键，卡片的 `turn` 改为直接绑定 `this.searchTurns[index]`；遍历完整状态数组，再按消息关联的 ID 显示卡片。键生成回调同时声明索引参数，但键值仍只使用 ID。未通过更换随机键或重建卡片规避问题，也未改动 Mock 延时与搜索结果。

依据：[OpenHarmony ForEach 循环渲染文档](https://github.com/openharmony/docs/blob/master/zh-cn/application-dev/ui/rendering-control/arkts-rendering-control-foreach.md)中的组件复用与数据变化不渲染说明。本机未找到项目指定的 `arkts-grammar-standards` skill，沿用项目第 7 节约束，并核对官方文档；未引入新系统 API。
