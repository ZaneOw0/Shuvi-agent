## 1. 目标与范围

### 1.1 目标

使用同一套代码、同一 bundleName 和同一构建产物，在手机与平板上安装、启动并使用当前已接入的功能。平板横屏、竖屏及系统支持的分屏/窗口缩放后，关键内容可见、控件可操作、状态不串改，业务权限和数据规则与手机一致。

最终验收必须实际拉起平板模拟器，在其上安装并启动应用，按第 6 节逐项操作。构建通过、设备类型声明和宿主测试通过不能替代平板功能验收。

本轮“下载安装”指交付已签名 HAP 并通过 DevEco 安装运行的开发验收闭环；应用市场上架、审核、正式分发渠道另行处理。

## 2. 用户流程

1. 在手机与平板分别安装同一版本；平板通过桌面图标冷启动，进入当前真实助手首页，无白屏或设备类型不匹配错误。
2. 平板竖屏/较窄窗口沿用抽屉导航；窗口足够宽时显示侧栏与内容并排布局。助手、日程、知识库、我的及历史对话入口仍可达。
3. 用户在平板本机配置所需 Key、授予权限并按原流程使用功能；不默认继承手机凭据、费用许可或知识库授权。
4. 对话输入、录音、选择图片、日程确认、检索与预览过程中旋转或调整窗口，布局重新计算；不能因纯布局变化重复发送、重复入库或重复创建日程。
5. 应用退后台、进程回收、用户取消等真实生命周期仍执行原取消/凭据释放规则。重启恢复普通对话记录；不恢复知识库授权或自动续跑云端任务。
6. 窄窗口恢复后，导航、输入框、确认与关闭按钮可见；PDF 返回后仍在原资料上下文，历史对话与未提交草稿遵循原契约。

## 3. 页面事项

### 3.1 响应式布局策略

基于当前应用可用窗口/容器尺寸（vp），不根据静态 `deviceType` 或物理像素给平板固定套用横屏布局。已新增纯布局策略 `entry/src/main/ets/model/ResponsiveLayoutPolicy.ets`，以外层 `onAreaChange` 的窗口宽度为唯一导航断点，以内容层宽度决定紧凑控件文案；未引入新 UI 框架，也未把 V1 页面改写成 V2。下表数值即当前实现值。

| 应用可用宽度 | 拟定呈现 | 内容约束 |
|---|---|---|
| `<600vp` | 保留现有手机式 Overlay 抽屉与页面入口 | 现有紧凑边距；内容与输入区不超过可用宽度 |
| `600–839vp` | 保留临时抽屉，扩大可用内容区 | 主内容目标上限约 720vp，宽按钮组可折行；小窗口优先完整可操作 |
| `≥840vp` | 同一 SideBarContainer 切为 Embed，左侧常驻导航/历史入口 | 侧栏目标 240–280vp；内容使用剩余空间；普通表单不超过约 960vp，对话/输入区上限约 840vp |

600/840vp 取自官方响应式区间；侧栏宽度与内容上限是本项目设计参数，不是系统保证值。内容区不足时退回紧凑布局；当前 840vp 起才启用 Embed，最小内容宽 600vp 由宿主测试守护。

- 导航断点读取最外层可用窗口宽度，卡片布局读取扣除侧栏后的实际内容宽度，避免展开侧栏后反复跨断点、闪烁或循环更新。
- 区分“宽屏侧栏可见”和“窄屏遮罩抽屉打开”。Embed 下不显示阻断遮罩、不禁用正文触摸，也不把正文标为无障碍不可访问。
- 尽量保持同一页面树、服务引用和稳定组件身份，只调整属性和布局；不在两个布局分支各创建一个 Agent、知识库会话或 ArkWeb。
- 首次尺寸尚未测得时使用可操作的紧凑态，不按 0 尺寸创建错误的宽屏或悬浮位置。

### 3.2 具体页面

| 页面/组件 | 适配内容 |
|---|---|
| 助手与历史对话 | 聊天、输入框、图片/语音草稿、日程确认卡宽度一致；长消息与来源换行；历史列表与按钮不被侧栏截断 |
| 日程 | 日期/时间选择、日程列表、确认/取消及失败提示在横屏和小窗口可操作；不改变日程默认值与写入确认 |
| 知识库 | 导入、文件列表/详情、L0/L1 搜索、分页、来源按钮、设置入口不丢失；按钮组按内容宽度排列，缩略图按容器调整 |
| 我的 / API Key / 解析 / 视觉 / Embedding | 沿用 PR #26 的统一入口；表单限宽居中；长文字和确认项可滚动，不以扩大窗口取消费用/基线确认 |
| PDF 与图片 | 原件覆盖当前应用完整可用区域；横竖屏、侧栏变化后重算视口；关闭/返回仍释放正确租约，不重复创建 Web 引擎 |
| 应用内悬浮助手 | 按当前内容容器和安全区域吸边，不落在侧栏或屏幕外；缩放/旋转中停止旧拖动并重新约束位置 |

键盘弹出后必须仍能输入、发送、取消和确认；按当前系统避让行为验证，发现遮挡再按官方窗口/UIContext API 修复，避免重复叠加键盘高度。长弹窗支持滚动，主要操作区域至少 44vp；保留品牌色、语义字号和系统字体缩放，不将字体按平板物理像素整体放大。

横竖屏/窗口变化不得主动调用 `changeTab()`、`resetConversation()` 或重新打开查询来获取新布局；只有实际业务导航才走原有生命周期。

## 4. 业务与 Agent 事项

### 4.1 功能一致性与状态边界

- 手机和平板使用同一 `RuntimeAssistantCoordinator`、`RuntimeChatService`、日程工具、搜索与 `KnowledgeAssembly`，布局策略不读取 Key、直接调用模型或写系统日历。
- 普通对话与历史恢复按 spec 16；图片与语音组合消息按 spec 15/12，不因平板布局将转写显示在气泡中。
- L0 继续共用 FTS5、候选读回和有界字面补充；L1 保留当前资格、配置/费用校验和兼容空间；L2 保留授权后的自主 `knowledge_search`、同一 loop 回注、来源与撤销规则。
- 知识库默认未授权；“仅本机检索”与“允许语义查询”分开；普通持久记忆与知识临时上下文边界不变。
- 持久化保持本机隔离；新平板空库是正常初始状态，不能把手机的路径、加密库或凭据直接复制过去伪装恢复。
- 页面重排和尺寸回调不得创建新的网络请求/后台任务；等待中旋转不能产生第二次模型请求、Embedding、解析或系统写入。

### 5.2 环境准备和安装

本轮使用的环境准备步骤见下（名称/serial 与执行时清单一致）；镜像在实施阶段已下载，本轮复核 `emulator image list --all --device-type tablet --format json` 为 `osVersion=HarmonyOS 7.0.0(26.0.0)`、`SoftWareVersion=7.0.0.107`、`downloaded=true`。同一时间只运行一个实例，切换先用 `devecocli emulator stop <name>` 停止另一个：

```text
devecocli emulator image list --all --device-type tablet --format json
devecocli emulator image download --device-type tablet --os-version "HarmonyOS 7.0.0(26.0.0)"
devecocli emulator create ShuviTablet26 --device-type tablet --os-version "HarmonyOS 7.0.0(26.0.0)"
devecocli emulator start ShuviTablet26
devecocli emulator list
devecocli device list
```

仅在实例名称未占用时创建，不使用 `--force`，不覆盖或删除现有 Phone26/其他实例。下载、登录与模拟器许可按工具真实提示处理，不替用户接受许可；不盲目升级 SDK 或改成低版本 tablet 镜像。

构建、签名与启动沿用仓库脚本及 `.local/` 签名缓存设计：先 build 成功再 run，明确目标 serial 和 product，设备未就绪不安装。签名不一致时停止，不卸载或清数据绕过；不输出凭据或签名配置。新平板需要的业务 Key 由用户在设备安全输入界面配置，不读取或搬运手机密钥。

本轮不增加权限；现有网络、麦克风与日历权限仍逐能力生效。文件/图库选择器仅访问用户选择资料；系统能力缺失或失败应如实反馈，不能因平板类型静默隐藏对应功能或改成 Mock。

## 6. 验收方式

### 6.1 准入与测试分层（本轮结果）

## 7. 已知限制与未覆盖项

- 日程写入：平板仅完成草稿、确认卡与系统权限申请，写入被用户侧停止，未取得「创建成功 + 系统读回 + 提醒送达」证据；手机未做写入。
- 手机知识库：既有 138MB 旧库首次打开 182–222 秒（CPU 满载，页面最终可交互），可能是既有数据规模与启动对账导致；本轮未清理数据、未定位到具体阶段，需单独排查。
- 手机端模型与检索能力未验证：不跨端搬运 Key，手机未配置 Provider；L1/L2、搜索、DOCX/图片导入仅平板侧有证据。
- 异常与失败路径（空资料、坏文件、断网、权限拒绝、模型失败、后台回收）本轮未取证，沿用既有 spec 结论，不能视为本次已通过。
- 较大字体/系统字体缩放、分屏（多窗口）未在两端实测；平板窄窗用自由窗口验证，不等同系统分屏。
- 模拟器平台能力与 ARM 平板真机不能互相替代；真实平板、应用市场分发与跨设备同步不在本轮结论内。
- 两个模拟器共用 `127.0.0.1:5555`：同一时间只能运行一个实例；切换时若 hdc 未就绪，需等待其重新注册（本轮最长约 80 秒）。
- 布局参数（840vp Embed、240–280vp 侧栏、640/720/840/960vp 内容上限、480vp 紧凑标签）为本机设计值，按当前截图确定；后续调整需同步更新 `ResponsiveLayoutPolicy` 与 8 条宿主用例。
