# 06 设备直连模型与连接验证

> 状态：debug 已实现待验收。当前模型路径为设备直连 DeepSeek；Windows 网关为独立子项目。

## 1. 用户流程

1. 在应用 API Key 管理中配置 DeepSeek Key，启用真实助手。
2. 启动会话完成本机资源与 Provider 装配，正常发送问题或使用已授权工具。
3. 退后台、停止或销毁时关闭活动会话；返回前台不自动续跑旧任务。
4. 调试连接检查可核对 MCP 握手与工具目录；启动检查只验证装配，不作为真实任务执行证据。

## 2. 页面事项

复用现有 Key 输入、启动、就绪、忙碌、取消和失败提示。不开启真实模式时保留演示模式。连接探针、启动检查、模型请求与工具执行分别反馈结果。

## 3. 业务与 Agent 事项

应用通过 `DeepSeekModelTransport` 和生产 Runtime 装配直连服务，工具统一由 Registry、参数校验、授权、预算、持久化派发和结果记录约束。页面使用应用会话端口，不直接创建 Provider 或读写执行库。

供应商响应、模型输出、tool_calls 和用量均经运行时校验。错误保留可理解原因和定位信息，不用默认账单、假结果或 Mock 回退伪造成功。

普通助手、知识库授权、联网搜索、日程与文档工具分别见相应功能 spec；[接口边界](../docs/integration/agent/接入与边界.md) 说明宿主职责。

## 4. 平台能力与隐私

复用既有网络权限、HTTPS 传输、安全凭据和加密 RDB。持久化 Key 使用系统安全存储；会话缓冲消费后清零，关闭时释放资源。

设备直连不要求运行 Windows 网关。主仓库保留网关源码、固定来源与独立测试，见 [网关部署](../docs/deployment/Windows模型网关.md)。目标 OpenHarmony 设备兼容性仍待确认。

## 5. 验收方式

| 路径 | 验收重点 |
|---|---|
| 正常 | 启动、普通回答、连续工具调用、用量记录与关闭 |
| 异常 | 无网络、服务错误、响应不合法、数据库打开失败、取消和迟到响应 |
| 授权拒绝 | 未启用或撤销工具授权不派发；连接检查不能执行任务 |
| 模型失败 | 空回答、超时、非法 JSON / tool_calls / 用量，不伪造成功 |

Host 用例在 `entry/src/test/run-direct-model-tests.cjs`，启动/网络探针与真实服务测试分开取证。已有模拟器真实调用反馈见 [进度与验收](../docs/08-项目进度与验收.md)；正式发布、账单与真机不据探针通过认定完成。
