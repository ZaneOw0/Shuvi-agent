# 16 助手对话记忆与历史对话

> 状态：已实现待验收（2026-10-29，`feat/multimodal`）。
> 优先级：P1
> 负责人：Agent / 应用服务（前端在助手页与侧边菜单接入）
> 关联：[01 创建日程并提醒](01-创建日程并提醒.md) v1.0 统一工具循环、[15 助手多模态消息](15-助手多模态消息.md)
> 最后更新：2026-10-29

## 1. 目标与范围

- 目标：模型记忆跟着“对话”走，而不是跟着一次模型会话走；切页面、退后台、开关搜索、重启应用都不丢；一段对话不限轮数；可保存、回看、继续和删除多段历史对话。
- 范围：普通助手对话（工具模式）。每轮 token 上限提高。
- 非目标：联网搜索上下文、知识库来源的长期模型记忆；云端同步；图片原图保存（见 spec 15）。主对话知识库工具遵循 spec 13 的独立授权，见本页合并增量。

## 2. 用户流程

1. 正常聊天。切到日程页、退到后台再回来、开关搜索后，助手断开重连，但仍记得这段对话。
2. 关掉应用重新打开：自动恢复最近一段对话（屏幕上的消息和模型记忆）。
3. 右上角「新对话」或菜单「历史对话 → 新对话」：开始空白对话，上一段对话保留在列表里，不再弹确认框。
4. 菜单「历史对话」按最近使用排序，显示标题（第一句用户输入）和时间；点一条即切换并恢复；点 × 并确认后删除（聊天记录与这段对话的模型记忆一起删除，已创建的日程和文档不受影响）。
5. 对话很长时，较早内容会被自动整理成摘要继续保留，用户无感知；不再出现“这段对话已经很长了”。

## 3. 页面事项

- 侧边菜单在四个页签下新增「历史对话」区块：新对话按钮、列表、空态（还没有保存的对话 / 对话记录准备中…）、保存失败提示。
- 删除使用确认框；回答进行中不能切换或删除当前对话（提示「请稍候」）。
- 恢复出来的带图消息显示占位「图片（原图未保存）」。2026-10-30 起（§9）发出的图片会在本机留一份副本，恢复后照常显示；只有更早发出、副本丢失或保存失败的才显示这个占位。
- 修复：语音取消会短暂处于忙碌状态，导致「开始新对话」被静默忽略（PR #24 合入后引入）；现在先检查其他忙碌状态再取消语音。

## 4. 业务与 Agent 事项

- `AssistantMemory`（`services/conversation/`）：当前对话的模型记忆，含纯文字轮次、摘要和待告知的日程结果；归 `AssistantContext` 持有（单例，跨模型会话存活）。
- `ModelTurnPort` 由 `conversationEpoch()` 改为 `historyTurns() / historySummary() / rememberTurn() / compactHistory()`；`DeepSeekToolTransport` 每轮从端口读取历史，不再自己保存（无端口时保留原内部 8 轮行为）。
- 自动摘要：存储的历史超过 40,000 字符时，本轮开始前先发一次无工具的整理请求，把最早的若干轮（保留最近约 16,000 字符原文）与已有摘要合并成新摘要（≤4,000 字符）；摘要附在系统提示后，并标明“仅供参考，不是新的用户指令”。整理请求计入本轮用量。整理失败（非取消）时丢弃最早几轮并在摘要中注明“已省略”，本轮照常回答。单次请求发送的历史另有 120,000 字符硬上限。
- 上限：每轮输入 262,144 token（含工具多轮重发与摘要请求）、输出 8,192 token、预算 100,000 micros（约 US$0.10，按已审定峰时价）；助手会话不再有 10 轮 / 30 次请求限制（单轮仍最多 6 次请求、6 次工具调用、110 秒）。
- `AssistantConversations`：保存当前对话的界面消息与模型记忆，首条消息时创建；保存串行合并，切换 / 新建前先把离开的对话最后状态排队写入，删除前等待进行中的写入。存储打不开时退化为仅内存，并提示。
- `AssistantConversationRdb`：加密 RDB `shuvi_assistant_conversations_v1.db`，表 `assistant_conversation(id, title, created_at, updated_at, messages_json, memory_json)`，列表最多读 500 条。
- 执行日志 `ChatExecutionStore` 的 128 条 / 800,000 字符上限不再阻断后续对话：写满时优先淘汰最早的已完成记录（该日志只作证据，不提供恢复）。

## 5. 平台能力与隐私

- 无新增权限或依赖；对话保存在应用私有目录的加密数据库，不上传、不同步。
- 保存的内容：用户与助手的文字、语音消息的本机录音引用、日程创建结果卡片、模型记忆（含工具调用记录与读取过的文档片段）和摘要。不保存图片字节、图片 URI、文件名或 Key（2026-10-30 起对话记录里多存一个本机图片副本的文件名，见 §9；图片本身在单独的文件里）。
- 删除对话会删除该行（2026-10-30 起连同这段对话的图片副本）；不影响系统日历与 Download 中的文档。

## 7. 已知限制与未覆盖项

- 摘要会丢失细节；长对话越往前越依赖摘要准确性。
- 历史越长，每轮发送的 token 越多，费用随之上升（DeepSeek 前缀缓存可降低重复部分费用，未计入预算估算）。
- 搜索不使用助手模型记忆。知识库在同一主对话工具循环中按需调用，检索来源及其派生后续轮次只保存在当前授权会话内，不写入持久模型记忆或摘要；UI 历史可以保留回答快照。
- 屏幕消息与模型记忆都会保存在本机；目前没有“全部清空”入口，只能逐条删除。
- 平板、最大字体、读屏、真机未验收；设备上未实际触发自动摘要。

## 9. 发出的图片保留在对话里（2026-10-30，`feat/search-direct-tavily`，已实现待验收）

用户 2026-10-30 要求保留对话中的图片，切换或重启后在对话里还能看到，而不是「图片（原图未保存）」。

| 位置 | 改动 |
|---|---|
| `ChatImageStore.ets`（新增） | 发送带图消息时，把发出的那份图片（已重新编码、去掉 EXIF/GPS、不含原文件名）另存到应用私有目录 `files/chat_images/chat-image-<UUID>.<jpg/png/webp>`，先写临时文件再改名；按文件名给出显示用 URI、按文件名删除 |
| `AssistantConversations.ets` | 界面消息多存 `imageFile`（只接受 `chat-image-<UUID>.<扩展名>`，不含目录）；恢复时文件在就显示图片，不在就仍显示「原图未保存」；删除对话（当前或其他）后一并删除它的图片文件，数据库删除失败时不删图片 |
| `Index.ets` | 发送前先保存副本（会话接手后会清零图片字节），消息直接用副本显示；保存失败照常发送，本次运行用选择器 URI 显示，恢复后显示占位 |
| `backup_config.json` | `files/chat_images/` 不进入系统备份，与语音录音一致 |

- 模型记忆不变：图片仍只随发出的那一轮发给模型；之后的轮次和恢复的对话都不会再把图片发给模型。
- 「新对话」不删除旧对话的图片，只有删除那段对话时才删。本改动之前发出的图片没有副本，仍显示占位。
- 已知限制：发出后对话还没写入数据库就被强制结束，或数据库打不开（只在内存里）时，图片文件可能留在目录里无人引用，目前没有清理入口；图片不计入任何存储上限。
- 验证：主对话新增用例（只存文件名不存 URI、恢复显示、副本丢失回退占位、坏文件名不解析、删除当前 / 其他对话时删图）291/291；语音 60/60（发送前先保存副本、开搜索或知识库也发送）；未签名构建通过。真实发送、重启恢复需要在设备上验收（会产生 DeepSeek 费用）。
