# 08 设备直连模型与连接验证

> 状态：已实现待验收，v0.1；2026-10-23 用户选择设备直连方案，当前仅有 HarmonyOS 模拟器。
> 优先级：真实 Agent 接入前置。
> 负责人：UX 实现应用适配与调试入口；Agent、平台负责人共同审核生产装配与目标设备能力。
> 关联需求：[项目总览](../docs/00-项目总览.md)、[Agent 接入](../docs/06-Agent模块接入.md)。
> 最后更新：2026-10-23。

## 1. 目标与范围

- 设备通过 HTTPS 直接访问 DeepSeek，模型连接不再必须经过 Windows Local AI Gateway。
- 提供实现既有 `ModelTransportPort` 的应用适配器，以及接受所选 Provider 的后端装配函数；上游模块的源码与公共契约保持原样。
- 提供一个仅在 debug 构建显示的固定问题测试入口，先验证设备网络与凭据。
- 本轮不切换首页 Mock，不实现完整 Agent 搜索、凭据持久化、团队 Key 分发、流式输出或新的部署服务。Windows 网关继续作为可选方案保留。

## 2. 用户流程

1. 运行新 debug 版本，进入「我的 → 模型直连 · 调试」。打开页面不会请求模型。
2. 用户从自己的控制台核对准确模型标识，在应用内填写个人 API Key；不要把 Key 发给 AI、组员或写入仓库。
3. 阅读用途和计费提示后，点击「同意发送一次测试」。只发送 `Reply with exactly OK.`，非流式，关闭思考，最多输出 64 tokens；不附带聊天记录、资料或工具。
4. 校验 HTTP 状态、响应结构、模型标识、token 用量及结束原因；仅完整返回 `OK` 才显示直连测试通过。
5. 失败时显示不含供应商原始正文的错误类别。用户重新填写凭据后可以手动重试；不自动重试。
6. 停止、离开页面或应用进入后台均取消本地请求；迟到结果不显示成功。进程终止后不续跑。

## 3. 页面事项

- `DirectModelCheck.ets` 是「我的」中的独立调试卡片；release 不显示，服务层也拒绝 release 测试调用。
- 状态：未发送 → 正在请求 → 通过 / 失败；请求中允许停止，禁止重复提交。取消结束前保持忙碌。
- 密码输入保留系统菜单，支持用户主动粘贴；`CopyOptions.None` 禁止复制/剪切，仍支持粘贴和全选。禁用预览和自动填充；提交、离开页面、进入后台时清空输入。请求执行期间 HTTP 层仍需在内存中持有凭据，不能据此声称内存已安全擦除。
- 没有 Key 的文件存储、日志、偏好设置或测试报告；状态对象不保存 Key、模型回答或原始错误正文。
- 输入和状态带无障碍文本。最大字体、读屏和实际键盘遮挡效果待模拟器/设备验收。

## 4. 业务与 Agent 事项

### 4.1 实现分层

| 文件（位于 `entry/src/main/ets/services/model/`） | 职责 |
|---|---|
| `DeepSeekProtocol.ets` | 模型配置、请求编码、响应运行时校验、实现 `ModelTransportPort` |
| `DeepSeekHttpClient.ets` | 原生 HTTPS、绝对超时、响应字节上限、释放与取消 |
| `DeepSeekProvider.ets` | 复用 `ProviderCatalog`、`ProviderOperationRunner` 与 `GenericModelProvider`；凭据由已有端口取得 |
| `ShuviModelBackend.ets` | 注入选定 Provider，复用带恢复能力的生产 Runtime 与搜索工具准备器 |
| `SessionModelCredentials.ets` | 仅当前会话持有 Key，限定 Provider/作用域，关闭时清理拥有的字节缓冲 |
| `AgentHostDigest.ets` | 原生 SHA-256 摘要，供 Provider、授权绑定及快照校验复用 |
| `AgentRdbResources.ets` | 两个独立加密 RDB 的打开、恢复、失败回滚与关闭；代理现有持久化/恢复端口 |
| `ShuviDeviceHostResources.ets` | 将真实资源绑定到后端端口；构造和绑定均不打开数据库或网络 |
| `SessionModelHttpClient.ets` | 跟踪当前会话模型请求，停止时统一取消并隔离迟到响应 |
| `ShuviRuntimeSession.ets` | 组合实际 Provider 与后端，管理启动/停止及资源收尾，转发任务/授权/取消 |
| `ShuviRuntimeController.ets` | 前台启动门控、会话代次隔离、页面事件订阅与停止失败保护 |
| `ShuviRuntimeService.ets` | 单 Ability 应用的会话控制实例；Ability 回调接入，不自动创建生产配置 |
| `DirectModelCheckSession.ets` | 一次固定测试的状态机；不伪装成 Agent 任务 |
| `DirectModelCheckService.ets` | 调试会话和应用生命周期入口，导出 Provider/装配函数 |

生产调用方向：`应用宿主 → createShuviModelBackend → Runtime → GenericModelProvider → DeepSeekModelTransport → 原生 HTTPS`。

调试调用方向：`DirectModelCheck → DirectModelCheckSession → 原生 HTTPS → 共用响应校验器`。它没有装配生产 Runtime，不是完整链路的验收替代品。

### 4.2 配置与生产接入要求

`DeepSeekProfile` 的模型标识、版本、区域、输入/输出上限、质量等级和隐私类别须依据实际服务填写，默认不可用。不得把网关别名 `aigw/default` 当作供应商模型标识。

模型版本是宿主登记的能力版本；HTTPS 响应只核验实际 `model` 字段，不能证明供应商后台权重未变化。模型别名或能力变化后须重新核对版本与价格。

`createDeepSeekProvider(profile, price, digest, credentials)` 要求匹配的非零价格快照和真实摘要/凭据实现。凭据范围为 `deepseek.invoke`，只接受一个 `Authorization: Bearer …` 头，不转发附加头。

`GenericModelProvider` 按快照估算/结算预算；上游接口仅支持一个输入单价，应审核保守价格及生效时间，不能把估算当作供应商实际账单。缓存命中、折扣及取消后的实际费用以供应商记录为准。

`createShuviModelBackend(config, ports, registered, provider)` 仍要求真实 credential/execution/memory 宿主资源、ID、持久化与恢复端口、MCP manager/adapter/registry、摘要及策略。构造函数不启动网络；由 Ability 持有后端并按其生命周期启停。不能用空 `open()` 或测试授权策略填充生产资源。

### 4.3 协议边界

- 固定请求 `https://api.deepseek.com/chat/completions`，不允许自定义地址或跟随重定向。
- `stream: false`、顶层 `thinking: { type: 'disabled' }`；结构化请求启用 `response_format: { type: 'json_object' }`，并要求 system/user 提示词包含 JSON。
- 支持 system/user/assistant 文本，不接图片或供应商原生 tool calls。结构化响应必须是 JSON 对象；具体 Planner schema 继续由既有 Planner 校验，传输层不宣称通用 JSON Schema 验证。
- 只接受单条 assistant choice；验证模型、finish reason、非空文本和非负整数用量总和。截断响应不暴露为可用结构化输出。
- 401、402、403、429、参数失败、服务失败分别映射为安全错误。无效 UTF-8、畸形 JSON、字段不匹配及超限均失败，不能用默认内容替代。

### 4.4 真实宿主资源（2026-10-23）

新增资源组合已实现，可由 `createShuviDeviceHostResources(context, recovery)` 创建，再通过 `bind(ports)` 接入原有 `createShuviModelBackend`。同一个资源组合只能绑定一次，禁止覆盖调用方已提供的资源。调用方仍须配置实际模型、价格、预算、MCP、身份和策略；本轮没有从 Ability 自动创建生产后端，也没有切换首页。

生命周期由既有 `SingleAgentHostRuntime` 负责：会话凭据 → 执行库 → 记忆库 → MCP → Runtime；失败按相反顺序回滚，退出时先关闭 Runtime，再关闭资源。数据库关闭会等待本资源已经接受的持久化调用；关闭开始后拒绝新调用。并发打开/关闭复用正在执行的操作；关闭失败保留句柄所有权，禁止重新打开，须先完成清理。

| 资源 | 数据与边界 |
|---|---|
| 会话凭据 | `configure(Uint8Array)` 消费并清空调用方字节数组；拒绝空值、空白/控制字符、非 ASCII 或超过 4096 字节。仅打开状态允许 `deepseek-direct` / `deepseek.invoke` 读取；不落盘、不进入 DTO 或日志。关闭清空拥有的缓冲；已经创建的 HTTP 头字符串不能保证被安全擦除，因此仍须先停止请求。活动会话不能原地换 Key |
| 执行库 | `shuvi_agent_execution_v1.db`，复用 `RdbSnapshotBackend`、`DurableExecutionRecoveryStore.openForRuntimeRecovery`、`RuntimeExecutionRecoveryBridge`；快照 schema 为上游 `1.2` |
| 记忆库 | `shuvi_agent_memory_v1.db`，复用 `RdbMemorySnapshotBackend`、`DurableMemoryStore` 和 `RuntimeMemoryContextAdapter`；schema 为上游 `1.0`。本轮仅提供读取上下文的入口，过滤其他 owner、敏感记忆和原始个人轨迹；不是已经接入 RAG 数据 |
| 加密与升级 | 两库使用 S3、`encrypt: true`、`persist: true`，由系统管理默认加密密钥；专用库名不得用于创建明文库。库名中的 `v1` 是宿主命名代际，不等于快照 schema。不修改既有知识库数据库；损坏/未知 schema/打开失败均拒绝启动，不删除、不重建、不回退为空数据。尚未配置跨 schema 迁移器 |
| 摘要 | 原生 SHA-256、UTF-8、64 位十六进制。普通摘要用于一致性检查，不是带密钥的真实性证明。上游端口为同步接口，本版单次限制 2 MiB，超限报错而非截断；大量历史快照的性能与执行线程仍需在设备验收，不能据 host 测试宣称 UI 无阻塞 |

恢复配置必须提供明确 `ownerId`、`policyVersion`、正数租约时长和实际 `RuntimeOutcomeAccountingPort`；没有工具用量依据时返回不可结算，不能填零表示免费。已确认的人工对账还需要明确的 settlement 实现。资源组合不会自动执行模型、搜索或恢复旧任务。

上游 `AgentApplicationBackend.onBackground()` 只标记后台状态，不会停止任务。应用采用第 4.5 节的会话控制，后台关闭整个本地会话，不仅转发上游后台回调。

### 4.5 应用会话启停与结果隔离

`createShuviRuntimeSession(config, ports, resources, profile, price)` 构造真实 Provider 和后端，仍要求完整实际配置，没有默认模型价格、预算或搜索地址。工厂每次创建新的资源组合、MCP manager 和后端，不复用已停止的实例。调用 `ShuviRuntimeService.session.start(factory, keyBytes)` 才启动；Key 由凭据资源消费，启动拒绝或配置失败也清空传入缓冲。工厂构造阶段不得持有 Key 或执行 I/O。

| 触发 | 行为 |
|---|---|
| Ability 前台 | 仅允许后续手动启动；不自动创建、恢复或重新请求 |
| 明确启动 | 同一时间只允许一个会话；完成后进入 READY。配置/启动失败先收尾；清理成功后可手动提供新配置重试 |
| 后台 / Ability 销毁 / 主动停止 | 立即禁止页面新命令和旧事件回写；取消当前会话 HTTP、撤销 Key 后续读取、清空授权预览，并断开 MCP。等待进行中的启动结束后关闭 Runtime 和数据库，再次清理迟到连接与预览 |
| 启动途中退后台 | 即使迟到启动成功也不暴露 READY；资源继续收尾。关闭完成前不能启动另一个会话 |
| 返回前台 | 停留在停止状态；需用户再次手动配置 Key 并启动，不能自动续跑旧任务 |
| 关闭失败 | 进入 BLOCKED，保留会话引用，拒绝新的启动；不以清空状态或打开第二套数据库伪造清理完成。仅显示固定安全错误，后续需排查或重启进程 |
| 旧请求 / 订阅迟到 | 按会话代次丢弃结果，迟到订阅立即关闭；停止时关闭当前订阅。旧授权、澄清提示不能进入新会话 |

页面服务入口已提供 `submit`、`authorize`、`cancel`、`getTask`、`subscribe`。批准搜索仍通过实际参数预览复核；取消成功清理对应预览。后台期间所有入口均拒绝调用。`EntryAbility` 已接入前台/后台/销毁回调，保留 RAG 与调试入口原有生命周期；错误日志只记录固定分类，不打印 Key、请求或上游正文。

会话停止与“每个任务已取消”“供应商未计费”不是同一结论：已经发出的请求可能到达服务端，工具结果可能需要恢复/对账。HTTP 取消保留 `operationStarted`，不假定免费；Runtime 立即关闭会中断规划，任务的业务终态以实际记录为准。进程被系统直接回收时不能保证执行 Ability 清理回调。

**当前边界**：生命周期回调及会话服务已接线，首页仍为 Mock。后续已增加第 4.6 节的启动检查入口，仅验证实际宿主装配；任务预算、工具费用结算及首页任务/授权/澄清/回答渲染仍待完成，不能把启动成功当作手机端到端流程完成。

### 4.6 手动启动检查入口（2026-10-23）

调试包“我的”页新增 `RuntimeStartupCheck`，使用 `RuntimeStartupFactory` 创建真正的加密 RDB 资源、Provider、MCP manager、受控工具目录与生产 Runtime。打开页面没有 I/O；明确点击“同意连接并检查启动”后才打开数据库和发现工具，完成后显示“启动检查通过”，并注明没有校验 Key 或执行任务。离开本页、关闭会话、退后台都执行会话清理；回到前台不会自动启动。页面订阅状态而非轮询，后台即使没有活动会话也清空未提交的凭据。

这是宿主启动验收入口，**不是已开放的真实搜索聊天**。`StartupOnlySession` 明确拒绝全部任务命令，工具 grant 校验器默认拒绝；搜索缺少用量收据时 `UnsettledSearchAccounting` 返回 `undefined`，不会以零费用结算。前端任务预算保持禁用。恢复记录只按既有恢复流程读取/归一化，不自动恢复执行，不删除用户数据。该入口可填写 `startup-check-only` 等非敏感测试值，无需真实 Key；凭据资源仅检查格式，不能据启动通过声称鉴权通过。

固定配置便于首轮排错，不开放任意模型/端点：

| 配置 | 当前值与含义 |
|---|---|
| 模型 | 用户已确认的 `deepseek-flash`；能力版本 `DeepSeek-V4.1-Flash-1017`，启动时不发送模型请求 |
| 本地上限 | 输入 32768 / 输出 2048 tokens；Planner 估算输入 8192、记忆最多 2048 字符、3 步、30 秒。这是应用保守上限，不是供应商最大能力 |
| 模型估价 | USD，每百万输入 300000 微元、输出 1200000 微元；按峰时/缓存未命中估算，不是账户账单。快照日期为核对日期，不宣称供应商价格生效日 |
| 搜索 | `http://127.0.0.1:8787/mcp`，只允许 debug 本机连接；可以使用 `start:discovery` 模式，不加载 Tavily Key |
| 搜索估价 | basic 搜索每次 8000 USD 微元，按 PAYG 估算，不代表账户套餐或免费额度；未用于实际结算 |
| 身份/策略 | 本应用本机 owner `shuvi-local-owner-v1`、`shuvi-startup-check-v1`；这不是登录账号或多用户隔离方案 |
| 区域 | `provider-managed` 是路由标签，不是地域或数据驻留保证；当前 Profile 只登记 PUBLIC |

价格与能力依据（2026-10-23 核对）：[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)、[Tavily Credits & Pricing](https://docs.tavily.com/documentation/api-credits)。正式开放任务前必须重新核对配置、设置用户可理解的预算，并接入真实授权验证与费用结算；不得仅移除检查入口的拒绝逻辑。

## 5. 平台能力与权限

- 使用已有 `ohos.permission.INTERNET`，没有新增依赖、权限或云服务。API Key 在设备内手动输入，仅用于用户发起的测试；正式凭据存储仍待平台装配。
- 本机依据：DevEco Studio `26.0.0.821` 配套 API 26 SDK 的 `@ohos.net.http.d.ts`；`requestInStream` 标记 since 10，`maxRedirects` 标记 since 23，设置为 0 禁止重定向。使用系统 TLS 校验，不关闭证书校验。
- HTTPS 响应通过分块接收实现大小限制，这不等于模型 token 流式输出。响应流必须收到结束和状态才完成，并使用绝对计时器限制整个请求。
- 调试连接/总超时为 10/30 秒，响应上限 64 KiB；生产 Profile 默认请求 1 MiB、响应 2 MiB，总超时由 Runtime 指定且上限 180 秒。
- 停止会销毁本地 HTTP 请求，但无法保证供应商尚未执行或未计费。每次用户点击都是新请求，无自动重试、无后台续跑。
- 目前用户只有 HarmonyOS 模拟器；未确定 OpenHarmony 发行版、API 和设备。正式移植前必须核对网络、TLS、输入控件及导入 Agent 存储接口的兼容性，不能直接把 API 26 构建称为 OpenHarmony 验收。

官方协议依据（2026-10-23 核对）：[Chat Completion](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON 模式](https://api-docs.deepseek.com/guides/json_mode/)、[错误码](https://api-docs.deepseek.com/quick_start/error_codes/)。SDK 声明的本机位置为 `sdk/default/openharmony/ets/api/@ohos.net.http.d.ts`。

宿主资源依据：安装的 API 26 SDK `@ohos.data.relationalStore.d.ts`（`getRdbStore` since 9、异步 `close` since 12）和 `@ohos.security.cryptoFramework.d.ts`（`createMd` since 9、`updateSync` / `digestSync` since 12）。系统能力分别为 `SystemCapability.DistributedDataManager.RelationalStore.Core` 与 `SystemCapability.Security.CryptoFramework.MessageDigest`，本次未新增权限或依赖。官方参考：[RDB 获取与配置](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-arkdata/arkts-apis-data-relationalStore-f.md)、[Crypto Framework](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-crypto-architecture-kit/js-apis-cryptoFramework.md)。加密配置不能把既有明文库自动转换为密文；本功能使用独立新库名，仍需设备验收。

## 6. 验收方式

| 路径 | 用例 | 预期结果 | 当前证据 |
