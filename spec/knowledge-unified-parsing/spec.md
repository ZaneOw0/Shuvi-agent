## Overview

将现有TXT/MD、PDF、独立图片、DOCX的解析输出收敛为统一ParsedDocument。下游知识库通过该结构保存正文、结构化块、图片资产和解析身份，不再依赖特定解析实现或要求DOCX正文必须与原件逐字对应才可入库。图片、公式及未知对象不能静默消失；来源不足明确标记，不伪造原生位置。

导入默认自动发布可用正文/OCR关键词，并在视觉/文本嵌入设置已启用时自动生成图片描述和tags、完成全部合格文本的向量入库。查询先展示正文/OCR Direct，同时展示本机tags；获准语义查询时仅生成一次问题向量，在统一空间检索正文与图片代理文本。结果分两组独立加载分页，同图跨路合卡，语义失败不撤销已有本机结果。

### 已确认决策

1. 本轮接入现有四类：TXT/MD、PDF、独立图片（JPEG/PNG/静态WebP现支持范围）、DOCX。PPTX/XLSX未来接同一合同，不在本轮同时实现；统一结构不等于所有新格式已经支持。
2. 保留用户给定的六个核心信息：markdown、可选blocks、可选asset_dir、source_hash、parser_signature、engine。增加统一images资产引用和必要版本/来源/覆盖状态；asset_dir为本机目录，不能代替图片身份。结构化块支持文字、图片、公式、表格及未知占位，缺结构化产物时明确说明，不能补造定位。
3. 解析器Markdown/结构化块是入库内容；OOXML/PDF原生校验留在上游适配器作来源增强与覆盖提示，不再是正文逐字对应硬门禁。不能因部分原生锚点缺失丢弃服务已提取正文，亦不能把未知来源伪造成已核原文。
4. 解析基本结构/资产关联通过即自动发布正文/OCR关键词；报告用于查看限制和恢复，不要求每文档人工确认覆盖后才可用。明显无效产物仍失败，未知/缺失图片等应保可见状态和可用正文，不假完整成功。
5. 每张独立或提取图片形成可检索图片条目并保留父文档/原位置。各格式解析出的图片需独立落盘成受管资产，不能仅留在原件/ZIP或内存中计算hash；原件图片和服务派生图片的区别与关系如实记录。
6. 视觉服务固定本轮DeepSeek的deepseek-flash，用户给定Chat Completions接口文档已只读核查：当前文档列出该模型、image_url图片内容块、JPEG/PNG/GIF/WebP和JSON输出模式。此为文档依据，非账号可用性、费用、隐私或识别质量实证；不因此扩大应用静态图片范围，不调用服务探测。
7. 设置中一次配置并启用视觉服务，明确导入图片发送范围、接收方和可能费用；之后导入默认自动处理，不逐图弹授权。默认发送当前已落盘图片及固定任务提示，不附整篇文档、图注上下文或聊天内容；输出中文描述和中文为主的自由tags，专名可保原文，不增加受控分类体系。
8. OCR复用既有解析结果，独立保存，不额外请求一次OCR。图注、OCR、模型描述、自动tags和用户修正分栏，不把AI描述冒成原图文字；无字图片照常通过描述/tags参与检索。
9. 文本嵌入也采用设置级自动完整入库：一次启用并确认接收方、实际输入类别、自动处理及可能费用后，导入自动处理全部合格正文/OCR及描述＋tags，不再强制前三块试验/逐批确认。保进度、暂停恢复和有限失败处理，不将部分成功标全量就绪。
10. 自动描述/tags可编辑、删除；用户修正/删除记录独立，重跑不覆盖修正或复活已删tag。当前有效文本与向量版本绑定，旧向量不能冒当前编辑后的语义结果。
11. 本机批量迁移旧快照/已收ZIP，生成统一结构、提取可恢复图资产及待嵌入文本；保旧wire/hash/索引/向量继续可读，不自动云外发。历史视觉和统一空间重嵌入由一次明确的批量升级操作触发；缺原件/包明确列失败，不自动重新解析。
12. 正文和图片语义必须同一次查询：进入经确认的新统一文本空间，不能因模型/维度相同就混旧空间。一次问题嵌入供该空间全部候选和分页复用；未升级覆盖明确提示，不混旧距离、不自动多发问题向量。
13. 第一组只有正文/OCR Direct；第二组为本机tags、正文语义及图片语义，命中原因分别标注。即使有Direct，用户允许时第二组仍执行一次语义查询；描述不混入OCR Direct。两组独立状态/分页，语义失败不清Direct或tags。
14. 同图按图片字节hash＋有效标注版本合卡：OCR Direct图片优先留第一组，迟到tags/向量原因追加，不在第二组重复；只tags/语义命中的图归第二组。保全部父文档来源，跨分页也去重，不做感知相似图合并，不强合不同有效用户标注版本。
15. 批准新执行档案/feature指针与逐阶段评审，之后实现、保数据构建部署。不新增权限/依赖/Native/无关服务，不清库卸载强签或Git写。DeepSeek作为用户明确选定的新视觉接收方，在独立设置中配置；已有解析/嵌入Key不读取或代填。
16. 本轮Agent真实外发初始全部0。视觉、嵌入、查询测试的样本/接收方/费用/参数/次数在任务阶段分别批准；默认产品流程不等同授权Agent现在发送历史全集或用户资料，不继承旧测试额度。

## User Scenarios & Testing

### 用户故事1：通过统一解析结构完整保存内容和图资产（P1）

**价值**：无论文件由哪个解析器处理，下游得到相同合同，正文不再因格式专属硬门禁被丢弃，图片资源可长期关联。

**独立测试**：四类自制输入或受控解析产物进入同一消费端，核统一字段、内容顺序及实际落盘图片，无需真实模型。

**验收场景**：

1. 四类入口均输出统一ParsedDocument，正文、块、原件hash、解析器签名和engine可核；知识存储/分块/索引不分支调用PDF/DOCX解析内部实现。
2. PDF/DOCX结果images及独立图片成为本机受管图资产；统一images能打开实际文件、核hash/类型/大小，保父文档、块和原件关系。缺失或不支持图格式保明确占位/原因，不冒已落盘。
3. 结构化块保阅读顺序，公式保实际可用文本/LaTeX/图像表示或明确未支持占位；图片/公式纯对象段落不能因普通文字为空而消失，不猜公式内容。
4. Markdown存在但blocks缺失时，统一适配器提供明确文字投影及结构未知状态；未知content_list字段不能动态猜类型或创造原生坐标。
5. 原生页/段落/cell证据可增强来源，但不能因服务文字和OOXML换行、格式或字面对照失败就排除整段。无法精确定位时显示文件/块级来源和限制。

### 用户故事2：默认图片理解、可编辑标注与自动完整入库（P1）

**价值**：一次设置后，用户导入即可获得可查文字和图片，无字照片也有可检索代理文本。

**独立测试**：受控视觉/嵌入端口核设置生效、队列、文本来源、缓存与失败隔离；真实DeepSeek质量及费用另验。

**验收场景**：

1. 视觉和嵌入分别一次明确开启并确认输入范围/可能费用后，导入默认处理获准当前图片和全部合格文本，无逐图/逐三块确认；未配置/关闭时保存基础内容，显示对应待处理而非假完成。
2. DeepSeek仅收到当前图片与固定描述/tag提示，输出经校验保存为自动结果；OCR/图注不被覆盖，不虚构confidence或内容。无字图片仍生成描述/tags；图片理解失败不阻正文/OCR关键词。
3. tags建立本机关键词索引，描述＋tags生成文本向量并绑定实际图像/标注版本；正文/OCR和图片代理文本进入相同新统一空间，全部目标读回核验后才就绪。
4. 导入重入或重启复用匹配图hash/模型/提示词版本的有效结果，保队列进度、暂停/恢复；未知请求不盲重发，失败项明确，不能导致已可用文档回滚。
5. 用户编辑/删除描述或tags后，当前标注及本机索引更新，旧向量资格失效或准确待更新；已启用流程可为新有效文本排队，重跑不覆盖用户修正或恢复已删tags。
6. 更换接收方/模型/费用条件需重新确认设置，不暗中发送到新服务；关闭自动处理停后续请求，但本机已有有效快照、原图、OCR和tags仍可用。

### 用户故事3：批量本机迁移与显式历史升级（P1）

**价值**：兼容现有资料，又不因新模型结构触发不可控整库外发或旧知识丢失。

**独立测试**：隔离旧Text/Pdf/Image/Docx快照及包，迁移中断/缺资产/重跑后核身份、旧数据及网络计数。

**验收场景**：

1. 本机迁移读取旧快照和已收包，保存统一内容及可恢复图片，逐文档记录完整/部分/失败，0视觉/嵌入/解析请求；已封存旧wire/hash不改写。
2. 旧索引和向量在升级完成前保持可读，不能复制旧向量到新空间假兼容。缺原件/ZIP明确说明并保旧可用记录，不清库或自动重新解析。
3. 用户显式启动已列范围的批量升级后，才按设置向视觉/嵌入服务发送历史图片和文本；可查看费用范围/进度并暂停，失败不改分母或销毁旧结果。
4. 新统一空间只对完成当前版本全覆盖的候选授资格；查询明确哪些资料尚未升级，迁移/升级恢复不重复消耗已确认成功输入。

### 用户故事4：一次语义查询、双组结果、失败隔离与全局合卡（P1）

**价值**：直接命中立即可看，图片标签及语义结果不会被Direct排他规则挡住，也不会多路重复刷屏。

**独立测试**：预置正文/OCR、tags、统一空间受控向量，通过延迟/失败/分页端口验证先后、一次请求和卡片身份。

**验收场景**：

1. 一次输入先展示正文/OCR Direct及真实字符高亮，同时第二组本机tags可立即显示；描述不伪装OCR，tag命中不冒原文事实。
2. 当前问题获准语义查询时，无论Direct有无，仅生成一次问题向量，在同一统一空间召回正文和描述＋tags候选；未允许、取消/改问题/改配置后不发送或不采纳旧请求。
3. 两组独立加载、独立分页，语义超时/鉴权/限频或其他失败只影响语义状态，已显示Direct和本机tags保留；翻页复用当前问题向量/候选会话，不再嵌入同问题。
4. 同图OCR/tags/向量召回按已确认身份合并一张卡，显示全部命中原因及来源；OCR Direct已显示图不再出现在第二组，迟到语义仅追加原因。跨页更新不重排或刷出重复卡，多个父文档来源不丢失。
5. 当前统一空间覆盖不足时准确提示尚未升级资料，而非混入旧空间距离或额外多发一次查询；服务失败不虚构无结果，历史显示真实路由和版本。

### 用户故事5：统一资产和知识生命周期（P1）

**价值**：新图片/自动任务/迁移不会破坏原件、已显示证据或旧资料，页面离开和删除都有明确结果。

**独立测试**：隔离存储和受控在途作业验证重开、换版、归档、共享图多来源删除与晚到回调。

**验收场景**：

1. 自动处理、迁移、来源阅读和查询都绑定当前文档/图资产/标注/索引版本；离页/后台按操作规则暂停/保存，不把取消等同云任务已删。
2. 删除某父文档不误删其他来源仍持有的图片/标注；最后引用释放后按所有权清理，失败留待清理，不假文件仍可打开。文档归档不自动重传或重算。
3. 原件/结果包/图片文件/统一快照及向量纳共享预算、资产读持有及备份排除，未知文件不清理；迁移或新版本失败保旧活动。
4. 历史保原文/OCR/AI描述/tag命中原因和来源版本，删除或编辑后明确旧版/失效；查看历史不自动外发、不在已删原图之外暗留未声明副本。

### 边界情况

图像资产相同不意味着OCR或人工标注一定相同，合卡须当前有效版本与全部来源可核；不感知去重相似照片。动态图片、未知图像编码、超资源输入仍按既有支持边界处理，不为视觉文档支持GIF自动扩App范围。失败视觉输出、截断JSON、无图片资产、无字OCR和未支持公式分别有状态；模型生成描述不等于人工核实事实。统一结构隐藏解析实现，但不能消除来源/覆盖/错误和授权边界。

## Requirements

### 页面事项

保现四个一级入口和V1/单Index，格式选择可保现入口但后续使用相同导入任务/内容审查/资产展示语义。报告改为可查看，不再每文档阻断自动关键词和嵌入；基础失败与增强失败分栏。独立视觉设置可配置DeepSeek/模型/凭据状态及自动处理/费用确认，文本嵌入设置有相应统一自动模式和暂停队列。图详情展示原图、OCR、图注、自动描述/tags、用户修正和失败原因，可编辑删除；图片/公式/未知对象保顺序和占位。

检索两组分离：正文/OCR直接命中；标签与语义候选。第二组有独立加载/错误/分页，tags不等待语义；同图合卡追加原因与父文档来源，第一组已显示图第二组不重复。模型描述或标签结果不能用“原文直接命中”标签。迁移页展示本机迁移与显式云升级的不同范围/费用/进度，缺缓存不自动重解析。不得新增回答生成/营销说明页或与任务无关视觉改版。

### Key Entities

ParsedDocument（六核心字段、统一block/images/版本及状态）、ParsedBlock（类型/顺序/实际内容/公式/图片引用/可选locator与来源可信程度）、ParsedImageAsset（实际文件及hash/类型/尺寸/父来源/原生或派生身份）、ImageKnowledge（独立OCR/图注/自动描述tags/用户修正/有效版本）、自动处理设置和费用范围、可恢复导入/视觉/嵌入队列、统一文本块和空间/向量资格、本机迁移回执/显式批量升级、双组查询会话/一次问题向量/独立游标、合卡身份/多路原因/父文档来源、统一历史和资产持有清理记录。

### 平台与非功能要求

沿现HarmonyOS/API26、phone/tablet、单entry/五层/V1、现INTERNET，无新增SDK/依赖/Native/后台权限。ArkTS采用具名类/接口承载统一结构，Python dataclass仅需求参考，不直接引入Python或任意dict运行时。保持当前原件大小、图片像素、结果/展开、共享派生及响应基本资源保护，统一预算/并发上限在设计中明确；不因加格式/图增强各重复分一份预算。图片原字节与派生文件均原子登记/读回，不静默转码覆盖原件。

视觉DeepSeek与已有解析/嵌入设置分用途/接收方，设置明确可能付费而非默认免费，每阶段可暂停/恢复；配置改变不暗用旧同意。上传图片用可控本机资产，不凭结果URL任意拉外链，不发送整篇文档。长处理异步，前台/离页/后台/进程结束各保可核状态，取消不冒云取消或资源硬停。真实测试每次capture留档，私图/OCR/原始响应/凭据不进入Git或公共日志，host/build/平台/服务/质量/UI/真机分报。

### 四类验收与完成界限

正常：四类统一结构/图片落盘→自动基础发布/视觉与全量嵌入→Direct/tags/一次语义→合卡/分页/来源。异常：缺图/坏包/缺blocks/未知公式/错误空间/缺向量/迁移中断，保部分有效内容与可见占位。拒绝：未启用/关闭视觉或嵌入、不允许当前语义、配置或费用改变，0相应未同意请求。模型失败：网络/鉴权/额度限频/服务/截断JSON/不合结构/幻觉描述分状态，不伪造成功或回滚Direct/tags。

真实视觉内容质量需独立样本/gold，JSON有效不证明描述正确；标签只作召回线索，不授权生成回答。统一结构与迁移源码/确定性测试、构建部署、真实平台/服务/正式UI/内容质量分别验收；没有真实请求许可不以fixture冒全链，但也不能把未完成适配解释为只差授权。

## Assumptions

现来源及向量/资产公共端口可作为迁移接点，但当前没有ParsedDocument或视觉服务，必须实际实现而非字段改名。PDF已有受管派生JPEG分片资产、DOCX尚仅媒体关系/hash、独立图有原件；统一images需补可消费的真实文件和保真/派生身份，不能把包存在等同图片已落盘。

用户指定DeepSeek文档已读取，只采用页面明确列出的模型/图片输入/JSON方向，不外推免费、零留存、账号可用或准确性。服务默认处理为产品设置级能力，本轮Agent没有真实外发许可。新的正文权威、自动处理及双组语义行为明确替代旧M2/M3/M4相应门禁；旧数据与历史批准记录不改写。PPTX/XLSX/受控分类、图像embedding、以图搜图、回答生成和同步本轮不实施。

禁止读取修改执行`scripts/paste-to-emulator.sh`、`spec/knowledge-emulator-e2e/`以及秘密/.local/signing/private/raw/生产库；后续若需实际本机迁移验证必须有准确样本/库scope许可，不能用调查现状的名义扫用户全集。
