# Feature Specification: 启动脚本 macOS 与 Windows 可用性

**Created**: 2026-10-13
**Status**: 阶段 1 需求审核中
**Input**: 修复现有启动脚本，只验证是否可使用；确保 macOS 与 Windows 运行兼容。

## Overview

修复仓库一键启动和日志脚本，使 macOS Bash 与 Windows Git Bash/cmd.exe 入口能够正确解析带空格的模拟器名称，锁定目标并执行签名模板拼装、构建和安装启动。保持仓库既有平台工具基线，不使用 IDE 菜单操作，不修改应用功能；真实密钥/签名材料只由脚本和既有工具处理，不进入上下文或日志。

用户已确认：允许修改 dev-run.sh、必要的 dev-run.cmd/capture-test-log.sh、新增隔离回归测试及同步 AGENTS 第六节/脚本说明；本机实际目标只用现存 `Mate 90 Pro`，不假称它是 Phone26。允许复用缓存或在已有登录前提下常规生成签名，不强制重签、登录、接受协议、卸载或清数据。本机无 Windows 环境，Windows 分支回归与真正 Windows 实机验证分开，后者待复验，不谎报两端实机通过。

## User Scenarios & Testing

### User Story 1：选择并锁定正确运行目标（P1）

开发者可以不带参数使用一键启动，也可以指定带空格的模拟器名称或设备序列；其他连接设备不能夺走显式目标。

**Independent Test**：隔离工具输出中配置空列表、唯一/多活动设备、带空格实例、启动中状态、查询失败和冲突；真实验证仅启动获准实例。

**Acceptance Scenarios**：
1. 无参数且只有一个活动设备，选择它并向后续安装传递明确目标；多活动设备停止并要求指定。
2. 无活动设备且存在模拟器，按列表顺序选择第一个；没有实例则失败，不创建或改名。
3. 指定模拟器时核验完整名称并启动/等待它，不使用其他活动设备替代；指定不存在目标、查询失败或等待超时明确失败。
4. 同时给 device/emulator 时必须核验为同一实例，否则在目标变更前拒绝；no-emulator 不启动已停止实例。

### User Story 2：安全拼装、缓存与还原签名模板（P1）

开发者可以复用合法签名缓存或正常生成，再构建安装；完成或异常退出后共享模板与用户修改不被破坏。

**Independent Test**：隔离项目与假的签名工具测试缓存命中/失效、产品变化、脏/暂存模板、并发运行、INT/TERM和恢复失败；真实流程只由现有工具处理私有签名。

**Acceptance Scenarios**：
1. 签名缓存按实际模板与产品对齐，构建/运行使用相同产品和已锁定目标。
2. 模板存在用户修改、签名残留或不明恢复状态时停止，不自动 checkout、覆盖或删除用户内容。
3. 完成、构建/安装失败或可捕获中断后模板字节一致；恢复失败保留可恢复备份并明确失败，不能先宣称完成。
4. 并发启动不互相覆盖备份/缓存；签名生成输出不泄露敏感信息，缺登录/许可或安装身份冲突明确停止。

### User Story 3：两端入口与可追溯使用验证（P1）

macOS Bash 3.2+ 与 Windows Git Bash 通过同一脚本实现启动，Windows 包装正确传递空格路径和参数、退出状态；日志能记录真实结果。

**Independent Test**：本机 Bash 3.2/Homebrew Bash 运行隔离回归，覆盖 .cmd/.exe 分派与 Windows 路径场景；实际 Mac 启动、模板还原和应用运行留证据；提供 Windows 可复现入口并标未实测。

**Acceptance Scenarios**：
1. 系统 Bash 3.2 不因空数组或缺 GNU 专属校验工具失败；Windows 仍显式定位 Git Bash，不命中 WSL。
2. CLI 列表用结构化字段校验，不按空格切名称；工具失败/畸形输出不当有设备或已登录。
3. 日志目录不覆盖，命令结果、运行后的设备日志、模板状态/版本可追溯；失败不能因日志脚本退出0被当成功。
4. 使用仓库脚本在 Mate 90 Pro 完成签名拼装→构建→安装启动，确认模板恢复、既有资料保留；前置阻塞如实报告。
5. Windows 回归与实机结果分别列出，未执行 cmd.exe/Git Bash 实机不得标两端实机PASS。

### Edge Cases

设备/模拟器名称包含空格、Unicode、Shell特殊字符；CLI 非零退出或输出污染；多实例同名/矛盾状态；Windows .cmd/.exe 和带空格工具/项目路径；产品参数不一致；模板脏或暂存、既有恢复文件、并发、中断、恢复失败；未登录/未接受许可、签名缓存/证书过期或身份不一致；构建失败不得安装；命令与日志获取各自失败。

## Requirements

### Functional Requirements

- **FR-001**：仅修启动/Windows入口/日志及其回归/说明，不修改应用代码或 M1 功能，不自动提交/推送。
- **FR-002**：支持 macOS Bash 3.2+、Windows Git Bash 与 cmd 包装；保留 Windows 显式 Git Bash 定位及 CLI 后缀适配，不新增工具依赖安装。
- **FR-003**：无参数采用唯一活动设备，多个活动设备报错；无活动设备按列表首个模拟器启动，无实例明确失败。
- **FR-004**：显式 device/emulator 优先，双参数核验同一实例；缺失/冲突/查询错误停止，不自动切换其他目标；全程安装固定明确目标。
- **FR-005**：完整解析名称、状态和序列等结构化输出，验证退出状态/字段；等待启动有界，no-emulator 不自动启动。
- **FR-006**：产品选择贯穿签名、缓存、构建、运行；缓存与实际模板/产品匹配，不以 HEAD 模板哈希替代当前模板。
- **FR-007**：取消隐式 Git 配置/checkout；拒绝脏/暂存模板与不明恢复状态，不覆盖已有修改。钩子安装是独立人工授权操作，文档对齐。
- **FR-008**：模板备份归本次独占操作，并发互斥；成功、失败与可捕获中断真实还原；失败保留备份，不删除恢复证据或假报恢复成功。
- **FR-009**：允许工具复用真实缓存或已有登录时常规生成签名；不读取/展示私有内容、不强制重签、不自动登录/接受协议。原强签选项可保留显式语义，本轮不使用。
- **FR-010**：缺登录/许可、签名无效、安装身份冲突或构建失败停止并清楚提示，不卸载、不清用户/探针资料，不创建/改名模拟器。
- **FR-011**：日志脚本兼容原生校验工具、空数组、独占目录；分别记录命令与日志状态，并传播真实失败，运行后的设备日志与构建输出可回溯。
- **FR-012**：签名输出/缓存/备份不得进入公共日志、截图、上下文或Git；有限错误摘要需脱敏，不能为了排错输出原私有配置。
- **FR-013**：增加隔离回归测试，假CLI/合成无秘密模板覆盖目标/路径/缓存/恢复/退出状态，不操作真实设备/账号/签名目录。
- **FR-014**：真实使用只选获准 Mate 90 Pro，不扩展五故事UI，不对已有资料做删除；Windows 实机未执行明确记录。
- **FR-015**：.sh保持LF，.cmd保持ASCII/CRLF；测试日志保留本轮版本/命令/平台/结果；同步AGENTS第六节及必要脚本说明，不改平台基线。

### Key Entities

运行目标（来源、完整名称、状态、唯一序列）、执行上下文（OS、Shell、CLI、产品）、签名缓存身份（模板/产品版本，不是敏感内容）、独占备份/锁及恢复状态、测试记录（命令/退出/证据/平台层级）。

## Success Criteria

- **SC-001**：已冻结的目标选择/冲突/启动/失败回归全部通过，任何案例不误选或启动未授权目标。
- **SC-002**：缓存、产品、模板修改、并发、中断与恢复失败固定案例均按要求保留数据、还原或明确可恢复失败，无静默覆盖。
- **SC-003**：在本机两套 Bash 下全部隔离回归通过；Windows相关入口/后缀/路径回归通过且实机未覆盖透明。
- **SC-004**：实际 Mac 流程可由仓库脚本执行到构建、安装启动，并校验模板一致；若环境前置不足，正确失败并记录缺项，不使用伪验证成功。
- **SC-005**：日志和文档准确区分脚本回归、真实Mac使用、Windows实机，未暴露签名秘密、未发生用户资料清理或未授权Git写操作。

## Assumptions

本节仅记录已明确批准事项：脚本/回归/AGENTS范围、新独立执行目录、真实Mate 90 Pro、常规签名工具流程、无强签/登录/协议/卸载/清数据、Windows回归而实机待复验、默认唯一活动设备或首个模拟器、双参数必须一致。既有CLI/Node/DevEco工具仅探测/使用，不安装升级。
